入门脚本#

本指南介绍了一系列示例脚本，旨在协助完成典型的 Isaac Sim Replicator 工作流程。这些示例包括通过 Script Editor 进行的“异步”用法，以及通过 Standalone Application 进行的“同步”用法。这些脚本涵盖了基于仿真的场景以及用于合成数据生成 (SDG) 的配置。

先决条件#

在开始这些示例之前，请确保您具备：

  • Python 编程的基础知识

  • 对 USD（通用场景描述）概念的熟悉程度

  • 访问 NVIDIA Omniverse™ Isaac Sim 的权限

  • 用于数据捕获的充足磁盘空间（具体取决于分辨率和帧数）

  • 具有足够内存以进行渲染的 GPU（建议：8GB 以上）

设置与配置#

本节介绍此类工作流程中通常使用的配置。

编排器步骤函数#

在 Replicator 中，orchestrator.step() 函数用于触发整个合成数据生成 (SDG) 流程，包括执行随机化和捕获数据。对于 Isaac Sim 工作流，此函数仅用于触发数据捕获，随机化触发器则分配给自定义事件并手动激活。

step() 函数具有以下签名：

rep.orchestrator.step(rt_subframes: int = -1, pause_timeline: bool = True, delta_time: float = None, wait_for_render: bool = True)

其中：

  • rt_subframes：指定要渲染的子帧数量。大于 0 的值可启用子帧生成，从而减少渲染伪影或允许材质完全加载。

  • pause_timeline：如果设置为 True，则在步骤执行后暂停时间线（如果当前正在播放）。

  • delta_time：指定在步骤期间推进时间线的时间。如果 None，则默认为时间线的速率。

  • wait_for_render：如果 True，则函数会阻塞，直到渲染器完成当前帧后才返回。默认为 True。

有关基于图的 Replicator 随机化器的更多详细信息，请参阅 Randomizer Details，而对于自定义 Isaac Sim 或基于 USD API 的随机化，请参阅 Isaac Sim Randomizers Guide。

Capture on Play 标志#

默认情况下，Replicator 在播放期间每帧捕获数据。对于 Isaac Sim 工作流，数据捕获被配置为在用户定义的帧发生，使用 step() 函数。为此，需禁用 capture-on-play 标志：

import omni.replicator.core as rep

rep.orchestrator.set_capture_on_play(False)
# OR
import carb.settings

carb.settings.get_settings().set("/omni/replicator/captureOnPlay", False)

RT Subframes 参数#

在需要减少时间渲染伪影的场景中，例如由快速移动或传送资产导致的重影，或在弱光照条件下，可以使用 RTSubframes 对同一帧进行多次渲染。这会暂停模拟并渲染额外的子帧，从而提高渲染质量。

rt_subframes 参数通常在 step() 函数中的捕获请求期间设置，但也可以全局配置：

# Set the rt_subframes parameter for a specific capture step
rep.orchestrator.step(rt_subframes=4)

# Set the rt_subframes parameter globally
import carb.settings

carb.settings.get_settings().set("/omni/replicator/RTSubframes", 4)

有关更多详细信息，请参阅文档示例。

SDG 的 DLSS 质量模式#

在使用 Replicator 进行合成数据生成 (SDG) 工作流时，建议将 DLSS 模型设置为 Quality 模式以避免渲染伪影。在较低分辨率下（尤其是低于 600x600 时），默认的 Performance 模式可能会导致生成图像中出现透明或边缘渲染错误等问题。

import carb.settings

# Set DLSS to Quality mode (2) for best SDG results (Options: 0 (Performance), 1 (Balanced), 2 (Quality), 3 (Auto))
carb.settings.get_settings().set("/rtx/post/dlss/execMode", 2)

DLSS 时域重置#

DLSS 会在多次渲染之间累积运动和降噪器历史记录。当物理模拟推进但未进行渲染时（例如在多次捕获之间进行大量 SimulationManager.step() 调用），下一帧可能会出现重影，因为 DLSS 仍然引用过期的历史记录。请在捕获步骤之前立即重置。Workflow 1 和 simulation event driven capture 示例在捕获之间物理模拟运行但未渲染时执行此操作。

使用 /rtx-transient/post/dlss/forceParamReset 或 omni.usd.get_context().reset_renderer_accumulation()。请二选一：

import carb.settings

carb.settings.get_settings().set("/rtx-transient/post/dlss/forceParamReset", True)
rep.orchestrator.step(rt_subframes=4)

import omni.usd

omni.usd.get_context().reset_renderer_accumulation()
rep.orchestrator.step(rt_subframes=4)

方面

/rtx-transient/post/dlss/forceParamReset

omni.usd.get_context().reset_renderer_accumulation()

范围

仅 DLSS 和 DLSS 光线重建（NGX NVSDK_NGX_Parameter_Reset：丢弃 DLSS 运动和降噪器缓存）。

下一帧渲染器累积：之前的 G-buffer 和 AA 资源、DLSS 和 TAA、抖动和 RNG 种子、RT 光照缓存以及光线引导。

生命周期

一次性 Carb 设置；RTX 在下一次 DLSS 通道中读取该设置，并将其重置为 False。在渲染间隙后的每次捕获之前重新设置。

一次性 API；调度 omni.rtx.ForceResetAccumulation。RTX 在下一次渲染时消耗该标志并清除它。

使用时机

仅物理模拟步骤、传送或其他导致 DLSS 重影的渲染间隙。对于该情况，单独使用即可。

完整的时间性冷启动（黄金图像确定性；TAA、上一帧缓冲区或光照缓存不得延续）。同时会在下一个 RTX Real-Time 帧上重置 DLSS，因此对于 DLSS 重影，无需同时使用两者。

等待渲染参数#

默认情况下，step() 函数会阻塞，直到渲染器完成当前帧的生成后才返回。设置 wait_for_render=False 可将捕获请求与渲染管线解耦，从而允许在上一个帧仍在渲染时立即开始下一次随机化。在捕获数据无需与 step() 调用返回时的当前仿真状态完全匹配的工作流中，这可以显著提高吞吐量。

# Default behavior: blocks until the frame is rendered
rep.orchestrator.step(wait_for_render=True)

# Non-blocking: returns immediately, allowing the next randomization to start
rep.orchestrator.step(wait_for_render=False)

注意

使用 wait_for_render=False 时，标注和写入器数据可能对应于前一帧，而不是由最近的 step() 调用触发的帧。仅在不需要严格的帧与数据对应关系时使用此模式。

写入 Fabric 模式#

Fabric 是渲染器直接读取的运行时数据层。默认情况下，Replicator 将属性更改（如位置、旋转和颜色）写入 USD 阶段，然后在渲染前同步到 Fabric。启用写入 Fabric 模式可绕过 USD 阶段，直接将更改写入 Fabric，从而减少 USD 到 Fabric 同步的开销并提高随机化性能。

import carb.settings

# Enable write-to-fabric mode
carb.settings.get_settings().set("/exts/omni.replicator.core/enableWriteToFabric", True)

注意

由于更改直接写入 Fabric 并绕过 USD 阶段，因此这些更改不会反映在 USD 阶段中，也不会在保存场景时持久化。此模式旨在用于数据生成期间的临时随机化，而非永久性的场景修改。

自定义事件随机化#

为了提供灵活性，复制器随机化器可以通过自定义事件独立触发。这通过通过 trigger.on_custom_event 注册随机化器触发器并使用 utils.send_og_event 激活它来实现。例如，以下示例为穹顶灯创建了一个随机化图并随机化其颜色。然后通过其自定义事件名称手动触发该随机化图。step() 函数不会触发此随机化图。

# Create a randomization graph for creating a dome light and randomizing its color
with rep.trigger.on_custom_event(event_name="randomize_dome_light_color"):
    rep.create.light(light_type="Dome", color=rep.distribution.uniform((0, 0, 0), (1, 1, 1)))

# Trigger the randomization graph using its custom event name
rep.utils.send_og_event(event_name="randomize_dome_light_color")

自定义事件的示例代码片段也可在 此处 获取。

等待完成#

在关闭应用程序之前，确保所有数据完全写入磁盘对于防止数据丢失至关重要。高数据吞吐量（例如来自多个相机或高分辨率）可能会引入 I/O 瓶颈；有关缓解此类问题的策略，请参阅 I/O 优化指南。

wait_until_complete 函数通过等待写入器后端完成其操作，确保所有写入任务最终完成。此过程允许应用程序在所有写入任务完成之前继续更新，从而防止潜在的数据丢失。

from omni.replicator.core import BackendDispatch
import omni.kit.app

async def wait_until_complete():
    while not BackendDispatch.is_done_writing():
        await omni.kit.app.get_app().next_update_async()

或者，使用文档中记录的辅助函数：同步上下文中使用 rep.orchestrator.wait_until_complete()，异步上下文中使用 await rep.orchestrator.wait_until_complete_async()。

示例#

带有性能优化的批量随机化#

本示例演示如何使用功能 API 和 ReplicatorRNG 批量创建并随机化 100 个立方体。它运行三种配置以比较性能：默认配置（wait_for_render=True）、非阻塞捕获（wait_for_render=False），以及启用 write-to-fabric 的非阻塞捕获。每次运行都会打印每步的随机化和捕获耗时，以及包含 wait_until_complete 的总时长，从而说明 wait_for_render 和 write-to-fabric 对吞吐量的影响。该独立示例也可以直接运行（在 Windows 上，请使用 python.bat 而不是 python.sh）：

import asyncio
import os
import time

import carb.settings
import isaacsim.core.experimental.utils.app as app_utils

NUM_CUBES = 100
NUM_CAPTURES = 10


async def run_example_async(wait_for_render, write_to_fabric):
    print(f"\n[SDG] Running with wait_for_render={wait_for_render}, write_to_fabric={write_to_fabric}")
    await stage_utils.create_new_stage_async()
    rep.orchestrator.set_capture_on_play(False)

    settings = carb.settings.get_settings()
    settings.set("rtx/post/dlss/execMode", 2)
    settings.set("/exts/omni.replicator.core/enableWriteToFabric", write_to_fabric)

    rng = rep.rng.ReplicatorRNG(seed=42)

    # Setup stage with a dome light and batch-created cubes
    rep.functional.create.xform(name="World")
    rep.functional.create.dome_light(intensity=500, parent="/World", name="DomeLight")
    cubes = rep.functional.create_batch.cube(
        count=NUM_CUBES,
        parent="/World",
        name="Cube",
        semantics={"class": "my_cube"},
    )
    rep.functional.modify.scale(cubes, (0.2, 0.2, 0.2))

    # Create the camera and render product
    cam = rep.functional.create.camera(position=(5, 5, 5), look_at=(0, 0, 0), parent="/World", name="Camera")
    rp = rep.create.render_product(cam, (512, 512))

    # Write data using BasicWriter with rgb annotator
    backend = rep.backends.get("DiskBackend")
    out_dir = os.path.join(os.getcwd(), f"_out_fabric_{write_to_fabric}_wait_{wait_for_render}")
    backend.initialize(output_dir=out_dir)
    print(f"[SDG] Output directory: {out_dir}")
    writer = rep.writers.get("BasicWriter")
    writer.initialize(backend=backend, rgb=True)
    writer.attach(rp)

    # Randomize and capture, measuring timing for each phase
    randomization_times_ms = []
    capture_times_ms = []
    total_start = time.perf_counter()

    for i in range(NUM_CAPTURES):
        random_positions = rng.generator.uniform((-3.0, -3.0, -3.0), (3.0, 3.0, 3.0), size=(NUM_CUBES, 3))
        random_rotations = rng.generator.uniform((0.0, 0.0, 0.0), (360.0, 360.0, 360.0), size=(NUM_CUBES, 3))
        random_scales = rng.generator.uniform(0.1, 0.4, size=(NUM_CUBES, 3))

        rand_start = time.perf_counter()
        rep.functional.modify.pose(
            cubes,
            position_value=random_positions,
            rotation_value=random_rotations,
            scale_value=random_scales,
        )
        rep.functional.randomizer.display_color(cubes, rng=rng)
        rand_ms = (time.perf_counter() - rand_start) * 1000.0
        randomization_times_ms.append(rand_ms)

        cap_start = time.perf_counter()
        await rep.orchestrator.step_async(wait_for_render=wait_for_render)
        cap_ms = (time.perf_counter() - cap_start) * 1000.0
        capture_times_ms.append(cap_ms)

        print(f"[SDG] Step {i}: randomization {rand_ms:.1f} ms, capture {cap_ms:.1f} ms")

    # Wait for all data to be written to disk
    print("[SDG] Waiting for all data to be written to disk..")
    await rep.orchestrator.wait_until_complete_async()
    total_ms = (time.perf_counter() - total_start) * 1000.0

    avg_rand = sum(randomization_times_ms) / len(randomization_times_ms)
    avg_cap = sum(capture_times_ms) / len(capture_times_ms)
    print(f"[SDG] Avg randomization: {avg_rand:.1f} ms, avg capture: {avg_cap:.1f} ms, total: {total_ms:.1f} ms")

    writer.detach()
    rp.destroy()

使用 Actor 触发器响应事件#

本示例展示了如何将事件生成（Event Generation）（isaacsim.replicator.incident）与 Actor 合成数据生成（SDG）（isaacsim.replicator.agent）端到端地连接起来，无需编写一行 Python 代码。你只需编辑两个 YAML 配置文件，并从各自的 Omniverse 窗口驱动这两个扩展。

在运行时，事件生成会在仓库中触发一个火灾事件，该事件会派发一个 carb 事件；Actor SDG 角色通过 event_trigger 订阅该 carb 事件并切换其行为：短暂暂停，走到安全点，静止站立，最后恢复其漫游例程。


先决条件#

  • 两个扩展均已启用。有关 Actor SDG 部分，请参阅 启用扩展；事件生成扩展会在启动 Action and Event Data Generation 应用时自动启用。

  • 熟悉独立教程会有所帮助，但并非必需：

    • Actor 模拟与合成数据生成

    • 物理空间事件生成

两个扩展如何连接#

这两个扩展之间没有直接的 API 耦合。它们通过 Kit 应用实例中所有扩展共享的 carb 事件总线进行连接。当事件触发时，Event Generation 会派发一个命名的 carb 事件，而 Actor SDG 的 event_trigger 会监听该名称。匹配的字符串是它们之间唯一的契约。

派发的事件名称始终为：

isaacsim.replicator.incident.core.events/<event_name>

将 <event_name> 替换为你在 Event Generation YAML 中 FireEvent.name（或 SpillEvent.name）下放置的内容。扩展会将事件名称按原样插值到派发的字符串中。请使用下划线代替空格；name 中的空格会导致 actor 的 event_trigger 查找静默失败。

只有 FireEvent 和 SpillEvent 会派发 carb 事件。ToppleEvent 目前仅在 Event Generation 内部发出信号，无法驱动 actor 触发器。有关事件支持的完整触发器类型列表（包括从一个事件链式触发另一个事件），请参阅 Triggers。

步骤 1 - 编写 Event Generation YAML#

将以下内容保存为 incident_config.yaml，位置任意：

isaacsim.replicator.incident:
  version: 0.1.0
  global:
    report_dir: ~/EventsResult
    seed: 42
  event:
    event_list:
      - FireEvent:
          name: warehouse_fire
          flammable_item:
            item: $random_flammable_item$
            flammable_nearby_radius: 1.5
          trigger:
            type: time
            time: 4

time: 4 是从时间轴开始播放起计算的秒数。该扩展在设置阶段通过扫描带有 IsaacSim_Replicator_Incident_Attr:FlammableItem 标签的 prim 来解析 $random_flammable_item$。

步骤 2 - 编写 Actor SDG YAML#

保存为 agent_config.yaml。触发器的 event: 字符串必须与步骤 1 派发的内容完全匹配。

isaacsim.replicator.agent:
  version: 1.7.0
  seed: 42
  simulation_duration: 25.0
  environment:
    base_stage_asset_path: Isaac/Environments/Simple_Warehouse/full_warehouse.usd
  sensor:
    groups:
      sensor_group_00:
        num: 1
        aim_at_targets: {}
  character:
    groups:
      warehouse_workers:
        num: 2
        routines:
          - wander:
              weight: 1.0
              repeat: 1
              walk:
                speed_range: [1.0, 1.0]
                distance_range: [5.0, 10.0]
                navigation_areas: []
              idle:
                - animation: idle
                  weight: 1.0
                  time_range: [3.0, 5.0]
        triggers:
          - event_trigger:
              event: isaacsim.replicator.incident.core.events/warehouse_fire
              priority: 10
              behavior:
                - stop:
                    weight: 1.0
                    repeat: 1
                    time_range: [1.0, 2.0]
                - patrol:
                    weight: 1.0
                    repeat: 1
                    speed_range: [3.0, 4.0]
                    path_points:
                      - [0.0, 0.0, 0.0]
                - stop:
                    weight: 1.0
                    repeat: 1
                    time_range: [10.0, 15.0]
  replicator:
    writers:
      IRABasicWriter:
        output_dir: ~/out_event_reactive_actors
        rgb: true
        camera_params: true

关于此配置的一些说明：

  • sensor 块创建一个占位相机。触发器不需要它，但配置编辑器会默认填充它；保留该块可确保 YAML 文件能通过编辑器 UI 进行往返读写。

  • weight、repeat 和 navigation_areas: [] 虽然均为默认值，但在此显式展示。此示例将其列出，以便您查看配置编辑器生成的内容并就地修改这些值。

  • 触发器的 behavior 列表按顺序执行：先短暂停留 1-2 秒，然后巡逻至 (0, 0, 0)，接着再停留 10-15 秒。列表执行完毕后，Actor 恢复其常规行为。

重要

这两个扩展均作用于 Actor SDG 加载的阶段，因为它们共享同一个 Kit 阶段。如果将 Actor SDG 指向未标记的仓库，Event Generation 会记录 '$random_flammable_item$' is not a tagged prim 且不会触发事件。请手动标记一个 prim（步骤 5），或加载一个预标记的阶段，例如 Isaac/Samples/Replicator/Incidents/full_warehouse_with_incident_tags.usd。

步骤 3 - 启动应用#

从 Isaac Sim 安装目录：

./isaac-sim.action_and_event_data_generation.sh

这将打开 isaacsim.exp.action_and_event_data_generation.full.kit，从而启用 Actor SDG 和 Event Generation 界面。在 Tools > Action and Event Data Generation 下会出现两个菜单项：

  • Actor SDG – Actor SDG 的配置窗口。

  • Event Config File – Event Generation 的配置窗口。

从 Tools 菜单打开这两个窗口，它们将并排停靠。

步骤 4 - 设置 Actor SDG#

在 Actor SDG 窗口中：

  1. 点击 Select A Configuration File 字段（或粘贴 agent_config.yaml 的路径）。

  2. 设置路径后，点击 Set Up Simulation。

在内部，这会打开仓库阶段，实例化两个带有漫游例程的 warehouse_workers 角色，并为每个已订阅 isaacsim.replicator.incident.core.events/warehouse_fire 的角色附加一个 carb-event 监听器。在你执行任何其他操作之前，该订阅已处于活动状态。

不要启动时间轴。请避免点击 Start Data Generation 和 Play 按钮，因为一旦时间轴播放，Event Generation 的时间倒计时就会开始。请先完成步骤 5。

步骤 5 - 设置事件生成#

如果 Event Config File 窗口尚未打开，请通过 Tools > Action and Event Data Generation > Event Config File 打开它。只有当 isaacsim.replicator.incident.ui 扩展启用时，该菜单项才会出现，而步骤 3 中启动的 action_and_event_data_generation 应用会自动启用它。然后：

  1. 使用 Config File Path 选择器选择 incident_config.yaml。

  2. 在 Stage 窗口中，选择货架上的任意箱子 prim（例如，来自 Simple Warehouse 阶段的 /Root/Box_21069）。

  3. 在所选 prim 的 Property 面板中，点击 + Add > IncidentTagging > FlammableItem > Box。

  4. 点击 Set Up Incident。

如果你调整此示例以使用 SpillEvent 或 ToppleEvent，请在点击 Set Up Incident 之前，在 + Add > IncidentTagging 下选择 LeakableItem 或 LooseItem。

在内部，Event Generation 读取 YAML，等待导航网格烘焙，选择被标记的 prim 作为易燃目标，并设置一个时间触发器，该触发器将在时间轴播放后 t = 4 s 触发。目前尚未触发任何事件。

Global 部分的 Seed 字段应填充为 42，事件列表应显示 warehouse_fire。

步骤 6 - 播放并观察#

您有两种方式启动模拟：

  • Play 按钮 – 位于视口左侧的工具栏中。它仅播放时间轴且不写入任何数据。适用于预览事件和行为序列。

  • Start Data Generation（Actor SDG 窗口）– 播放时间轴并运行在 replicator 部分中配置的 Replicator 写入器，以捕获合成数据。simulation_duration: 25.0 会在运行完成时自动停止播放；IRABasicWriter 输出将显示在主目录下的 ~/out_event_reactive_actors/ 中。

无论采用哪种方式，请验证您是否收到：

时间 (s)

发生的情况

0

两个工人开始漫游。

~4

Event Generation 触发 FireEvent(warehouse_fire)。标记的 prim 上出现火焰和烟雾。派发一个 carb 事件。

~4（下一个 tick）

两个 worker 取消漫游例程并暂停 1-2 秒（触发器中的第一个 stop）。

暂停后

Worker 以较快的速度（3-4 m/s）走向 (0, 0, 0)。行进时间取决于每个 worker 的起始位置。

到达时

每个工人在安全点静止站立 10-15 秒。

触发器完成

每个工人采样一个新的漫游例程并恢复。

25

模拟结束。

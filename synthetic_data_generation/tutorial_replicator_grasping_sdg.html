Grasping 合成数据生成#

本教程介绍 isaacsim.replicator.grasping 扩展及其关联的 UI，即 isaacsim.replicator.grasping.ui。这些工具为在 Isaac Sim 中生成合成抓取数据集提供了全面的工作流。

学习目标#

完成本教程后，您将能够：

  • 理解 Grasping SDG 扩展的核心组件和数据流。

  • 导航并使用 Grasping SDG UI 来配置和运行抓取生成工作流。

  • 定义夹爪属性、关节状态和多步抓取阶段。

  • 配置物体属性和抓取姿态采样参数。

  • 执行并解读基于物理的抓取评估结果。

  • 使用 YAML 文件管理抓取配置，以保存、加载和共享设置。

这些扩展在 Isaac Sim 中会自动加载，可以通过主菜单中的 Tools > Replicator > Grasping 打开 UI 窗口。

入门指南#

在继续之前，建议您先熟悉以下内容：

  • Simulation Fundamentals：用于理解物理仿真概念和夹爪绑定（例如，驱动关节）。

  • Grasp Editor：本教程涵盖相关概念，并为抓取定义奠定基础。

注意

抓取采样器需要 libspatialindex 库。如果看到相关警告，请安装该库（例如，在 Ubuntu 上：sudo apt-get install libspatialindex-dev）。

本教程使用一个示例场景，其中包含预配置的夹爪和适合抓取练习的物体。您可以在以下位置找到此场景：

https://omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/6.1
/Isaac/Samples/Replicator/Stage/sdg_grasping_xarm.usd

场景资源位于 Content Browser 中的 Isaac Sim > Samples > Replicator > Stage > sdg_grasping_xarm.usd，或者可以通过在路径字段中输入完整 URL 来加载。

示例场景包含一个带有驱动关节的夹爪，以及三个配备了刚体物理和碰撞器的物体。为了简化初始交互，这些物体禁用了重力。打开时，Grasping UI 窗口通常停靠在 Property 面板中。

概述#

该扩展旨在自动化查找和评估给定夹爪-物体对的潜在抓取姿态的过程。其核心工作流围绕几个关键组件和阶段展开：

  1. 配置：定义特定的夹爪、目标物体，以及控制如何查找和测试抓取的参数。

  2. 抓取姿态采样：算法（例如，对置采样器）在目标物体周围生成一组候选抓取姿态。这些姿态代表了夹爪可能持有物体的潜在方式。

  3. 抓取执行阶段：对于每个候选抓取姿态，会模拟一系列动作，称为“抓取阶段”（例如，移动到预抓取位置、闭合手指、提升）。这允许定义类似于真实世界机器人动作的复杂多步抓取行为。

  4. 基于物理的评估：在物理引擎中模拟抓取的每个阶段。可以记录抓取尝试的成功或失败，以及其他指标（如接触力、物体位移）。在当前状态下，该扩展将夹爪状态保存为结果，从而可以评估抓取效果。

  5. 数据记录与管理：记录成功的抓取及其相关参数。整个设置可以保存到配置文件（YAML 格式）并从其中加载，从而确保可重复性并便于批处理。

GraspingManager 类是协调这些步骤的核心 Python API，而 UI 提供了一种直观的方式来配置和运行此流水线。

UI 窗口概览#

Grasping UI 窗口提供了设置和运行抓取模拟工作流的界面。它分为几个部分，每个部分处理流程的特定环节。一般工作流包括配置这些部分，通常从夹爪和物体开始，然后定义评估工作流和模拟参数，最后管理整体配置。

夹爪部分#

此部分专门用于定义夹爪的属性和行为，这对于任何抓取尝试都是至关重要的。

  • Path：指定夹爪根 prim 的 USD 路径（例如，/World/Robot/gripper_base）。

  • Joints：选择夹爪后，将列出其关节。在此您可以：

    • Include/Exclude：选择在抓取阶段中主动控制的关节。这些关节必须是驱动关节。

    • 设置 pre-grasp positions：定义每个关节的初始状态（通常为张开配置），在抓取序列开始之前。

    • 切换显示所有关节或仅显示驱动（非 mimic）关节。

  • Grasp Phases：此强大功能允许您定义构成完整抓取尝试的一系列离散动作。这类似于为夹爪定义状态机或运动原语序列。

    对于每个阶段（例如，“Open”、“Close”），您需指定：

    • 活动夹爪关节的目标关节位置。

    • 该阶段内物理步骤的仿真步长 delta time（dt）。

    • 该阶段要执行的仿真步数。

    阶段可以重新排序、删除或单独仿真以进行调试。如果 pre-grasp 关节位置已充分准备夹爪（例如，完全张开），则可能不需要显式的“Open”阶段。

对象部分#

本节重点在于指定目标对象并配置如何为其生成潜在的抓取姿态。

  • Path：目标对象 prim 的 USD 路径（例如，/World/MyObject）。

  • 抓取姿态采样器：用于配置查找潜在抓取姿态的算法。本教程主要使用对置抓取采样器（在 sampler_utils.py 中实现）。对于平行夹爪而言，对置抓取通常具有稳定性，涉及物体相对两侧的接触点。关键参数包括：

    • 每个抓取轴的朝向数量：围绕主抓取轴采样的旋转变体数量。

    • 夹爪悬停距离：在接近阶段，夹爪的工具中心点 (TCP) 或指尖到物体表面的距离，对于避免过早碰撞至关重要。

    • 最大夹爪开口度：夹爪钳口的最大张开宽度，用于过滤掉对于物体而言过宽的抓取。

    • 抓取的对齐轴：定义用于与物体特征或抓取线对齐的局部夹爪轴。

    • 夹爪接近方向：夹爪向物体移动方向的向量。

    • 横向扰动 (sigma)：沿抓取轴为抓取点位置添加随机性，允许在标称接触点周围进行探索。

    • 随机种子：用于确保采样结果的可复现性。

  • 抓取姿态：管理由采样器生成的候选抓取姿态集合。

    • 指定期望的候选姿态数量。

    • 清除先前生成的姿态。

    • 在视口中可视化姿态（在世界坐标系或物体局部坐标系中），并循环浏览以检查其放置情况。

    下图展示了由对置抓取采样器在各种物体上生成的示例抓取姿态：

  • Trimesh：提供用于调试可视化物体三角网格的选项，采样器内部使用这些网格进行几何计算和碰撞检查。

注意

Measure Tool 对于确定夹爪开口度或悬停距离等值可能很有用。

工作流部分#

工作流部分用于使用在夹爪和物体部分中定义的配置来编排实际的抓取评估过程。

系统首先保存夹爪的初始姿态。然后，对于每个选定的用于评估的生成抓取姿态，它在物理模拟中依次执行定义的抓取阶段。完成给定姿态的所有阶段后，记录结果（例如，基于物体稳定性或与目标接触的成败）以及其他相关指标。

  • 抓取样本数量：指定应评估多少生成的抓取姿态。使用 -1 以评估所有可用姿态。

  • Output Path：定义保存评估结果的目录和基础文件名。结果通常以 YAML 等结构化格式保存，详细记录每个评估的抓取姿态及其结果。

  • Overwrite Results：如果启用，将覆盖输出路径中已有的结果文件。否则，将创建新文件（例如，通过递增编号）以避免数据丢失。

  • Start Workflow：启动抓取评估流程。UI 通常会提供进度反馈。

仿真部分#

此部分允许您微调影响抓取评估期间物理仿真运行方式的全局参数。

  • Render each simulation step：控制在抓取阶段内的每个单独物理步骤后是否更新视口。对于大型数据集，禁用此选项可以显著加快评估过程，渲染可能仅在每个完整的抓取尝试或阶段之后发生。

  • Simulate using timeline：选择是通过步进主 Isaac Sim 时间线还是直接步进物理场景来推进仿真。直接物理步进可以为快速评估提供更精确的控制，而基于时间线的仿真可能更接近完整机器人应用程序的运行方式。

  • 隔离物理场景：可选地指定一个 Physics Scene prim 的路径。如果提供该路径，抓取仿真将在该专用物理场景中运行，从而防止主舞台中的其他动态对象或物理设置产生干扰。这有助于确保抓取评估的一致性和可重复性。

配置部分#

配置部分提供了关键功能，可将整个抓取设置保存为 YAML 文件，并在之后重新加载。这对于可复现性、共享配置以及运行批量实验至关重要。

  • 文件路径：指定用于保存或加载的 YAML 配置文件的路径。

  • 配置包含项：选择性地在保存/加载操作中包含设置的哪些组件。这支持模块化配置。选项通常包括：

    • 夹爪路径

    • 关节预抓取状态

    • 抓取阶段

    • 对象路径

    • 采样器参数

    • 生成的抓取位姿（如果您希望保存特定的一组位姿）

  • 覆盖现有文件：保存时，此选项决定指定路径下已存在的文件是否应被覆盖。

  • 加载/保存按钮：执行相应的文件操作。

这种结构化的 UI 和配置系统为生成多样化的抓取数据集提供了详细的控制和灵活性。

代码示例#

以下脚本演示了使用 GraspingManager API 生成抓取数据集的完整工作流程。该脚本以编程方式执行可通过 UI 配置的以下步骤：

  • 打开一个 stage

  • 设置 GraspingManager（可能通过加载配置文件）

  • 生成抓取位姿（Poses）

  • 使用物理仿真评估这些位姿

  • 保存结果

import asyncio
import os

import omni.kit.app
import omni.usd
from isaacsim.core.utils.extensions import get_extension_path_from_name
from isaacsim.replicator.grasping.grasping_manager import GraspingManager
from isaacsim.storage.native import get_assets_root_path_async


async def run_example_async(
    stage_path,
    config_path=None,
    sampler_config=None,
    physics_scene_path=None,
    output_dir=None,
    gripper_path=None,
    object_prim_path=None,
):
    assets_root_path = await get_assets_root_path_async()
    print(f"Assets root path: {assets_root_path}")
    stage_url = assets_root_path + stage_path
    print(f"Opening stage: {stage_url}")
    await omni.usd.get_context().open_stage_async(stage_url)
    stage = omni.usd.get_context().get_stage()

    grasping_manager = GraspingManager()

    if config_path is not None:
        load_status = grasping_manager.load_config(config_path)
        print(f"Config load status: {load_status}")

    # Make sure the object to grasp is set (either from the config file or from the argument)
    if not grasping_manager.get_object_prim_path() and object_prim_path:
        grasping_manager.object_path = object_prim_path

    if not grasping_manager.get_object_prim_path():
        print("Warning: Object to grasp is not set (missing in config and argument). Aborting.")
        return

    # Make sure the gripper is set (either from the config file or from the argument)
    if not grasping_manager.gripper_path and gripper_path:
        grasping_manager.gripper_path = gripper_path

    if not grasping_manager.gripper_path:
        print("Warning: Gripper path is not set (missing in config and argument). Aborting.")
        return

    # If there are already grasp poses in the configuration, don't generate new ones
    if grasping_manager.grasp_locations:
        print(
            f"Found {len(grasping_manager.grasp_locations)} grasp poses in the configuration file. No new poses will be generated."
        )
    else:
        print("No grasp poses found in configuration, generating new ones...")

        # Determine Sampler Configuration
        if not (grasping_manager.sampler_config and grasping_manager.sampler_config.get("sampler_type")):
            if sampler_config:
                grasping_manager.sampler_config = sampler_config.copy()
            else:
                print(
                    "Warning: Sampler configuration is missing or invalid (not in config file and not provided as argument). Aborting pose generation."
                )
                return

        # Generate the grasp poses
        success_generation = grasping_manager.generate_grasp_poses()
        if not success_generation or not grasping_manager.grasp_locations:
            print("Failed to generate grasp poses or no poses were generated.")
            return
        print(f"Generated {len(grasping_manager.grasp_locations)} new grasp poses.")

    # Store the initial gripper pose to be able to restore it after the evaluation
    grasping_manager.store_initial_gripper_pose()

    print("Evaluating grasp poses...")
    poses_to_evaluate = grasping_manager.get_grasp_poses(in_world_frame=True)
    if not poses_to_evaluate:
        print("No poses available to evaluate..")
        return

    # Determine Output Path
    if not output_dir:
        print("Warning: Output path is not defined data will not be saved.")

    # Set the output path and overwrite flag
    grasping_manager.set_results_output_dir(output_dir)
    grasping_manager.set_overwrite_results_output(True)

    # Determine Physics Scene Path
    physics_scene_path_for_eval = None
    if physics_scene_path and stage.GetPrimAtPath(physics_scene_path):
        physics_scene_path_for_eval = physics_scene_path
    print(f"Physics scene path for evaluation: {physics_scene_path_for_eval}")

    await grasping_manager.evaluate_grasp_poses(
        grasp_poses=poses_to_evaluate,
        render=True,
        physics_scene_path=physics_scene_path_for_eval,
        simulate_using_timeline=False,
    )

    print("Grasping workflow example finished.")
    grasping_manager.clear()

复制代理（IRA）#

本指南涵盖从 IRA 0.x.x（随 Isaac Sim 5.1 及更早版本发布）升级到 IRA 1.x.x（Isaac Sim 6.0 及之后版本）时的破坏性变更和迁移步骤。

IRA 1.0.0 是一次彻底的架构重构。配置架构、Python API、依赖图以及内部模块布局均已变更。 现有的 0.x 配置和代码若未经修改将无法正常工作。

变更概览#

IRA 1.x 保留了 0.x 的所有核心功能，包括：

  • 环境加载

  • 角色和机器人生成

  • 传感器放置

  • 合成数据生成

但它重新设计了这些领域的配置和执行方式。下表总结了每个主要功能领域，包括支持该功能的版本以及变更内容：

功能

0.x

1.x

备注

是

是

scene.asset_path 已重命名为 environment.base_stage_asset_path（现为必填项）。路径可以是相对于 Isaac Sim 资源的路径、URL 或绝对路径。

环境道具子层

–

新增

prop_asset_paths 允许您将额外的 USD 资源叠加到基础阶段中。

人类角色生成

是

是

扁平的 character 部分已被带有命名组的 character.groups 取代。

是

是

nova_carter_num 和 iw_hub_num 已被带有指向 IAR 配置的 config_file_path 的命名组取代。

角色行为控制

是

是

外部 .txt 命令文件已被 YAML 中的内联 routines 取代。

机器人行为控制

是

是

相同变更：外部命令文件被内联 routines 取代。

命名角色组

–

新增

角色、机器人和传感器被组织到独立配置的命名组中。

例程触发行为循环

–

新增

角色持续选择加权行为；触发器通过优先级队列序列中断例程。取代了旧的 response、event 和 incident 模型。

行为类型（wander、patrol、stop/halt）

是

是

0.x 版本通过文本文件支持 GoTo、Idle 和类似 Patrol 的命令。1.x 版本将这些形式化为类型化行为（wander、patrol、stop、halt），并支持丰富的内联参数。

行为树组

–

新增

角色或机器人组可以使用 behavior_tree + overrides 代替 routines/triggers，将所有逻辑委托给引用的 JSON 树。请查阅配置文件指南中的“Behavior Tree Character Group”和“Behavior Tree Robot Group”章节。

事件和时间触发器

是

是

0.x 版本使用 response、event 和 incident 配置部分。1.x 版本将其替换为具有优先级队列的一等 event_trigger 和 time_trigger 类型。

USD Schema 集成

–

新增

角色配置持久化在 USD API schema 中（IRACharacterAPI、AnimRobotAPI）。行为和触发器成为独立的 USD prim，以便进行检查和编辑。

每个角色的确定性种子

–

新增

每个角色的种子由其名称、组和全局种子派生而来，从而实现可复现且独立的随机化。

传感器和相机放置

是

是

camera_num 和 camera_list 已被具有可插拔放置策略的命名传感器组取代。

传感器放置策略

–

新增

aim_at_targets 和 maximum_coverage 算法；num: -1 可自动计算实现目标覆盖所需的相机数量。

相机随机化参数

是

是

高度、角度、焦距和距离范围已从扩展设置移至每个组的 YAML 配置中。

单一数据写入器

是

是

IRABasicWriter 在两个版本中均可用。

多个并发写入器

–

新增

replicator.writers 字典支持多个写入器同时运行。

每个写入器的时间控制

–

新增

每个写入器的 start_frame 和 end_frame 或 start_time 和 end_time。

每个写入器的传感器选择

–

新增

sensor_prim_list 为每个写入器选择特定的相机。

额外写入器

–

新增

CosmosIRAWriter、SceneGraphWriter、CustomWriter。（BasicWriter 可通过 CustomWriter 配合 writer_name: "BasicWriter" 访问。）

Actor 上的语义标签

新增

每个角色/机器人组的 semantic_labels 字段。

角色碰撞体

–

新增

每个角色组可选的圆柱体或盒体碰撞形状。

机器人机载相机选择

–

新增

camera_prim_paths 指定用于数据生成的机器人机载相机。

Pydantic 配置验证

新增

是

是

response、event 和 incident 配置部分

是

已移除

由单个角色组上的 triggers 取代。

角色上的 filters 字段

是

已移除

不再支持。

工作流和 UI 变更#

运行 IRA 的端到端工作流发生了显著变化。

UI 工作流#

UI 工作流已简化。最大的变化是移除了 Generate Random Commands 步骤。

1.x 工作流

点击 Set Up Simulation

在 0.x 版本中，命令生成和保存是分开的两个手动步骤。在 1.x 版本中，所有 actor 行为都通过 routines 和 triggers 在 YAML 配置中预先定义，因此从设置到生成的流程只需两次点击。

默认配置文件位置#

版本

位置

0.x

[ext-path]/config/default_config.yaml（启动时自动加载）

1.x

[ext-path]/data/sample_configs/（有关捆绑的示例，请参阅 Sample Configs）

在 1.x 版本中，默认加载 minimal.yaml。如需包含角色、相机和写入器的完整示例，请使用 full_pipeline.yaml。

无头模式或基于脚本的数据生成#

脚本入口点已更改：

# OLD (0.x)
./python.sh tools/actor_sdg/sdg_scheduler.py -c [config file path]

# NEW (1.x)
./python.sh tools/actor_sdg/actor_sdg.py -c [config file path]

sdg_scheduler.py 脚本已被 actor_sdg.py 取代。旧脚本中的 --save_usd 标志不再作为脚本参数记录在案。

仿真持续时间#

在 0.x 版本中，simulation_length 以帧为单位指定（假设 30 FPS）。用户需要进行心理换算：300 帧 = 10 秒。

在 1.x 版本中，simulation_duration 直接以秒为单位指定（例如 60.0）。仿真内部仍以固定的 30 FPS 运行。

配置文件变更#

YAML 配置架构已从头重新设计。

版本字段#

version 字段现在用于跟踪扩展版本，并且必须具有 1.x.x 主版本号。

# 0.x
isaacsim.replicator.agent:
  version: 0.7.0

# 1.x
isaacsim.replicator.agent:
  version: 1.6.0

顶层结构#

0.x 字段

1.x 替代项

备注

global.seed

seed

已移至根级别。现在是一个 32 位无符号整数 (0..4294967295)。如果省略，则根据系统时间自动生成。

global.simulation_length

simulation_duration

已重命名。原位于 frames（以 30 FPS 为单位），现在以 seconds 为单位。1800 帧 = 60.0 秒。

scene.asset_path

environment.base_stage_asset_path

章节名称从 scene 更改为 environment。

sensor

sensor

完全重构（见下文）。

character

character

完全重构（见下文）。

robot

robot

完全重构（见下文）。

replicator

replicator

完全重构（见下文）。

response

（已移除）

Response 部分不再存在。请改用 triggers。

event

（已移除）

Event 部分不再存在。请改用 triggers。

顶层迁移示例：

# OLD (0.x)
isaacsim.replicator.agent:
  version: 0.7.0
  global:
    seed: 123456789
    simulation_length: 1800

# NEW (1.x)
isaacsim.replicator.agent:
  version: 1.6.0
  seed: 123456789           # optional, auto-generated if omitted
  simulation_duration: 60.0  # 1800 frames / 30 FPS = 60 seconds
  environment:
    base_stage_asset_path: "Isaac/Environments/Simple_Warehouse/full_warehouse.usd"  # now required

Environment（原 scene）#

scene 部分已重命名为 environment 并进行了扩展。

# OLD (0.x)
# scene.asset_path was defined in the config, OR fell back to settings

# NEW (1.x)
environment:
  base_stage_asset_path: "Isaac/Environments/Simple_Warehouse/full_warehouse.usd"
  prop_asset_paths: []  # optional: additional USD assets loaded as sublayers

主要区别：

  • base_stage_asset_path 现在是必填项（不再回退到扩展设置）。

  • 支持相对于 Isaac Sim 资源根目录解析的相对路径、完整 URL 以及绝对文件系统路径。

  • 新增 prop_asset_paths 字段，用于将其他资源分层添加到 stage 中。

Character 部分#

character 部分现在使用命名组系统，并包含内联行为定义（routines），取代了原先使用外部命令文件的扁平结构。

# OLD (0.x)
character:
  asset_path: ""                       # single path for all characters
  command_file: default_command.txt     # external text file for commands
  num: 8
  filters: []
  spawn_area: []
  navigation_area: []

# NEW (1.x)
character:
  root_prim_path: "/World/Characters"   # optional, defaults to /World/Characters
  motion_library_path: ""                # optional; 1.4.0+ moved this to character root (was per-group)
  groups:
    warehouse_workers:                   # named group
      num: 10
      asset_path: "Isaac/People/Characters/"
      spawn_areas: []                    # renamed from spawn_area
      semantic_labels: [["class", "character"]]
      routines:                          # replaces command_file
        - wander:
            weight: 1.0
            repeat: 1
            walk:
              speed_range: [0.8, 1.5]
              distance_range: [5.0, 10.0]
              navigation_areas: []       # renamed from navigation_area
            idle:
              - animation: idle
                weight: 1.0
                time_range: [2.0, 5.0]
      triggers: []                       # new: event-driven behavior interrupts
      colliders: null                    # new: optional collision shapes

主要区别：

  • 命名组：角色现在组织在 character.groups 下的命名组中，每个组具有独立的设置。

  • 不再使用命令文件：command_file 字段和外部 .txt 命令文件已移除。行为现在通过 routines 以内联方式定义。

  • 例程取代命令：每个例程条目都是一个行为类型（wander、patrol、stop、custom_behavior），并包含内联参数。

  • filters 字段已移除。

  • spawn_area 已重命名为 spawn_areas。

  • navigation_area 现在作为 walk.navigation_areas 下的每个行为属性存在。

  • 角色组新增了 semantic_labels、triggers 和 colliders 字段。motion_library_path 也是新增字段，但从 IRA 1.4.0 版本开始，它位于 character: 根节点（不在组内）；现在将其放在组内会导致验证失败。

机器人部分#

与角色类似，机器人现在也使用带有内联例程的命名组。

# OLD (0.x)
robot:
  command_file: default_robot_command.txt
  nova_carter_num: 0
  iw_hub_num: 0
  write_data: false
  spawn_area: []
  navigation_area: []

# NEW (1.x)
robot:
  root_prim_path: "/World/Robots"
  groups:
    carters:
      num: 2
      config_file_path: "nova_carter.yaml"   # IAR robot config file
      spawn_areas: []
      agent_radius: null                      # optional NavMesh agent radius
      write_data: false
      camera_prim_paths: []                   # optional: specific cameras for data
      semantic_labels: [["class", "robot"]]
      routines:
        - wander:
            move:
              distance_range: [10.0, 15.0]
              navigation_areas: []
            idle:
              time_range: [2.0, 5.0]
      triggers: []

主要区别：

  • nova_carter_num / iw_hub_num 已移除。请使用命名组，并通过 num 和 config_file_path 指向相应的 IAR 配置。

  • command_file 已被内联 routines 取代（与角色相同）。

  • 新增 config_file_path 字段，用于引用机器人的 Isaac Anim Robot (IAR) 配置。

  • 新增 camera_prim_paths，用于指定在数据生成时使用哪些车载摄像头。

  • spawn_area 已重命名为 spawn_areas。

传感器部分#

传感器部分已重新设计，以支持命名组和可插拔的放置策略。

# OLD (0.x)
sensor:
  camera_num: 4
  # OR
  camera_list: ["/World/Camera1", "/World/Camera2"]

# NEW (1.x)
sensor:
  root_prim_path: "/World/Cameras"
  groups:
    ceiling_cameras:
      num: 6
      aim_at_targets:           # placement strategy
        height_range: [7.0, 10.0]
        look_down_angle_range: [30.0, 45.0]
        focal_length_range: [10.0, 15.0]
        distance_range: [5.0, 10.0]
    coverage_cameras:
      num: -1                   # auto-calculate for maximum coverage
      maximum_coverage:
        target_coverage_ratio: 0.8
        height_range: [2.0, 5.0]

主要区别：

  • camera_num / camera_list 已被 sensor.groups 下的命名组取代。

  • 每个组指定一种放置策略：aim_at_targets 或 maximum_coverage。

  • 原先位于扩展设置中的相机随机化参数（高度、角度、焦距、距离）现已移至配置 YAML 文件中，并按传感器组进行配置。

  • num: -1 与 maximum_coverage 会触发自动相机数量计算。

Replicator 部分#

Replicator 部分现在支持多个并发写入器，并具备每个写入器的时序控制功能。

# OLD (0.x)
replicator:
  writer: IRABasicWriter          # single writer, selected by name
  parameters:                     # flat parameter dict
    object_info_bounding_box_2d_tight: false
    object_info_bounding_box_2d_loose: false
    semantic_filter_predicate: "class:character|robot;id:*"
    rgb: true
    camera_params: true

# NEW (1.x)
replicator:
  hide_debug_visualization: true  # new: hides NavMesh/skeleton debug viz
  writers:
    IRABasicWriter:               # writer name is the dict key
      rgb: true
      camera_params: true
      object_info_bounding_box_2d_tight: true
      object_info_bounding_box_2d_loose: true
      semantic_filter_predicate: "class:character|robot;id:*"
      start_frame: 30             # new: per-writer frame control
      # OR use time-based:
      # start_time: 1.0
      # end_time: 50.0
      # sensor_prim_list: []      # new: optional per-writer sensor selection

主要区别：

  • writer + parameters 已被 writers 字典取代。键为写入器名称，值直接包含参数（不再嵌套在 parameters 下）。

  • 多个写入器：您可以在单个配置中定义多个写入器（例如，IRABasicWriter + CosmosIRAWriter）。

  • 每个写入器的 start_frame 和 end_frame 或 start_time 和 end_time 用于时序控制。

  • 每个写入器的 sensor_prim_list 用于选择特定相机。

  • 默认 start_frame 为 30（跳过初始稳定帧）。

  • 新增写入器：CosmosIRAWriter、SceneGraphWriter、CustomWriter。可通过 CustomWriter 配合 writer_name: "BasicWriter" 使用标准 Replicator BasicWriter。

  • IRABasicWriter 默认值已更改：object_info_bounding_box_2d_tight、object_info_bounding_box_2d_loose 和 object_info_bounding_box_3d 现在默认为 true。

行为系统架构变更#

Actor 行为系统已进行根本性重新设计。

旧系统 (0.x)：命令文件 + omni.anim.people#

在 0.x 版本中，Actor 行为由外部命令文件控制（.txt）：

  • 角色由 omni.anim.people 驱动，该组件逐行读取基于文本的命令文件。

  • 机器人由 isaacsim.anim.robot 驱动，并使用类似的命令文件。

  • UI 中的 Generate Random Commands 按钮根据存储在扩展设置中的随机化设置创建这些命令文件。

  • 命令转换映射（.json）控制命令之间的概率转换。

新系统 (1.x)：例程-触发器循环 + omni.anim.behavior#

在 1.x 中，角色行为使用由 omni.anim.behavior.core 支持的例程-触发器循环：

  1. 例程 (Routines)：在 YAML 配置中定义的加权行为列表。角色根据概率权重从其例程池中反复选择行为，使用角色各自的种子。

  2. 触发器 (Triggers)：事件驱动或时间驱动的中断。激活时，角色暂停其例程并执行触发器的行为序列。高优先级触发器可以抢占正在运行的触发器。

  3. USD Schema：加载后，每个角色的配置嵌入在 USD API schemas 中（角色在 SkelRoot 上使用 IRACharacterAPI，机器人根 prim 上使用 AnimRobotAPI）。行为和触发器成为由角色引用的独立 USD prim。

可用的行为类型#

角色行为：

  • wander – 随机游走和空闲循环，可配置速度、距离和空闲动画

  • patrol – 跟随由 3D 点或目标 prim 定义的路径

  • stop – 在可配置的时间内保持静止

机器人行为：

  • wander – 随机移动和空闲，可配置距离和等待时间

  • patrol – 跟随由 3D 点或目标 prim 定义的路径

  • halt – 停止可配置的持续时间

触发器类型（角色和机器人共用）：

  • event_trigger – 在命名事件上触发

  • time_trigger – 在指定时间（以秒为单位）后触发

  • collision_trigger – 当 actor 上的命名碰撞体开始或结束与另一个命名碰撞体重叠时触发

行为树组（例程/触发器的替代方案）#

从 IRA 1.3.0（角色）和 1.5.0（机器人）开始，组可以通过在组级别声明 behavior_tree JSON 资产和可选的 overrides 块来选择退出例程-触发器系统。所有行为逻辑随后都在引用的树中编写；routines、triggers 和 colliders 将不被应用。有关完整的 schema 和示例，请查阅配置文件指南中的“Behavior Tree Character Group (Experimental)”和“Behavior Tree Robot Group (Experimental)”章节。

逐步迁移检查清单#

配置文件迁移#

  1. 将 version 更改为 1.x.x（例如，1.5.0）。

  2. 将 global.seed 移动到根级别的 seed。

  3. 在根级别将 global.simulation_length（帧）转换为 simulation_duration（秒）。

    • 公式：simulation_duration = simulation_length / 30.0

  4. 将 scene.asset_path 重命名为 environment.base_stage_asset_path（此字段现在为必填项）。

  5. 将 character 重构为 character.groups.<group_name>，包含 num、asset_path 和内联的 routines。

  6. 将外部命令文件（.txt）转换为内联的 routines 条目。将旧命令映射到新的行为类型：

    • GoTo 命令 -> 带有 distance_range 的 wander 行为

    • Idle 命令 -> 带有 idle 列表的 wander 行为

    • 类似巡逻的序列 -> 带有 path_points 或 target_prims 的 patrol 行为

    • 查阅 配置文件指南 以获取完整的行为类型文档。

  7. 将 robot 重构为 robot.groups.<group_name>，包含 num、config_file_path 和内联的 routines。

    • 使用 config_file_path: "nova_carter.yaml" 将 nova_carter_num: N 替换为组条目。

    • 使用适当的 IAR 配置以类似方式替换 iw_hub_num: N。

  8. 使用放置策略（aim_at_targets 或 maximum_coverage）将 sensor.camera_num 和 camera_list 替换为 sensor.groups.<group_name>。

  9. 将相机随机化设置（高度、角度、焦距、距离范围）从扩展设置移动到传感器组配置中。

  10. 将 replicator.writer + replicator.parameters 替换为 replicator.writers.<WriterName>: { ... }。

  11. 移除 response、event 和 incident 部分。在单独的 character/robot 组上替换为 triggers。

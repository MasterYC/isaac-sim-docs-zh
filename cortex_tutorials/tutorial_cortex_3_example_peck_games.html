行为示例：啄木鸟游戏#

Tutorial

警告

[已弃用]：Cortex 框架自 Isaac Sim 6.0.0 起已被弃用，并将在未来的版本中移除。 对于行为编程，请迁移到开源库，例如用于行为树的 py_trees 或 用于有限状态机的 transitions。 有关替代教程，请参阅 用于机器人行为的状态机。

本教程展示了如何设计简单的行为，并探讨了状态机与决策网络之间的权衡。教程逐步介绍了 Franka 机器人的两种简单地面啄食行为实现方式，其中机器人需要在方块周围进行啄食。第一种实现使用状态机，但无法对移动到其路径前方的方块做出反应。我们在第二种实现中通过一个简单的决策网络解决了该问题，该决策网络内部利用了原始状态机的部分组件。状态机本质上保持不变，但更高层级的决策器可以根据需要抢占状态机以实现响应性。最后，我们使用纯决策网络实现了一个响应式抓取游戏。在该最终示例中，我们演示了自定义上下文对象及其监视器的实用性。

在所有命令行示例中，我们使用缩写 isaac_python 表示 Isaac Sim Python 脚本（在 Linux 上为 <isaac_sim_root>/python.sh，在 Windows 上为 <isaac_sim_root>\python.bat）。 命令行均相对于工作目录 standalone_examples/deprecated/api/isaacsim.cortex.framework 编写。

每个示例启动 Isaac Sim 时都不会播放仿真。按播放按钮以运行仿真和行为。

使用决策网络设计响应性#

我们从一个简单的行为开始，该行为让机器人在避开被方块占据的区域的同时啄食地面。

状态机实现#

peck_state_machine 模块将此简单的啄食行为实现为状态机。使用以下命令运行该行为：

isaac_python franka_examples_main.py --behavior=peck_state_machine

Franka 机器人将在避开方块的同时啄食地面。您可以移动方块，以观察这如何影响机器人选择啄食的位置。

实现方式非常直观：

class PeckState(DfState):
    ...

    def enter(self):
        # On entry, sample a target.
        target_p = self.sample_target_p_away_from_obs()
        target_q = make_target_rotation(target_p)
        self.target = PosePq(target_p, target_q)
        approach_params = ApproachParams(direction=np.array([0.0, 0.0, -0.1]), std_dev=0.04)
        self.context.robot.arm.send_end_effector(self.target, approach_params=approach_params)

    def step(self):
        target_dist = np.linalg.norm(self.context.robot.arm.get_fk_p() - self.target.p)
        if target_dist < 0.01:
            return None  # Exit
        return self  # Keep going


def make_decider_network(robot):
    root = DfStateMachineDecider(
        DfStateSequence(
            [DfCloseGripper(width=0.0), PeckState(), DfTimedDeciderState(DfLift(height=0.05), activity_duration=0.25)],
            loop=True,
        )
    )
    return DfNetwork(root, context=PeckContext(robot))

然而，在简单的状态机实现中，响应性方面存在一个错误情况。尝试将一个方块直接移动到当前啄食路径上。行为将挂起，因为无法成功地将末端执行器移动到目标位置。

状态机在进入时选择目标，并在整个行为过程中保持其固定。因此，它不会对变化的环境做出反应。状态机本身并不擅长建模响应性行为。我们将使用决策网络来解决这个问题。

决策网络实现#

peck_decider_network 模块通过添加一个响应式的 Dispatch 决策节点来增强此简单的啄食行为。使用以下命令运行该行为：

isaac_python franka_examples_main.py --behavior=peck_decider_network

决策器网络使用逻辑状态监视器来监视是否存在阻碍末端执行器到达当前啄击目标的方块。如果存在，则触发系统重新选择目标。

class PeckContext(DfContext):
    def __init__(self, robot):
        super().__init__(robot)
        self.robot = robot
        self.reset()
        self.add_monitors([PeckContext.monitor_active_target_p])

        def reset(self):
            self.is_done = True
            self.active_target_p = None

        # Monitor whether a block is too close to the active target.
        def monitor_active_target_p(self):
            if self.active_target_p is not None and self.is_near_obs(self.active_target_p):
                self.is_done = True

        # Called by a special state at the end of the peck behavior.
        def set_is_done(self):
            self.is_done = True

    ...


class PeckState(DfState):
    def enter(self):
        target_p = self.context.active_target_p
        target_q = make_target_rotation(target_p)
        self.target = PosePq(target_p, target_q)
        approach_params = ApproachParams(direction=np.array([0.0, 0.0, -0.1]), std_dev=0.04)
        self.context.robot.arm.send_end_effector(self.target, approach_params=approach_params)

    def step(self):
        # Send the command each cycle so exponential smoothing will converge.
        target_dist = np.linalg.norm(self.context.robot.arm.get_fk_p() - self.target.p)
        if target_dist < 0.01:
            return None  # Exit
        return self  # Keep going


class Dispatch(DfDecider):
    def __init__(self):
        super().__init__()

        self.add_child("choose_target", ChooseTarget())
        self.add_child(
            "peck",
            DfStateMachineDecider(
                DfStateSequence(
                    [
                        CloseGripper(),
                        PeckState(),
                        DfTimedDeciderState(DfLift(height=0.05), activity_duration=0.25),
                        DfWriteContextState(lambda context: context.set_is_done()),
                    ]
                )
            ),
        )

    def decide(self):
        if self.context.is_done:
            return DfDecision("choose_target")
        else:
            return DfDecision("peck")


def make_decider_network(robot):
    return DfNetwork(Dispatch(), context=PeckContext(robot))

请注意，如果监视器 monitor_active_target_p() 检测到目标附近有过近的方块，顶层 Dispatch() 决策器可以立即抢占顺序执行的“啄击”状态机。

尝试将方块移动到末端执行器下方。这一次，每当方块过于接近末端执行器的目标时，系统会立即选择另一个目标。

设计逻辑状态上下文#

现在让我们实现一个简单的游戏，其中机器人啄击最近被移动的方块。我们使用决策器网络来简化对方块移动的响应编程。此示例展示了当逻辑状态被上下文对象充分建模时，行为可以变得多么简单。

该行为在 peck_game 中实现。使用以下命令运行该行为：

isaac_python franka_examples_main.py --behavior=peck_game

PeckContext 类负责监视方块移动并相应地设置最新的活动目标。它还监视末端执行器是否接近方块，这对于决定机器人在移动到下一个目标之前是否需要从方块上抬起很有用。

class PeckContext(DfLogicalState):
    def __init__(self, robot):
        super().__init__()
        self.robot = robot

        self.monitors = [
            PeckContext.monitor_block_movement,
            PeckContext.monitor_active_target_p,
            PeckContext.monitor_active_block,
            PeckContext.monitor_eff_block_proximity,
            PeckContext.monitor_diagnostics,
        ]

基于上下文对象监视的逻辑状态，主要逻辑可以简洁地编写为以下 Dispatch 决策器节点：

class Dispatch(DfDecider):
    def enter(self):
        self.add_child("peck", PeckAction())
        self.add_child("lift", DfLift(height=0.1))
        self.add_child("go_home", make_go_home())

    def decide(self):
        if self.context.is_eff_close_to_inactive_block:
            return DfDecision("lift")

        if self.context.has_active_block:
            return DfDecision("peck")

        # If we aren't doing anything else, always just go home.
        return DfDecision("go_home")

从字面上看，它根据以下规则进行推理：如果末端执行器靠近一个非活动块，我们只需要将其抬起（因为它太近了）。否则，如果存在一个活动块，则移动到该块处进行啄取。如果没有活动块，则返回初始位置。这个 decide() 方法每个周期都会被触发，因此一旦活动块监视器检测到某个块发生了移动，就会立即对其做出响应。

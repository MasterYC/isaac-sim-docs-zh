针对独立安装程序构建 C++ USD 插件#

Isaac Sim 独立安装程序提供了 USD 运行时共享库（位于 extscache/omni.usd.libs-*/bin/）以及匹配的 Python 绑定，但未提供编译自定义原生 USD 插件所需的 C++ 头文件或 pxrConfig.cmake 包配置文件。本页介绍了一种受支持的工作流，用于获取匹配的头文件，并将原生插件链接到 Isaac Sim 在运行时加载的 USD 库。

如果您基于 Kit C++ 扩展模板在源代码树内进行开发，请改用 CLI 扩展模板 中描述的工作流。以下页面专门介绍如何针对已安装的 Isaac Sim 包构建独立的原生 USD 插件（即在运行时通过 Plug::Load() 发现并加载的插件）。

何时需要此工作流#

当您构建必须加载到 Isaac Sim 进程中的 C++ USD 插件，且从独立安装程序而非源代码仓库开始工作时，需要使用此工作流。

USD 在运行时通过遍历 PXR_PLUGINPATH_NAME、解析其 plugInfo.json，然后调用 Plug::Load() 来发现您的插件。 Plug::Load() 会对您的共享库执行常规的 dlopen()，这意味着您的插件必须与 Isaac Sim 进程中已加载的 USD 运行时库保持 ABI 兼容。

先决条件#

在独立安装程序中，找到捆绑的 packman 启动器以及固定 Isaac Sim 所有外部依赖项的清单文件：

<isaac-sim-install>/kit/dev/tools/packman/packman
<isaac-sim-install>/kit/dev/all-deps.packman.xml

打开 all-deps.packman.xml 并找到 usd-release 依赖项条目。它包含一个内部的 <package> 元素，其 name 和 version 属性标识了 Isaac Sim 编译时所针对的确切 OpenUSD 构建版本——例如：

<dependency name="usd-release">
    <package name="usd.py312.manylinux_2_35_x86_64.stock.release"
             version="0.25.11.kit.2-gl.19811"/>
</dependency>

name 编码了平台和 Python 版本信息；请将这两个属性原样复制到您自己的 packman 项目文件中（参见下文）。

您还需要安装程序中包含的 Python 开发头文件：

<isaac-sim-install>/kit/python/include/python3.XX/

USD 的 Ar 和 Tf 头文件通过 TfPyObjWrapper 间接包含 Boost.Python，因此即使是不直接调用 Python 的插件，也必须能够 #include <Python.h>。

使用 Packman 拉取匹配的 USD 开发构件#

在插件源代码旁边创建一个小型 packman 项目文件——例如，usd-dev.packman.xml：

<project toolsVersion="6.0">
  <!--
    Replace PACKAGE_NAME_FROM_ALL_DEPS and VERSION_FROM_ALL_DEPS with
    the inner <package> element's name and version copied verbatim
    from the usd-release entry in
    <isaac-sim-install>/kit/dev/all-deps.packman.xml.
  -->
  <dependency name="usd-release" linkPath="_deps/usd-release">
    <package name="PACKAGE_NAME_FROM_ALL_DEPS" version="VERSION_FROM_ALL_DEPS"/>
  </dependency>
</project>

然后使用安装程序捆绑的 packman 拉取匹配的开发构件：

<isaac-sim-install>/kit/dev/tools/packman/packman pull \
    usd-dev.packman.xml --platform linux-x86_64

packman pull 完成后，_deps/usd-release/ 将包含 USD 开发树：

_deps/usd-release/
  include/
    pxr/        # OpenUSD C++ headers; in OpenUSD 25.x and later,
                # Boost.Python is vendored under pxr/external/boost/
    tbb/        # TBB headers used by USD
  lib/          # Packman-built USD libraries (do NOT link against these)
  pxrConfig.cmake
  cmake/

使用 include/ 进行编译。pxrConfig.cmake 包含在发布包中，但它会间接 find_dependency() 加载 TBB、MaterialX、Imath 和 OpenSubdiv 的 *Config.cmake 文件，而 usd-release packman 发布包中不包含这些文件。因此，普通的 find_package(pxr REQUIRED) 无法解析。下一节中的配方通过让 CMake 直接指向 include/ 来规避此问题。**不要**将您的插件链接到 _deps/usd-release/lib/ 下的库——参见下一节。

编译和链接#

构建需要：

  • 来自 _deps/usd-release/include/ 和 <isaac-sim-install>/kit/python/include/python3.XX/ 的头文件。

  • 链接目录 <isaac-sim-install>/extscache/omni.usd.libs-*/bin/ （即 Isaac Sim 在运行时加载的库），而不是 _deps/usd-release/lib/。

  • 链接库 usd_ar、usd_sdf、usd_tf、usd_plug、 usd_vt（根据插件需求添加更多库）。

  • 在这些库周围使用链接器标志 -Wl,--no-as-needed。

相同的路径和标志适用于任何构建系统，但各工具表达它们的方式不同——有些直接接受绝对文件系统路径，有些则鼓励将预构建库封装为目标，或通过工作区本地路径进行引用。请使用符合你构建系统习惯的机制。例如，在 CMake 中：

cmake_minimum_required(VERSION 3.20)
project(my_usd_plugin LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# Python development headers shipped inside Isaac Sim.
set(ISAAC_SIM_INSTALL "/path/to/isaac-sim" CACHE PATH "Isaac Sim install root")
set(ISAAC_SIM_USD_LIBS "${ISAAC_SIM_INSTALL}/extscache/omni.usd.libs-<version>/bin"
    CACHE PATH "Directory containing libusd_*.so shipped with Isaac Sim")
set(ISAAC_SIM_PYTHON_INCLUDE "${ISAAC_SIM_INSTALL}/kit/python/include/python3.XX"
    CACHE PATH "Python development headers shipped inside Isaac Sim")

add_library(my_usd_plugin SHARED my_usd_plugin.cpp)

# Use the packman-pulled headers directly; do not call find_package(pxr).
# See the prose above for why pxrConfig.cmake is intentionally bypassed.
target_include_directories(my_usd_plugin PRIVATE
    "${CMAKE_SOURCE_DIR}/_deps/usd-release/include"
    "${ISAAC_SIM_PYTHON_INCLUDE}"
)

# Link against the USD libraries Isaac Sim actually loads at runtime,
# not the libraries packman pulled. Linking against packman's libs
# produces a binary that resolves to one set of pxrInternal_v0_* symbols
# at link time and a (potentially different) set at runtime, which
# manifests as undefined-symbol errors inside Plug::Load().
target_link_directories(my_usd_plugin PRIVATE "${ISAAC_SIM_USD_LIBS}")
target_link_libraries(my_usd_plugin PRIVATE
    -Wl,--no-as-needed
    usd_ar
    usd_sdf
    usd_tf
    usd_plug
    usd_vt
    -Wl,--as-needed
)

有两个链接行细节需要注意：

  1. 必须在 usd_* 库周围使用 -Wl,--no-as-needed。 如果没有它，链接器会丢弃那些仅通过插件类的 C++ vtable 和 RTTI 被引用的任何 USD 库——而对于任何由 Plug 发现的类，这实际上涵盖了你依赖的所有 USD 库。结果是插件链接成功，但在运行时在 Plug::Load() 内部失败，并针对 pxrInternal_v0_*::... 出现未定义符号错误。

  2. 传递给链接器的库搜索路径必须是 <isaac-sim-install>/extscache/omni.usd.libs-*/bin/，而不是 _deps/usd-release/lib/。通过 packman 拉取的库虽然使用相同的 OpenUSD 版本构建，但不一定是 Isaac Sim 随附的完全相同的二进制文件，任何不匹配（包括构建标志或符号版本控制）都会导致静默的 ABI 破坏。

在运行时，设置 PXR_PLUGINPATH_NAME（或将你的 plugInfo.json 放置在 USD 已扫描的目录下），以便 Isaac Sim 在打开阶段时发现你的插件。

插件源代码要求#

USD 的插件注册宏（TF_REGISTRY_FUNCTION、 TF_REGISTRY_FUNCTION_WITH_TAG）在全局命名空间作用域展开，并引用 非限定名 Tf_RegistryInit 以及每个库的标签 MFB_ALT_PACKAGE_NAME。以下两项源代码级要求是强制性的：

  1. 在编译时定义三个预处理器宏，每个插件目标对应一个。这些宏用于向 USD 的注册表标识插件；其值通常采用同一短名称的三种大小写变体。在 CMake 中，示例如下：

    target_compile_definitions(my_usd_plugin PRIVATE
    MFB_PACKAGE_NAME=myUsdPlugin
    MFB_ALT_PACKAGE_NAME=myUsdPlugin
    MFB_PACKAGE_MODULE=MyUsdPlugin
)

  2. 在任何使用 TF_REGISTRY_FUNCTION 的翻译单元顶部附近放置 PXR_NAMESPACE_USING_DIRECTIVE，以便宏展开中的非限定名 Tf_RegistryInit 能够解析到 OpenUSD 的内联命名空间：

    #include <pxr/pxr.h>
#include <pxr/base/tf/type.h>
#include <pxr/usd/ar/resolver.h>

PXR_NAMESPACE_USING_DIRECTIVE

class MyResolver : public ArResolver { /* ... */ };

TF_REGISTRY_FUNCTION(TfType) {
    TfType::Define<MyResolver, TfType::Bases<ArResolver>>();
}

若缺少其中任何一项，插件将无法编译。

保持头文件与运行时同步#

OpenUSD 将其发布版本编码在 pxrInternal_v0_* 内联命名空间中。针对某个 OpenUSD 发布版本编译的插件，无法加载到链接了不同 OpenUSD 发布版本的进程中——修饰后的符号名称将不匹配，并且你会在 Plug::Load() 中看到未定义符号错误。

Isaac Sim 中捆绑的 OpenUSD 版本可能会随发布版本而变化。下表记录了已知的映射关系；请务必通过检查目标安装程序中的 all-deps.packman.xml 内的 usd-release 条目来确认确切版本。

Isaac Sim 版本

OpenUSD 版本

内联命名空间（pxrInternal_v0_*）

5.1.0

24.05

pxrInternal_v0_24_5__pxrReserved__

注意

本页中的 packman 方法会自动拉取与您所针对的安装程序匹配的 OpenUSD 头文件，因此您无需自行读取内联命名空间字符串。此处列出这些字符串仅作为诊断辅助：如果您看到一个包含 pxrInternal_v0_24_5 的未定义符号，但您的插件是针对 pxrInternal_v0_25_11 编译的，则说明头文件和运行时不同步，且链接步骤指向了错误的 USD 库。在依赖此表之前，请使用 nm -D --defined-only extscache/omni.usd.libs-*/bin/libusd_tf.so | head 确认您的安装程序的确切命名空间字符串。

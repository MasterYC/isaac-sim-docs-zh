容器安装#

建议使用 Isaac Sim 的容器安装方式，以便在远程无头服务器或云端部署，使用运行 Linux 的 Docker 容器。

另请参阅

  • Workstation 与 Docker 之间的差异

容器设置#

  1. 确保您的系统满足运行 NVIDIA Isaac Sim 的系统要求。

  2. 安装 Docker：

# Docker installation using the convenience script
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# Post-install steps for Docker
sudo groupadd docker
sudo usermod -aG docker $USER
newgrp docker

# Verify Docker
docker run hello-world

另请参阅

  • 在 Ubuntu 上安装 Docker Engine

  • Linux 安装后步骤

  1. 安装 NVIDIA Container Toolkit：

# Configure the repository
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg \
    && curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
    sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
    sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list \
    && \
    sudo apt-get update

# Install the NVIDIA Container Toolkit packages
sudo apt-get install -y nvidia-container-toolkit
sudo systemctl restart docker

# Configure the container runtime
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker

# Verify NVIDIA Container Toolkit
docker run --rm --runtime=nvidia --gpus all nvcr.io/nvidia/cuda:12.8.0-base-ubuntu24.04 nvidia-smi

注意

  • 安装最新版本的 NVIDIA Container Toolkit 以获取安全修复。

  • 验证步骤使用 NGC 托管的 CUDA 基础镜像（nvcr.io/nvidia/cuda），该镜像是公开的，可避免 Docker Hub 的匿名拉取速率限制（HTTP 429 Too Many Requests）。该镜像支持多架构，因此同一标签可在 Linux x86_64 和 aarch64 上运行。

  • 如果从 Docker Hub 拉取镜像的步骤（例如 docker run hello-world）因 429 Too Many Requests 失败，请先运行 docker login 或稍后重试，因为 Docker Hub 对匿名拉取实施速率限制。

容器部署#

本节介绍如何在无头模式下运行 NVIDIA Isaac Sim 容器并启用直播流。

步骤：

  1. 设置并安装容器先决条件。请参阅上面的 Container Setup。

  2. 运行以下命令以确认 GPU 驱动程序版本：

nvidia-smi

  1. 拉取 Isaac Sim 容器：

docker pull nvcr.io/nvidia/isaac-sim:6.1.0

  1. 在主机上创建缓存卷挂载。每个目录都映射到下面 docker run 命令中的容器卷挂载：

mkdir -p ~/docker/isaac-sim/cache/main
mkdir -p ~/docker/isaac-sim/cache/computecache
mkdir -p ~/docker/isaac-sim/cache/kit
mkdir -p ~/docker/isaac-sim/config
mkdir -p ~/docker/isaac-sim/data
mkdir -p ~/docker/isaac-sim/logs
mkdir -p ~/docker/isaac-sim/pkg
mkdir -p ~/.cache/ov/hub
sudo chown -R 1234:1234 ~/docker/isaac-sim ~/.cache/ov/hub

  1. 使用交互式 Bash 会话运行 Isaac Sim 容器：

docker run --name isaac-sim --entrypoint bash -it --gpus all -e "ACCEPT_EULA=Y" --rm --network=host \
    -e "PRIVACY_CONSENT=Y" \
    -v ~/docker/isaac-sim/cache/main:/isaac-sim/.cache:rw \
    -v ~/docker/isaac-sim/cache/computecache:/isaac-sim/.nv/ComputeCache:rw \
    -v ~/docker/isaac-sim/cache/kit:/isaac-sim/kit/cache:rw \
    -v ~/docker/isaac-sim/logs:/isaac-sim/.nvidia-omniverse/logs:rw \
    -v ~/docker/isaac-sim/config:/isaac-sim/.nvidia-omniverse/config:rw \
    -v ~/docker/isaac-sim/data:/isaac-sim/.local/share/ov/data:rw \
    -v ~/docker/isaac-sim/pkg:/isaac-sim/.local/share/ov/pkg:rw \
    -v ~/.cache/ov/hub:/var/cache/hub:rw \
    -u 1234:1234 \
    nvcr.io/nvidia/isaac-sim:6.1.0

警告

Isaac Sim 以用户 1234:1234 身份运行。:rw 挂载选项不会授予主机上的写权限。在绑定挂载主机目录以允许写入用户数据之前，请授予 UID 1234 写访问权限。

如果 Ubuntu 上不可用 setfacl，请使用 sudo apt install acl 安装 acl 包。

例如，保留 stage 目录的现有所有者，并使用 POSIX 访问控制列表 (ACL) 使新文件对主机用户和容器用户均可写：

mkdir -p ~/my-stages
setfacl -m u:1234:rwx ~/my-stages
setfacl -d -m u:1234:rwx ~/my-stages
setfacl -d -m u:$(id -u):rwx ~/my-stages

然后将以下卷添加到 docker run 命令中，并将 stage 保存在 /workspace 下：

-v ~/my-stages:/workspace:rw

重要

--network=host 对于 WebRTC 直播流是必需的。NVIDIA 流式传输 SDK 将其 UDP 媒体套接字绑定到 ISAACSIM_HOST 地址，该地址必须是容器内的真实网络接口。Docker 桥接网络（-p 端口发布）不起作用，因为主机 IP 在容器的网络命名空间内不可用——信令可能连接，但视频流不会。

注意

  • Isaac Sim 容器现在以无根用户身份运行。

  • Isaac Sim 容器现已支持多架构。同一标签可在 Linux x86_64 和 aarch64 系统上运行。

  • 使用 -e "ACCEPT_EULA=Y" 标志即表示您接受位于 NVIDIA Omniverse 许可协议 的镜像许可协议。

  • 使用 -e "PRIVACY_CONSENT=Y" 标志即表示您选择加入位于 数据收集与使用 的数据收集协议。您可以不设置此标志以选择退出。

  • -e "PRIVACY_USERID=<email>" 标志可用于可选地标记会话日志。

  • 如果容器内检测 GPU 时出现问题，请添加 --runtime=nvidia 标志。

  • 企业用户请参阅 Enterprise Nucleus Server。

  • 如果没有可用的 Nucleus 服务器，Isaac Sim 容器将使用云端资产。

使用独立的 Nucleus 服务器时：

  • 请参阅 连接 Docker 容器时的问题，以暴露容器的所有端口并连接到外部 Nucleus 服务器。

  • 请参阅 设置默认 Nucleus 服务器 以设置默认 Nucleus 服务器。

  • 请参阅 设置连接 Nucleus 服务器的默认用户名和密码，以设置任何 Nucleus 服务器的默认凭据。

  1. 检查您的系统是否与 Isaac Sim 兼容：

./isaac-sim.compatibility_check.sh --/app/quitAfter=10 --no-window

注意

  • 若要单独运行兼容性检查器：

docker run --entrypoint bash -it --gpus all --rm --network=host \
    nvcr.io/nvidia/isaac-sim:6.1.0 ./isaac-sim.compatibility_check.sh --/app/quitAfter=10 --no-window

  • 如果您的系统兼容，您应该会看到文本“System checking result: PASSED”。

  1. 以原生直播模式启动 Isaac Sim：

./runheadless.sh -v

注意

  • 在运行直播流客户端之前，必须已加载并准备好 Isaac Sim 应用。

    Isaac Sim 完全加载可能需要几分钟时间。

  • 使用 -v 标志可在预热着色器缓存期间显示额外日志。

  • 要确认这一点，请在控制台或日志中查找以下行：

Isaac Sim Full Streaming App is loaded.

  • 首次加载 Isaac Sim 时，缓存着色器需要一段时间。后续运行 Isaac Sim 的速度会更快，因为着色器已缓存，并且在容器运行时挂载了缓存。

  • 有关在使用容器时使 Isaac Sim 配置和缓存持久化的信息，请参阅 Save Isaac Sim Configs on Local Disk。

  1. 连接原生 Isaac Sim WebRTC Streaming Client 以查看 Isaac Sim。 从 Latest Release 部分下载该客户端，输入主机的 IP 地址，然后单击 Connect。

    或者，如果您更喜欢无需安装客户端的基于浏览器的查看器，请改用下面的 Docker Compose deployment，而不是上述手动 docker run 工作流。

  2. 前往 Isaac Sim 基础 开始您的第一个教程。

注意

  • 使用未连接 Nucleus 的 Isaac Sim 容器时，某些使用 Content Browser 的教程可能无法正常工作。

  • 建议使用 Omniverse Launcher 中的 Workstation Isaac Sim 来运行所有教程。

  • Isaac Sim 容器仅支持以无头模式运行我们的 Python 应用和独立示例。

  • 对于直播（livestreaming）等某些功能，最新的 NVIDIA 驱动程序可能无法得到完全支持。有关推荐的驱动程序，请参阅 Technical Requirements。

  • 另请参阅 Isaac Sim Dockerfiles 以构建您自己的自定义 Isaac Sim 容器。

  • 您可以调试 在 Docker 中运行的 Python 脚本。

  • 过期的卷挂载：Docker 卷挂载目录中的旧缓存数据可能导致崩溃、配置错误或直播失败。请删除现有挂载并重新创建它们：

    sudo rm -rf ~/docker/isaac-sim
mkdir -p ~/docker/isaac-sim/cache/main
mkdir -p ~/docker/isaac-sim/cache/computecache
mkdir -p ~/docker/isaac-sim/cache/kit
mkdir -p ~/docker/isaac-sim/config
mkdir -p ~/docker/isaac-sim/data
mkdir -p ~/docker/isaac-sim/logs
mkdir -p ~/docker/isaac-sim/pkg
mkdir -p ~/.cache/ov/hub
sudo chown -R 1234:1234 ~/docker/isaac-sim ~/.cache/ov/hub

  • 第二个浏览器无法连接：一次只能有一个浏览器标签页或窗口连接到 Isaac Sim。在打开新会话之前，请关闭现有的浏览器会话。

  • Web Viewer 中剪贴板无法工作：浏览器剪贴板 API 需要安全上下文。当通过 HTTP 从非 localhost 地址访问 Web Viewer 时，剪贴板转发会被阻止。 在 Chrome 中，打开 chrome://flags/#unsafely-treat-insecure-origin-as-secure，添加 Web Viewer URL（例如 http://192.168.1.100:8210），然后重新启动浏览器。

提示

要从源代码构建 Docker 镜像而不是从 NGC 拉取，请参阅 Docker Build Tools README。 该 README 还涵盖了使用专用 GPU 的多实例部署、云 VM 配置（AWS、GCP、Azure）以及高级 Docker 选项。

容器中的扩展热重载#

Isaac Sim 会在 Python 扩展的源文件发生更改时重新加载该扩展，但默认情况下，容器内用于检测这些更改的文件监视器是禁用的。 在主机上对挂载的扩展所做的编辑会被忽略，直到应用程序重启。

要针对容器开发扩展，请将您的扩展目录挂载到容器中，并在启动时传递 --/app/extensions/fsWatcherEnabled=true。 随附的体验已经搜索 extsUser，因此挂载到该位置无需额外参数：

docker run --name isaac-sim --entrypoint bash -it --gpus all -e "ACCEPT_EULA=Y" --rm --network=host \
    -e "PRIVACY_CONSENT=Y" \
    -v ~/my-extensions:/isaac-sim/extsUser:ro \
    -u 1234:1234 \
    nvcr.io/nvidia/isaac-sim:6.1.0

然后使用该设置启动 Isaac Sim：

./isaac-sim.sh --enable my.custom.extension --/app/extensions/fsWatcherEnabled=true

该设置同样适用于直播流：

./runheadless.sh --enable my.custom.extension --/app/extensions/fsWatcherEnabled=true

现在，在主机上保存更改会在运行中的容器内关闭并重启该扩展。

注意

  • 若要将扩展挂载到 extsUser 以外的位置，请添加 --ext-folder <container path>。

  • 在其 extension.toml 中于 [core] 下设置了 reloadable = false 的扩展永远不会被重新加载，即使启用了监视器也是如此。 几个随附的扩展通过这种方式选择退出。

  • 该设置必须在启动时提供。监视器会在启动时为每个扩展搜索路径创建，因此在正在运行的应用程序中启用该设置没有任何效果。

  • 文件更改通知可以通过绑定挂载传播，因此无需额外的 Docker 选项。

  • 容器用户必须能够读取挂载的目录，默认情况下该用户为 1234:1234。

  • 在容器中，监视器默认处于禁用状态，因为对大型挂载目录树进行递归监视会增加启动时间并占用文件句柄。仅在进行开发时启用它。

集线器工作站缓存#

Hub Workstation Cache 是一项服务，它通过在本地缓存存储派生数据来加速 USD 工作流。在容器中运行 Isaac Sim 时，Hub 也应作为容器在同一主机上运行，以便所有基于 Kit 的客户端都能受益于共享缓存。

注意

Hub Workstation Cache 专为本地工作站使用而设计——例如，在本地工作站上进行的裸机运行或容器运行。它不适用于多用户服务器或云部署。有关分布式或云缓存，请参阅 Derived Data Cache Service (DDCS)。

Hub Workstation Cache 镜像是公开的，无需登录 nvcr.io 即可拉取。如果您的 Docker 客户端已登录 nvcr.io，NGC 会在允许拉取之前检查您的 NGC 组织是否已接受相关条款。

在使用 Docker 凭据拉取 Hub 镜像之前，请在浏览器中打开 Hub Workstation Cache Container 页面， 登录 NGC，选择版本 2.2.0，并接受相关条款。NGC 要求每个 NGC 组织接受一次条款。有关官方 NGC 流程，请参阅 NGC Accepting Terms Before Downloading。

如果 Docker 报告 DENIED 并带有 Please accept license on the browser to be able to download，请在浏览器中为 docker login nvcr.io 所使用的同一 NGC 组织接受条款，或者在匿名拉取此公共镜像之前从 nvcr.io 注销：

$ docker logout nvcr.io
$ docker pull nvcr.io/nvidia/omniverse/hub_workstation_cache:2.2.0

在启动 Isaac Sim 之前启动 Hub 容器：

mkdir -p ~/.cache/ov/hub
sudo chown -R 1234:1234 ~/.cache/ov/hub
docker run --name hub-cache --rm -d --network=host \
    -v ~/.cache/ov/hub:/var/cache/hub:rw \
    -u 1234:1234 \
    nvcr.io/nvidia/omniverse/hub_workstation_cache:2.2.0

容器运行后，可在 http://localhost:14090/index.html 访问 Hub 设置 UI。

Isaac Sim 容器已预配置为通过镜像中内置的以下环境变量在运行时发现 Hub：

变量

值

用途

HUB__CACHE__PATH

/var/cache/hub

告知本地 Hub 可执行文件缓存的位置

HUB__ARGS__DETECT_ONLY

true

防止客户端启动其自己的 Hub 实例

OMNICLIENT_HUB_EXE

/usr/local/bin/hub

用于客户端协调的 Hub 可执行文件路径

Isaac Sim docker run 示例中的 ~/.cache/ov/hub:/var/cache/hub 卷挂载将同一主机目录映射到两个容器中，以便它们共享缓存。需要 --network=host，以便 Isaac Sim 内部的 Hub 客户端能够访问 localhost 上的 Hub 服务。

注意

支持在没有 Hub 服务的情况下运行 Isaac Sim。由于容器设置了 HUB__ARGS__DETECT_ONLY=true，Hub 客户端会在启动期间查找 Hub 服务，当没有服务监听时，它会在大约十秒内记录数十条警告：

[Warning] [carb.omniclient.plugin] OmniHub: Hub encountered error. Trying to reconnect to Hub.
retry_reason="Hub failed to launch: ..."

随后重试停止，Isaac Sim 在无缓存的情况下继续运行。在该配置下，这些警告是预期行为，并不表示启动失败。启动上述 Hub 容器即可消除这些警告。

有关更多详细信息，请参阅 Hub as a Docker Container 文档。

Docker Compose 部署（Isaac Sim + Web Viewer）#

Docker Compose 可以一起部署 Isaac Sim 和基于 Web 的 WebRTC 流式客户端。这是上述手动 docker run 工作流的一种更简单的替代方案，并且不需要下载原生流式客户端。

有关 Docker Compose 配置、多实例部署和环境变量的完整详细信息，请参阅 Docker README。

tools/docker/ 中的 docker-compose.yml 会自动处理卷挂载、GPU 分配、网络和健康检查。Web viewer 基于 NVIDIA Omniverse Web SDK 构建。

注意

Docker Compose Web 查看器部署仅支持 Ubuntu 主机和 DGX Spark 系统。 不支持 Windows 主机（包括 WSL）。

警告

Isaac Sim 和 Web 查看器专为私有/受信任网络设计。它们不包含身份验证或加密功能。如果您需要通过互联网公开访问它们，请添加带有 HTTPS/TLS 和身份验证的反向代理（例如，使用 SSL 证书和基本身份验证的 nginx）。用户有责任确保任何面向公众的部署的安全性。

快速入门：

# Create cache/log mounts (use uid 1234 to match container user)
mkdir -p ~/docker/isaac-sim/{cache/main,cache/computecache,cache/kit,config,data,logs,pkg}
mkdir -p ~/.cache/ov/hub
sudo chown -R 1234:1234 ~/docker/isaac-sim ~/.cache/ov/hub

# Build the Isaac Sim image (one-time)
./tools/docker/prep_docker_build.sh --build --x86_64
./tools/docker/build_docker.sh --x86_64

# Launch both services
docker compose -p isim -f tools/docker/docker-compose.yml up --build -d

# Check the web viewer URL
docker compose -p isim logs web-viewer

注意

在 DGX Spark 上，请在上述构建命令中使用 --aarch64 代替 --x86_64。

在基于 Chromium 的浏览器中打开日志中显示的 URL（例如 http://<host-ip>:8210）。

如果 Docker Compose 在之前的测试后报告 Hub 启动或连接问题，请从 Hub Workstation Cache 重启 Hub 容器并重试 Docker Compose。

若要使用预构建的 NGC 镜像而非本地构建：

ISAAC_SIM_IMAGE=nvcr.io/nvidia/isaac-sim:6.1.0 docker compose -p isim -f tools/docker/docker-compose.yml up --build -d

要停止：

docker compose -p isim -f tools/docker/docker-compose.yml down

注意

  • Web 查看器在构建时固化了信令主机和端口。更改 --build 或端口变量时，请使用 ISAACSIM_HOST。

  • 如果 Docker 启动在构建中断、解压失败或磁盘满事件后失败，请清理生成的 Docker 构建上下文，并从已知良好的构建输出重新构建。有关恢复步骤，请参阅 Docker README 故障排除部分。

  • Docker Compose 支持多实例部署，包括专用 GPU、自定义信号/流端口等。有关完整的配置详细信息，请参阅 Docker README。

带 GUI 的容器部署#

本节介绍如何运行带 GUI 的 NVIDIA Isaac Sim 容器。

步骤：

  1. 设置并安装容器先决条件。请参阅上面的 Container Setup。

  2. 运行以下命令以确认 GPU 驱动程序版本：

nvidia-smi

  1. 拉取 Isaac Sim 容器：

docker pull nvcr.io/nvidia/isaac-sim:6.1.0

  1. 在主机上创建缓存卷挂载。每个目录都映射到下面 docker run 命令中的容器卷挂载：

mkdir -p ~/docker/isaac-sim/cache/main
mkdir -p ~/docker/isaac-sim/cache/computecache
mkdir -p ~/docker/isaac-sim/cache/kit
mkdir -p ~/docker/isaac-sim/config
mkdir -p ~/docker/isaac-sim/data
mkdir -p ~/docker/isaac-sim/logs
mkdir -p ~/docker/isaac-sim/pkg
mkdir -p ~/.cache/ov/hub
sudo chown -R 1234:1234 ~/docker/isaac-sim ~/.cache/ov/hub

  1. 使用交互式 Bash 会话运行 Isaac Sim 容器：

xhost +local:
docker run --name isaac-sim --entrypoint bash -it --gpus all -e "ACCEPT_EULA=Y" --rm --network=host \
    -e "PRIVACY_CONSENT=Y" \
    -v $HOME/.Xauthority:/isaac-sim/.Xauthority \
    -e DISPLAY \
    -v ~/docker/isaac-sim/cache/main:/isaac-sim/.cache:rw \
    -v ~/docker/isaac-sim/cache/computecache:/isaac-sim/.nv/ComputeCache:rw \
    -v ~/docker/isaac-sim/cache/kit:/isaac-sim/kit/cache:rw \
    -v ~/docker/isaac-sim/logs:/isaac-sim/.nvidia-omniverse/logs:rw \
    -v ~/docker/isaac-sim/config:/isaac-sim/.nvidia-omniverse/config:rw \
    -v ~/docker/isaac-sim/data:/isaac-sim/.local/share/ov/data:rw \
    -v ~/docker/isaac-sim/pkg:/isaac-sim/.local/share/ov/pkg:rw \
    -v ~/.cache/ov/hub:/var/cache/hub:rw \
    -u 1234:1234 \
    nvcr.io/nvidia/isaac-sim:6.1.0

  1. 检查您的系统是否与 Isaac Sim 兼容：

./isaac-sim.compatibility_check.sh

  1. 启动带 GUI 的 Isaac Sim：

./runapp.sh

  1. 前往 Isaac Sim 基础 开始您的第一个教程。

警告

  • 通常不建议在容器中以 GUI 模式运行 Isaac Sim。

  • 应用程序体验可能不符合预期。如需完整的 GUI 应用体验，请使用 工作站安装 运行 Isaac Sim。

  • GUI 模式需要 真实的本地显示器。它无法在远程或虚拟显示器（例如 NoMachine、VNC 或 DCV）或没有连接显示器的无头服务器上工作：渲染器无法创建 Vulkan 交换链，并因 Failed to initialize graphics environment 而中止（vkCreateSwapchainKHR 返回 VkResult: UNKNOWN_ERROR）。

  • 若要在远程或无头主机上运行 Isaac Sim，请改用带直播功能的无头模式。

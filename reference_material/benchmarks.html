在本地硬件上测量 KPI#

可以使用 standalone_examples/benchmarks 中提供的 Python 脚本测量 Isaac Sim KPI。选择以下类别以查看基准测试详细信息、命令和配置选项，以及类似工作流的优化提示。

更具体的优化指南可在 Isaac Sim 性能优化手册 中找到。

注意

命令以 bash 语法提供（适用于 Ubuntu）。对于 Windows，请将 .sh 替换为 .bat，并将多行命令中的 \ 替换为 `。

用于测量应用程序初始化和场景加载性能的基准测试。

Startup Time (Async)

目的： 在无头模式下测量 Isaac Sim 初始化时间，且不包含阻塞操作。

测量内容： 从应用程序启动到就绪状态的时间，在日志中通过 Runtime 针对 phase: startup 进行测量。

命令：

./isaac-sim.sh --no-window --/app/quitAfter=200 --/app/file/ignoreUnsavedOnExit=1 \
  --enable isaacsim.benchmark.services

结果解读： 在控制台输出中查找以下内容：

[INFO] Runtime for phase: startup = 15234 ms

典型值： 10-30 秒，具体取决于硬件和系统配置。

Startup Time (Non-Async)

目的： 使用 Python API 测量采用同步加载的 Isaac Sim 初始化时间。

测量内容： 通过 Python API 完成完整应用程序初始化所需的时间。

命令：

./python.sh standalone_examples/api/isaacsim.simulation_app/hello_world.py \
  --enable isaacsim.benchmark.services

结果解读： 在日志中查找 Runtime 针对 phase: startup。

对比： 由于同步加载，非异步启动通常比异步启动慢。

Full Warehouse Load Time + FPS

目的： 测量复杂仓库环境的场景加载性能和渲染 FPS。

测量内容： 阶段加载阶段的持续时间以及给定阶段在运行时的 FPS。

命令：

./python.sh standalone_examples/benchmarks/benchmark_scene_loading.py \
  --env-url /Isaac/Environments/Simple_Warehouse/full_warehouse.usd

配置：

  • 环境：完整仓库示例场景

结果解读：

[INFO] Runtime for phase: loading = 8123 ms
[INFO] Mean FPS for phase: benchmark = 45.2

Physics Steps per Second

目的：测量物理仿真性能，并比较复杂机器人的 CPU 与 GPU 物理后端。

测量内容：在完整的仓库示例场景中，针对 O3dyn 机器人，在固定步长、机器人数量和物理后端的情况下，每真实秒执行的物理步数。

测量方法：在物理时间步长（dt）为 1/60 秒的情况下，针对 phase: benchmark 测量 Mean FPS。

命令：

./python.sh standalone_examples/benchmarks/benchmark_robots_o3dyn.py \
  --num-robots 10 --num-gpus 1

配置：

  • 机器人数量

  • 物理后端（CPU：numpy，GPU：torch，warp）

# CPU Physics
./python.sh standalone_examples/benchmarks/benchmark_robots_o3dyn.py \
  --num-robots 2 --physics numpy

# GPU Physics (default: torch)
./python.sh standalone_examples/benchmarks/benchmark_robots_o3dyn.py \
  --num-robots 10 --physics warp

结果解读：

Mean FPS: 51.706 FPS

给定物理时间步长 dt 为 1/60，每秒物理步数等同于 FPS。较小的物理 dt 会导致每帧执行多次物理步，从而将计算量改变为 FPS * physics steps per frame。

性能说明： O3dyn 机器人非常复杂，尤其是由于模拟了高度铰接的车轮。较简单的机器人由于物理计算工作量减少，可以实现更高的帧率。随着机器人数量或物理对象数量的增加，更高规格的 GPU 将提供更高的吞吐量。

优化建议：

  1. 为工作负载选择合适的物理后端。建议对两个后端都进行测试，以确定最佳选择。

  • CPU 物理： 机器人数量较少和/或低复杂度的机器人 + 场景

  • GPU 物理： 机器人数量较多和/或高复杂度的机器人 + 场景

  1. 通过禁用不必要的碰撞体、关节和其他组件来降低机器人的复杂度。同样地，降低场景的复杂度。

性能扩展： O3dyn 机器人是一个很好的示例，可用于查看 CPU 和 GPU 物理性能如何随机器人数量和机器人复杂度的变化而扩展。

  • 1-4 个机器人：CPU 物理更快

  • 约 5 个机器人：CPU 和 GPU 物理性能相当（取决于硬件）

  • 6 个及以上机器人：GPU 物理更快

多 GPU： 由于 PhysX 在单个 GPU 上运行，GPU 物理性能不会随 GPU 数量扩展。

加载阶段指标#

加载阶段测量场景加载和其他设置步骤期间的资源使用情况：

  • 系统内存 RSS： 进程的常驻集大小（单位：GB）

  • 系统内存 VMS： 进程的虚拟内存大小（单位：GB）

  • System Memory USS：进程的独占内存集大小（Unique Set Size），单位为 GB

  • GPU Memory Tracked：GPU 使用的显存（VRAM），单位为 GB

  • Runtime：挂钟时间，单位为毫秒

基准测试阶段指标#

基准测试阶段测量在主动模拟期间的性能：

性能指标：

  • Mean FPS：计算方式为 1000/mean_app_update_frametime，其中 mean_app_update_frametime 是应用更新阶段的平均帧时间，单位为毫秒。

  • Real Time Factor：模拟时间接近挂钟时间的比率。计算方式为 simulation_time / wall_clock_time，其中 simulation_time 是总模拟时间，wall_clock_time 是实际经过的时间。

  • Runtime：基准测试阶段的挂钟持续时间，单位为毫秒。

帧时间细分：

帧时间部分显示不同模拟组件的详细计时：

  • App_Update：一次应用更新代表模拟的一帧。在默认配置中，这通常涉及一次物理步和一次渲染步。

  • Physics：物理步的持续时间。这是总 app_update 帧时间的一个组成部分，代表物理计算工作的持续时间。

  • GPU：GPU 工作的持续时间。这是总 app_update 帧时间的一个组成部分，代表渲染工作的持续时间。仅当启用 --gpu-frametime 标志时才会收集此数据。

要深入了解特定工作流的帧时间细分情况，请参阅 使用 Tracy 进行性能分析，以获取有关使用 Tracy 分析器对仿真进行性能分析的详细信息。

注意

一次应用更新（app update）由一定数量的物理计算和针对给定帧的一定数量的渲染工作组成。由于并行化、其他开销以及任何专用的每帧计算，这两个组件的总和不等于 app_update 帧时间。

解读结果#

本节详细介绍如何解读前几节中解释的一些关键结果，特别是与硬件选择相关的结果。

平均 FPS：

平均 FPS 是选择硬件时需要考虑的关键指标。它是基准测试期间仿真的平均帧率。它是硬件在给定工作流下整体性能的良好指标。

已跟踪的 GPU 内存：

“已跟踪的 GPU 内存”指标指示工作流所需的 VRAM 量。涉及大型场景、高分辨率相机或大量传感器的工作流需要更多的 VRAM。

物理帧时间：

如果物理帧时间非常接近应用更新帧时间，则表明物理计算可能成为性能瓶颈。使用 GPU 物理时，更高规格的 GPU 在处理更多物理对象和/或更复杂的机器人时具有更好的扩展性。

GPU 帧时间：

当 GPU 帧时间非常接近 App Update 帧时间时，表明 GPU 渲染可能正在成为性能瓶颈。添加额外的 GPU 或使用更高规格的 GPU 将有助于提升性能。否则，如果 GPU 帧时间远低于 App_Update 帧时间，则表明 CPU 性能可能是瓶颈。

  • 由于对整体基准测试性能有轻微影响，默认禁用 GPU 帧时间的收集。可通过 --gpu-frametime 标志启用。

版本 5.0.0#

测量变更：

  • 使用 Motion BVH 测量的 KPI（在 Isaac Sim 5.0.0 中默认启用）- 提高了与运动相关的传感器效果的渲染精度，但降低了整体渲染性能

脚本变更：

  • 在无头模式下默认禁用视口更新以提升性能（可通过 --viewport-updates 启用）

  • 每秒物理步数（benchmark_robots_o3dyn.py）：新增对 CPU 和 GPU 物理后端的支持（此前仅支持 CPU）。

    • 默认后端从 CPU 物理后端更改为 GPU (torch) 物理后端

    • 机器人数量默认值从 2 更改为 10

RTX Lidar 传感器#

Isaac Sim RTX 或光线追踪 Lidar 支持固态和旋转式 Lidar 配置。 每个 RTX 传感器必须附加到其自己的视口才能正确模拟。

注意

在 Isaac Sim 6.0 中，RTX Lidar 的发布频率由 OmniLidar prim 上的 omni:sensor:tickRate 属性控制，而不是由辅助节点上的 frameSkipCount 控制。对于 OmniLidar prim，omni:sensor:tickRate 必须等于 omni:sensor:Core:scanRateBaseHz 以确保扫描累积行为正确。有关迁移指南和相关已知问题列表，请参阅 Multi-Tick Rendering。

学习目标#

在本示例中，您将：

  • 简要介绍如何使用 RTX Lidar 传感器。

  • 创建一个 RTX Lidar 传感器。

  • 将传感器数据以 LaserScan 和 PointCloud2 消息形式发布到 ROS 2。

  • 使用菜单快捷方式创建 RTX Lidar 传感器发布者。

  • 将所有内容整合在一起，并在 RViz2 中可视化多个传感器。

入门指南#

重要

确保在运行 Isaac Sim 之前，在终端中正确 source ROS 2 环境。

先决条件

  • 已完成 ROS 2 Cameras 教程。

  • 在启动 Isaac Sim 之前已设置 FASTRTPS_DEFAULT_PROFILES_FILE 环境变量，并启用了 ROS 2 bridge。

  • 可选：通过查阅概述以及了解如何获取RTX 传感器标注器，来探索 RTX Lidar 传感器的内部工作原理。

  • 已完成URDF 导入：Turtlebot教程，以便加载 Turtlebot 并使其移动。

  • 本教程的可选部分需要 isaac_tutorials ROS 2 包，该包在 IsaacSim-ros_workspaces 仓库中提供。

  • 完成ROS 2 安装，以确保 ROS 2 工作区环境配置正确。

注意

在 Windows 11 中，根据机器的配置，RViz2 可能无法正确打开。在 WSL 中，某些带宽占用较高的话题可能无法在 RViz2 中进行可视化。

添加 RTX Lidar ROS 2 桥接#

  1. 添加一个 2D Lidar 传感器。前往 Create > Sensors > RTX Lidar > NVIDIA > Example Rotary 2D。

  2. 要将合成 Lidar 传感器放置在机器人 Lidar 单元的相同位置，请将 Lidar prim 拖到 /World/tb3_burger_processed/Geometry/base_footprint/base_link/base_scan 下。在 Property 选项卡中，将 Transform 字段中的所有位移归零。此时，Lidar prim 应与机器人的扫描单元重叠。

  3. 添加一个 3D Lidar 传感器。前往 Create > Sensors > RTX Lidar > NVIDIA > Example Rotary。

  4. 要将合成 Lidar 传感器放置在机器人 Lidar 单元的相同位置，请将 Lidar prim 拖到 /World/tb3_burger_processed/Geometry/base_footprint/base_link/base_scan 下。在 Property 选项卡中，将 Transform 字段中的所有位移归零。此时，Lidar prim 应与机器人的扫描单元重叠。

  5. 使用 OmniGraph 节点连接 ROS 2 桥接器。在 Stage（舞台）面板中选择 /World/tb3_burger_processed/Geometry/base_footprint/base_link/base_scan —— lidar 发布者图与特定传感器绑定，因此应放置在传感器 prim 旁边，而不是机器人根节点下。打开 Window > Graph Editors > Action Graph（窗口 > 图形编辑器 > 动作图），点击 New Action Graph（新建动作图），并将其命名为 ROS_LidarRTX。向图中添加以下节点：

    1. On Playback Tick（播放时触发）— 当按下 Play（播放）时触发下游节点。

    2. ROS 2 Context Node（ROS 2 上下文节点）— 设置 ROS 2 Domain ID（域 ID）（默认为 0；检查 Use Domain ID Env Var 以从启动环境中继承 ROS_DOMAIN_ID）。

    3. Isaac Run One Simulation Frame（Isaac 运行一帧模拟）— 在启动时运行一次渲染产品管线以提升性能。

    4. Isaac Create Render Product（Isaac 创建渲染产品）— 将 cameraPrim 设置为步骤 1 中的 2D Lidar。

    5. Isaac Create Render Product（Isaac 创建渲染产品）（第二个实例）— 将 cameraPrim 设置为步骤 3 中的 3D Lidar。

    6. ROS 2 RTX Lidar Helper（ROS 2 RTX Lidar 辅助节点）— 连接 2D 渲染产品输出。将 topicName 设置为 scan，将 frameId 设置为 base_scan。

    7. ROS 2 RTX Lidar Helper（ROS 2 RTX Lidar 辅助节点）（第二个实例）— 连接 3D 渲染产品输出。将 type 设置为 point_cloud，将 topicName 设置为 point_cloud，将 frameId 设置为 base_scan，并勾选 Publish Full Scan（发布完整扫描）。

注意

当 ROS2 RTX Lidar Helper 节点中的 type 设置为 laser_scan 时，仅当 RTX Lidar 生成完整扫描时才会发布 LaserScan 消息。 对于旋转式 Lidar，完整扫描指 360 度旋转；对于固态 Lidar，完整扫描指其配置文件中设定的完整方位角范围。 根据 Lidar 的旋转速率和时间步长，完成一次完整旋转扫描可能需要多个帧；例如，在渲染步长为 1/60 秒的情况下，旋转速率为 10Hz 的旋转式 Lidar 需要六帧才能完成一次完整扫描，这意味着 LaserScan 消息每六帧发布一次。固态 Lidar 在单帧内即可完成完整扫描，因此对应的 LaserScan 消息每帧都会发布。

PointCloud 消息的发布频率取决于 ROS2 RTX Lidar Helper 节点中 Publish Full Scan 设置的值：要么每帧发布，要么在累积完整扫描后发布。

正确设置图后，点击 Play 开始仿真。 验证 RTX Lidar 是否正在发送 LaserScan 和 PointCloud2 消息，并可在 RViz 中进行可视化。

对于 RViz 可视化：

  1. 在已 source 的终端中运行 RViz2 (rviz2)。

  2. Isaac Sim 中 RTX Lidar 的 lidar 坐标系设置为 base_scan，请相应地更新 RViz 中的固定坐标系名称。

  3. 添加 LaserScan 可视化项，并将话题设置为 /scan。

  4. 添加 PointCloud2 可视化项，并将话题设置为 /point_cloud。

图形快捷方式#

有一个菜单快捷方式可用于构建多个 Lidar 传感器图。请转到 Tools > Robotics > ROS 2 OmniGraphs > RTX Lidar。

如果未列出任何 ROS 2 图，则需要启用 ROS 2 桥接。系统将弹出一个窗口，要求提供用于填充图的参数。你必须提供 Graph Path、Lidar Prim、frameId、Node Namespaces（如果存在），并勾选要发布的数据对应的复选框。如果要将图添加到现有图中，请勾选 Add to an existing graph? 复选框。这会将节点追加到现有图中，并在存在的情况下使用现有的 tick 节点、context 节点和 simulation time 节点。

运行示例#

  • 在已加载 ROS 2 环境的新终端中，运行以下命令以启动 RViz 并显示 Lidar 点云。请根据实际情况将 ros2_ws 替换为 humble_ws。

    rviz2 -d <ros2_ws>/src/isaac_tutorials/rviz2/rtx_lidar.rviz

  • 运行示例脚本：

    ./python.sh standalone_examples/api/isaacsim.ros2.bridge/rtx_lidar.py

场景加载完成后，请确认你能够观察到正在模拟的旋转 Lidar 传感器的点云。

RTX Lidar 脚本示例#

虽然大部分示例代码相当通用，但创建和模拟传感器仍需几个特定部分。在此示例中，你使用 isaacsim.sensors.experimental.rtx Python API 创建 2D 和 3D RTX Lidar 传感器。

创建 3D 和 2D RTX Lidar 传感器，使用 LidarSensor 对其进行封装，并通过传感器 API 附加 ROS 2 和可视化写入器：

import isaacsim.core.experimental.utils.app as app_utils
import isaacsim.core.experimental.utils.prim as prim_utils
import omni.kit.app
from isaacsim.core.simulation_manager import SimulationManager
from isaacsim.sensors.experimental.rtx import Lidar, LidarSensor

# Enable the ROS 2 bridge so the RTX Lidar ROS writers are registered.
app_utils.enable_extension("isaacsim.ros2.bridge")
omni.kit.app.get_app().update()


def read_laser_scan_metadata(prim_path: str) -> dict[str, float | list[float]]:
    """Read the scan geometry required by the LaserScan writer."""
    rotation_rate = float(prim_utils.get_prim_attribute_value(prim_path, "omni:sensor:Core:scanRateBaseHz") or 0)
    near_range = float(prim_utils.get_prim_attribute_value(prim_path, "omni:sensor:Core:nearRangeM") or 0)
    far_range = float(prim_utils.get_prim_attribute_value(prim_path, "omni:sensor:Core:farRangeM") or 0)
    firing_rate = int(prim_utils.get_prim_attribute_value(prim_path, "omni:sensor:Core:patternFiringRateHz") or 0)
    if rotation_rate <= 0 or firing_rate <= 0:
        raise RuntimeError("LaserScan: scanRateBaseHz or patternFiringRateHz is 0 on the lidar prim")
    return {
        "horizontalFov": 360.0,
        "horizontalResolution": 360.0 * rotation_rate / firing_rate,
        "depthRange": [near_range, far_range],
        "rotationRate": rotation_rate,
        "azimuthRange": [-180.0, 180.0],
    }


# Example_Rotary scans at 10 Hz; tick_rate must match scanRateBaseHz so that scan
# accumulation and multi-tick rendering produce a full scan per tick.
lidar = Lidar.create(
    path="/sensor",
    config="Example_Rotary",
    tick_rate=10.0,
    translations=[[0.0, 0.0, 1.0]],
)

# Example_Rotary_2D provides a planar scan for the LaserScan publisher.
lidar_2d = Lidar.create(
    path="/sensor_2D",
    config="Example_Rotary_2D",
    tick_rate=10.0,
    translations=[[0.0, 0.0, 1.0]],
)

SimulationManager.setup_simulation(dt=1.0 / 60.0, device="cpu")
omni.kit.app.get_app().update()

# LidarSensor owns the render product and provides a common writer API.
sensor_3d = LidarSensor(lidar, annotators=[])
sensor_2d = LidarSensor(lidar_2d, annotators=[])

sensor_3d.attach_writer(
    "RtxLidarROS2PublishPointCloud",
    topicName="point_cloud",
    frameId="base_scan",
)

laser_scan_metadata = read_laser_scan_metadata(lidar_2d.paths[0])
sensor_2d.attach_writer(
    "RtxLidarROS2PublishLaserScan",
    topicName="scan",
    frameId="base_scan",
    **laser_scan_metadata,
)

# Optionally visualize both scans in the viewport.
sensor_3d.attach_writer("draw-point-cloud", color=[0.0, 1.0, 0.5, 1.0], size=0.05)
sensor_2d.attach_writer("draw-point-cloud", color=[1.0, 0.2, 0.8, 1.0], size=0.08)

此处 Example_Rotary 选择 3D Lidar 配置 USD，Example_Rotary_2D 选择平面配置。若要将 3D Lidar 切换为示例中的固态配置，请将 config="Example_Rotary" 替换为 config="Example_Solid_State"，并将 tick_rate 更新为该资产的 omni:sensor:Core:scanRateBaseHz 值（参见 OmniLidar Tick Rate Must Equal scanRateBaseHz）。LidarSensor 创建并拥有每个渲染产品。其 attach_writer 方法同时接受 ROS 2 写入器注册表名称和简短的可视化写入器名称。

注意

有关 Lidar.create 支持的其他参数（包括 aux_output_level 和 accumulate_outputs）的详细信息，请参阅 RTX Lidar Sensor 和 API Documentation。

（可选）在 ROS 2 PointCloud2 中暴露 RTX Lidar 元数据#

RTX Lidar 传感器可以选择性地暴露笛卡尔点云之外的元数据，包括回波强度和时间戳、生成各个回波的物体材质，以及生成各个回波的 prim 路径。 可暴露的元数据完整列表在 IsaacCreateRTXLidarScanBuffer (deprecated) Annotator 中描述。

要生成元数据，必须将 OmniLidar prim 上的 _replicator:rendervar:GenericModelOutput:channels 属性设置为包含 BASIC（或更高级别）——等效地，使用 Lidar(..., aux_output_level="BASIC")（或更高级别）构造 prim。有关如何从 Array Properties 小部件设置该属性的信息，请参阅 Auxiliary Output Level and the GenericModelOutput RenderVar。某些元数据字段在运行时需要额外的 carb 设置；请参阅 IsaacCreateRTXLidarScanBuffer (deprecated) Annotator 文档中的表格。

然后必须配置 Isaac Sim 以将元数据写入 PointCloud2 消息。有多种方法可以实现这一点。

通过 ROS 2 OmniGraphs 暴露元数据#

按照添加 RTX Lidar ROS 2 桥接章节中的步骤，创建一个 RTX Lidar 传感器，并将 ROS 2 OmniGraphs 节点添加到 Action Graph 中。然后：

  1. 如果仿真正在运行，请停止仿真。

  2. 将场景保存为 USD 文件。

  3. 关闭 Isaac Sim。

  4. 启动或重启 Isaac Sim，并在运行命令中添加 --/rtx-transient/stableIds/enabled=true。此设置使 RTX 渲染器能够生成 128 位 Object ID，作为 RTX Lidar 元数据的一部分。

  5. 重新打开刚刚保存的 USD 文件。

  6. 通过转到 Window > Graph Editors > Action Graph 打开可视化脚本编辑器。

  7. 选择您之前创建的 Action Graph。

  8. 向图中添加一个 ROS2 RTX Lidar Point Cloud Config 节点。

  9. 勾选 Include the Intensity 和 Include the ObjectId 复选框。这会将强度和对象 ID 元数据写入 PointCloud2 消息。

  10. 将 ROS2 RTX Lidar Point Cloud Config 节点的 selectedMetadata 输出连接到 3D Lidar 传感器的 ROS2 RTX Lidar Helper 节点的 selectedMetadata 输入。

  11. 在 3D Lidar 传感器的 ROS2 RTX Lidar Helper 节点上勾选 enableObjectIdMap 复选框。这将使 Isaac Sim 在 /object_id_map 主题上发布包含 Object ID 映射的 String 消息。

  12. 如果尚未选中，请在 3D Lidar 传感器的 ROS2 RTX Lidar Helper 节点上勾选 enabled 复选框。

  13. 选择 Example_Rotary Lidar prim，并将其 _replicator:rendervar:GenericModelOutput:channels 属性设置为 ["FULL"] - 有关逐步的 Array Properties 工作流程，请参阅 Auxiliary Output Level and the GenericModelOutput RenderVar。

  14. 按 Play 以启动仿真。

对于 RViz 可视化：

  1. 在已 source 的终端中运行 RViz2 (rviz2)。

  2. Isaac Sim 中 RTX Lidar 的 lidar 坐标系设置为 base_scan，请相应地更新 RViz 中的固定坐标系名称。

  3. 添加 PointCloud2 可视化并将话题设置为 /point_cloud。

验证 RViz2 是否自动将 PointCloud2 可视化下的 Channel Name 设置为 intensity，并将 Color Transformer 设置为 Intensity， 从而启用 PointCloud2 消息中强度通道的可视化。默认情况下，大多数其他元数据通道不会被可视化，除了 HitNormal，选中该通道后将可视化生成回波的对象表面的法向量。

通过 Python 脚本暴露元数据#

使用 aux_output_level="FULL" 创建 3D RTX Lidar 传感器，使用 LidarSensor 对其进行封装， 并附加带有 output* 标志的 RtxLidarROS2PublishPointCloud 写入器，这些标志用于选择 哪些辅助字段最终包含在 PointCloud2 消息中：

import isaacsim.core.experimental.utils.app as app_utils
from isaacsim.sensors.experimental.rtx import Lidar, LidarSensor

# Enable the ROS 2 bridge so the RTX Lidar ROS writers are registered.
app_utils.enable_extension("isaacsim.ros2.bridge")

# Create an RTX Lidar with FULL auxiliary output level so the GenericModelOutput buffer carries
# every per-point metadata field (intensity, object ID, hit normal, ...). This sets
# ``_replicator:rendervar:GenericModelOutput:channels = ["FULL"]`` on the OmniLidar prim.
lidar = Lidar.create(
    path="/sensor_with_metadata",
    config="Example_Rotary",
    tick_rate=10.0,
    aux_output_level="FULL",
    translations=[[0.0, 0.0, 1.0]],
)

# LidarSensor creates and owns the render product.
sensor = LidarSensor(lidar, annotators=[])

# Attach the RTX-Lidar PointCloud2 writer through the sensor. The ``output*`` flags select which
# auxiliary fields are unpacked from the GMO buffer and written into the PointCloud2 message.
sensor.attach_writer(
    "RtxLidarROS2PublishPointCloud",
    topicName="point_cloud",
    frameId="base_scan",
    outputIntensity=True,
    outputObjectId=True,
)

# Publish the Object-ID-to-prim-path map on a separate topic so subscribers can resolve
# returns back to USD prims.
sensor.attach_writer("ROS2PublishObjectIdMap", topicName="object_id_map")

在 lidar prim 上通过 Lidar.create(..., aux_output_level="FULL") 设置 _replicator:rendervar:GenericModelOutput:channels = ["FULL"]。有关属性流说明以及当多个具有不同辅助输出级别的 RTX 传感器共享同一 stage 时的已知问题，请参阅 Auxiliary Output Level and the GenericModelOutput RenderVar。

此外，在调用 SimulationApp 时指定 --/rtx-transient/stableIds/enabled=true，如下所示：

from isaacsim import SimulationApp

# Example for creating a RTX lidar sensor and publishing PointCloud2 data
simulation_app = SimulationApp({"headless": False, "extra_args": ["--/rtx-transient/stableIds/enabled=true"]})

播放时间轴时，PointCloud2 消息将发布到 /point_cloud 主题，并包含所需的元数据。

解释时间戳元数据#

如果元数据中包含 Timestamp，则 PointCloud2 消息将包含两个名为 timestamp_0 和 timestamp_1 的 uint32 字段。它们分别保存表示自模拟开始以来以纳秒为单位的逐点时间戳的单个 uint64 值的低 32 位和高 32 位。按如下方式重构 uint64 值：

# Example: a per-point timestamp pulled from a PointCloud2 message field.
# In a real subscriber you'd read these from points["timestamp_0"] and
# points["timestamp_1"] (uint32 each).
timestamp_0 = 0xCAFEBABE  # low 32 bits
timestamp_1 = 0x12345678  # high 32 bits

# Recombine to a single uint64 nanosecond value.
ts_uint64_ns = (int(timestamp_1) << 32) | int(timestamp_0)

注意

此编码方式在 Isaac Sim 6.0 中引入。在早期版本中，timestamp 作为单个 float32 字段（datatype=7, count=1）发出。针对先前编码方式编写的订阅者必须更新，以读取这两个 uint32 字段并重新组合它们。

解释对象 ID 元数据#

如 使用 RTX 传感器和对象 ID 进行语义分割 中所述，Object ID 元数据是一个稳定且唯一的 128 位无符号整数，映射到生成相应返回值的对象的 prim 路径。 这可用于场景的语义分割，方法是将对象 ID 映射到 prim 路径，然后从 prim 中检索语义标签。如果元数据中包含 ObjectId， PointCloud2 消息将包含 4 个 uint32 字段：object_id_0、object_id_1、object_id_2 和 object_id_3。

在上述示例之一中播放时间轴后，在一个新终端中验证您的 Isaac Sim ROS 工作区已加载，并运行以下节点以打印生成各个返回值的对象的 prim 路径：

ros2 run isaac_tutorials ros2_object_id_subscriber.py

有关如何解释 Object ID 元数据的更多详细信息，请参阅订阅者脚本。相关部分已复制如下以供参考；它本身无法在 Isaac Sim Script Editor 或独立的 Python 环境中运行。

import json

import numpy as np
from rclpy.node import Node
from sensor_msgs.msg import PointCloud2
from sensor_msgs_py.point_cloud2 import read_points
from std_msgs.msg import String


class ROS2ObjectIDSubscriber(Node):
    def __init__(self):

        super().__init__("ros2_object_id_subscriber")

        self.point_cloud2_subscriber = self.create_subscription(
            PointCloud2, "point_cloud", self.point_cloud2_callback, 10
        )
        self.object_id_map_subscriber = self.create_subscription(
            String, "object_id_map", self.object_id_map_callback, 10
        )
        self.object_id_map = None

    def point_cloud2_callback(self, msg: PointCloud2):
        self.get_logger().info(f"Received point cloud.")
        points = read_points(
            msg, field_names=("x", "y", "z", "object_id_0", "object_id_1", "object_id_2", "object_id_3"), skip_nans=True
        )
        if self.object_id_map is None:
            return
        object_ids_as_uint32 = (
            np.stack(
                [
                    points["object_id_0"],
                    points["object_id_1"],
                    points["object_id_2"],
                    points["object_id_3"],
                ],
                axis=1,
            )
            .flatten()
            .reshape(-1, 4)
        )
        object_ids_as_uint128 = [int.from_bytes(group.tobytes(), byteorder="little") for group in object_ids_as_uint32]
        prim_paths = [self.object_id_map[str(i)] for i in object_ids_as_uint128]
        print(prim_paths)

    def object_id_map_callback(self, msg: String):
        self.get_logger().info(f"Received object id map: {msg.data}")
        self.object_id_map = json.loads(msg.data)["id_to_labels"]

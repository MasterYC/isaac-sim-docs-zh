ROS 2 相机#

学习目标#

在本示例中，您将学习如何：

  • 向场景和机器人添加额外的相机

  • 在 OmniGraph 中添加相机发布者

  • 使用菜单快捷方式添加相机发布者

  • 通过 rostopics 发送真实合成感知数据

入门指南#

先决条件

  • 已完成 ROS 2 Installation：已安装 ROS 2，启用了 ROS 2 扩展，并构建或加载了本教程所需的 ROS 2 工作区。

  • 对 ROS 主题 以及 发布者和订阅者 的工作原理有基本了解。

  • 已完成 Isaac Sim OmniGraph 教程 和 教程 4：向机器人添加相机和传感器。

  • 已完成 URDF 导入：Turtlebot，以便舞台上已准备好一个 Turtlebot。

注意

在 Isaac Sim 6.0 中，ROS2 Camera Helper 和 ROS2 Camera Info Helper 上的 frameSkipCount 输入已弃用。请改为在相机 prim（必须应用了 OmniSensorAPI）上设置 omni:sensor:tickRate 以控制发布频率。有关迁移指南，请参阅 Multi-Tick Rendering。

Camera Publisher#

设置相机#

Viewport 中显示的默认相机是 Perspective 相机。您可以通过 Viewport 显示区域内部左上角的 Camera 按钮来验证这一点。点击 Camera 按钮，您将观察到还有其他几个预设相机位置：

  • Top

  • Front

  • Right side views

在本教程中，您将在 /World/Camera_1 和 /World/Camera_2 处添加两个固定相机，从两个不同的视角观察房间。直接在 /World 下创建每个相机，并使用这些确切的名称，以便 prim 路径与本教程系列后续部分中使用的 OmniGraph 节点和脚本相匹配（例如 ROS 2 Setting Publish Rates）。向 stage 添加相机的步骤可在 Tutorial 4: Add Camera and Sensors to a Robot 中找到。

打开额外的 Viewport 以同时观察多个相机视图。要打开额外的 Viewport：

  1. Window > Viewports > Viewport 2 以打开视口

  2. 从视口左上角的 Cameras 按钮中选择所需的相机视图。

构建 RGB 发布器的图#

  1. 在 Stage 面板中，选择 /World/Camera_1，以便创建一个新的 Action Graph，并将其放置在它所发布的相机 prim 旁边。将图作为其直接影响的传感器的子级，可以保持资产的可组合性：当 Camera_1 被引用到另一个场景中时，发布器图会随之一起移动。

  2. 打开图编辑器：Window > Graph Editors > Action Graph。

  3. 点击 Action Graph 窗口中间的 New Action Graph 图标，或者如果想将相机发布器附加到现有的动作图上，则点击 Edit Action Graph。将图命名为 Camera_1_Graph；生成的图路径为 /World/Camera_1/Camera_1_Graph。

  4. 构建包含以下内容的 Action Graph：

    • 以下图片中的节点和连接

    • 以下表格中的参数

    参数：

    节点

    输入字段

    值

    Isaac Create Render Product

    cameraPrim

    /World/Camera_1

    enabled

    True

    ROS 2 Camera Helper

    type

    rgb

    topicName

    rgb

    frameId

    turtle

勾选此图将自动创建一个分配给 Camera_1 的新渲染产品。

图解说明#

  • On Playback Tick Node：当仿真处于“Playing”状态时产生一个 tick。接收此节点 tick 的节点将在每个仿真步骤执行其计算函数。

  • ROS 2 Context Node：ROS 2 使用 DDS 作为其中间件通信机制。DDS 使用 Domain ID 来允许不同的逻辑网络独立运行，即使它们共享同一个物理网络。同一域中的 ROS 2 节点可以自由地发现彼此并发送消息，而不同域中的 ROS 2 节点则无法这样做。ROS 2 context node 会根据给定的 Domain ID 创建一个上下文。默认设置为 0。如果勾选了 Use Domain ID Env Var，它将从启动当前 Isaac Sim 实例的环境中导入 ROS_DOMAIN_ID。

  • Isaac Create Render Product：创建一个 render product prim，该 prim 从指定的 camera prim 获取渲染数据，并输出 render product prim 的路径。通过勾选或取消勾选 enabled 字段，可以按需启用或禁用渲染。

  • Isaac Run One Simulation Frame：此节点将确保流水线仅在启动时运行一次。

  • ROS 2 Camera Helper：指示要发布的数据类型以及用于发布的 rostopic。

Camera Helper Node

Camera Helper Node 为用户抽象了复杂的后处理网络。

在连接了 Camera Helper Node 后按下 Play，当你点击 Action Graph 窗口左上角的图标时，你可能会注意到在 Action Graph 列表中出现了一个新的条目：/Render/PostProcessing/SDGPipeline。

此图由 Camera Helper Node 自动创建。该管线从渲染器中检索相关数据，对其进行处理，并将其发送到对应的 ROS 发布者。此图仅在当前运行的会话中创建。它不会作为资产的一部分保存，也不会出现在 Stage 树中。

深度和其他感知真值数据#

除了 RGB 图像外，任何相机还可提供以下合成传感器和感知信息：

  • 深度

  • 点云

若要查看每个合成数据标注器所使用的单位，请参阅 omni.replicator。

注意

如果您想使用依赖于 vision_msgs 的 BoundingBox 发布者节点，请确保系统已安装该依赖项，或者尝试 配置选项并启用内部 ROS 库。

  • 2D 紧凑边界框

  • 2D 宽松边界框

  • 3D 边界框

  • 语义标签

  • 实例标签

每个 Camera Helper 节点只能检索一种类型的数据。您可以在 Camera Helper Node 属性选项卡中，通过 type 字段的下拉菜单指定要分配给该节点的类型。

注意

为 Camera Helper 节点指定类型并激活后（即启动仿真并生成底层 SDGPipeline 后），您将无法更改该类型并复用该节点。您可以使用新节点，或重新加载您的 Stage 并使用修改后的类型重新生成 SDGPipeline。

有关为多个相机发布多个 ROS Topics 的示例，请前往 Isaac Sim Content Browser，路径为 Isaac Sim>Samples>ROS2>Scenario>turtlebot_tutorial.usd。

Camera Info Helper 节点#

Camera Info Helper 发布者节点使用以下公式计算相机内参矩阵 K、P 和 R。

参数计算：

\(fx = width * focalLength / horizontalAperture\)

\(fy = height * focalLength / verticalAperture\)

\(cx = width * 0.5\)

\(cy = height * 0.5\)

K 矩阵（内参矩阵）

K 矩阵是一个 3x3 矩阵。

\[K = { fx, 0, cx 0, fy, cy 0, 0, 1 }\]

P 矩阵（投影矩阵）

对于双目相机，第二个相机相对于第一个相机在 x 和 y 方向上的立体偏移量分别表示为 Tx 和 Ty。如果节点附加了两个渲染产品（render products），这些值将自动计算。

对于单目相机，\(Tx = Ty = 0\)。

P 矩阵是一个 3x4 行主序矩阵。

\[P = { fx, 0, cx, Tx, 0, fy, cy, Ty, 0, 0, 1, 0 }\]

R 矩阵（校正矩阵）

R 矩阵是一个旋转矩阵，用于将相机坐标系与理想的立体图像平面对齐，确保两个立体图像中的极线平行。 R 矩阵仅用于双目相机，并设置为 3x3 矩阵。

图形快捷方式#

有一个菜单快捷方式可用于构建多个相机传感器图形。请前往 Tools > Robotics > ROS 2 OmniGraphs > Camera。

如果未观察到列出的任何 ROS 2 图形，则需要启用 ROS 2 桥接。下方将弹出一个对话框，询问填充图形所需的参数。您必须提供 Graph Path、Camera Prim、frameId、任何 Node Namespaces（如果有），并勾选您想要发布的数据对应的复选框。

如果要将图形添加到现有图形中，请勾选 Add to an existing graph? 复选框。这会将节点追加到现有图形中，并使用现有的 tick 节点、context 节点和 simulation time 节点（如果存在）。

验证 ROS 连接#

使用 ros2 topic echo /<topic> 来观察正在传递的原始信息。

在 Linux 上，您可以使用 rqt_image_view 来可视化深度：ros2 run rqt_image_view rqt_image_view /depth。Windows 不支持 rqt_image_view。

要在 RViz2 中验证发布的图像：

  1. 在已 source ROS 2 环境的终端中，输入命令 rviz2 以打开 RViz。

  2. 添加一个 Image 显示类型，并将 topic 设置为 rgb。

故障排除#

如果深度图像仅显示黑白区域，则可能是视场（field of view）具有“无限”深度，从而导致对比度失真。请调整视场，以限制图像中的深度范围。

在较慢或受 CPU 限制的系统上，大型相机消息可能会被丢弃，导致 RViz2 Image 显示出现闪烁。如果发生这种情况，请降低相机分辨率或发布频率。

其他发布选项#

若要按需或按指定频率定期发布图像，需要使用 Python 脚本。有关示例，请参阅 ROS 2 Camera。

总结#

本教程介绍了如何在 ROS 2 中发布相机和感知数据。

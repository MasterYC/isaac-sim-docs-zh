ROS 2 变换树与里程计#

学习目标#

在本示例中，您将：

  • 添加一个变换发布器，将相机位置作为变换树的一部分进行发布。

  • 发布对象的相对位姿。

  • 发布机器人的里程计。

  • 使用菜单快捷方式创建变换和里程计发布器。

  • 在 Isaac Sim 中查看变换树。

入门指南#

先决条件

  • 已完成 URDF 导入：Turtlebot、ROS 2 相机 和 RTX 激光雷达传感器 教程。

  • 已完成 ROS 2 安装，确保 ROS 2 可用且 ROS 2 扩展已启用。

变换树发布器#

假设你已经完成了 ROS 2 相机教程，并且场景中已有两个相机，让我们将这些相机添加到变换树中，以便你可以在全局坐标系中跟踪相机的位置。

Transform Publisher#

在 Isaac Sim 6.0 及更高版本中，ROS 2 Publish Transform Tree 节点从 Isaac Compute Transform Tree 节点消费预先计算好的帧数据，而不是在内部解析 Prim。如果您正在升级旧图，请参阅 迁移 ROS2 Publish Transform Tree。

  1. 在 Stage 面板中，选择 /World，以便在相机旁边创建新的 Action Graph，因为该图将发布这些相机的数据。打开 Window > Graph Editors > Action Graph，点击 New Action Graph，并将其命名为 ActionGraph_tf_ground_truth（生成的图路径为：/World/ActionGraph_tf_ground_truth）。 添加 On Playback Tick、Isaac Read Simulation Time、ROS2 Context、Isaac Compute Transform Tree 和 ROS 2 Publish Transform Tree 节点。 将 On Playback Tick 节点的 tick 输出连接到 Compute 节点的 execIn，将 ROS2 Context 节点的 context 输出连接到 Publish 节点的 context，并将 Isaac Read Simulation Time 节点的 simulationTime 输出连接到 Publish 节点的 timeStamp。构建一个与下图匹配的 Action Graph。

  2. 将 Compute 节点的输出连接到 Publish 节点：execOut → execIn，parentFrames → parentFrames，childFrames → childFrames，translations → translations，orientations → orientations。

  3. 在 Isaac Compute Transform Tree 节点的 Property 选项卡中，将 Camera_1 和 Camera_2 都添加到 targetPrims 字段。

  4. 在支持 ROS 2 的终端中检查变换树：ros2 topic echo /tf。验证两个相机是否都在变换树上。在视口中移动相机，并观察相机位姿的变化。

TF 发布在底层的工作原理及原因#

默认情况下，Isaac Sim 会为单个仿真时间戳发布一个合并的 tf2_msgs/msg/TFMessage，该数据聚合自进程内聚合组中的兼容 TF 发布节点。聚合组由 ROS 域、主题名称、动态或静态发布模式以及服务质量 (QoS) 配置文件定义。

TF 聚合的存在是为了让 ROS 2 消费者在每个仿真刻度接收一个连贯的变换快照。典型的机器人图可能包含多个 TF 发布节点，例如一个用于 odom 到 base_link 的原始发布节点，以及另一个用于机器人链接树的发布节点。如果每个节点独立发布，下游 TF 监听器可能会根据消息顺序观察到来自同一仿真时间的部分树。聚合还减少了 ROS 2 发布者的发现和消息处理开销，因为 Isaac Sim 对每个兼容的 TF 组使用一个发布者，而不是为每个 OmniGraph 节点使用一个发布者。

对于动态 TF 话题（如 /tf），聚合管理器通常会保持当前时间戳处于打开状态，直到接收到更新的时间戳。这使得每个在相同仿真时间运行的发布者节点都有机会在 Isaac Sim 发出合并消息之前贡献其数据。因此，最近提交的时间戳可能会比最近发布的批次超前一个仿真刻度。如果时间戳没有推进，例如使用常量/默认时间戳输入，待处理的批次将在下一个聚合刷新周期被刷新。

对于静态 TF 话题（如 /tf_static），聚合管理器会缓存每个贡献者的最新静态变换，并且仅在静态变换发生变化或贡献者被移除时才重新发布。这在保留预期的 transient-local 静态 TF 行为的同时，避免了在每个刻度发布相同的静态变换。

如果同一聚合组中的两个贡献者在同一批次中发布了具有相同子帧的变换，Isaac Sim 将保留第一个注册贡献者的变换并记录警告。请确保在单个 TF 话题内子帧 ID 保持唯一。

若要调试单个 TF 发布者的输出，请使用 /exts/isaacsim.ros2.nodes/tfAggregation/enabled 设置禁用聚合：

./isaac-sim.sh --/exts/isaacsim.ros2.nodes/tfAggregation/enabled=false

关节变换#

若要获取关节机器人上每个连杆的变换，请将机器人的关节根节点添加到为 ROS 2 Publish Transform Tree 节点提供输入的 Isaac Compute Transform Tree 节点的 targetPrims 字段中。关节根节点之后的所有连杆将自动发布。

重要

如果生成的关节机器人变换树选择了错误的链接作为根链接，请使用以下步骤手动选择关节根链接。

  • 在 Stage Tree 中选择机器人的根 prim，在其 Raw USD Properties 选项卡中，找到 Articulation Root 部分。点击该部分右上角的 X 将其删除。

  • 在 Stage Tree 中选择所需的链接，在其 Raw USD Properties 选项卡中，点击 +ADD 按钮，并添加 Physics > Articulation Root。

  • 更改关节根后，保存文件并重新加载。

发布相对变换#

默认情况下，变换是相对于世界坐标系的。您可以检查 Turtlebot 的 /base_link 变换是否相对于 /World 发布。如果您希望获取相对于其他对象（例如相机）的变换，请在 Isaac Compute Transform Tree 节点上设置 parentPrim 字段。在 Compute 节点的 parentPrim 字段中添加 Camera_1，在更改属性之间 Stop 并 Play 仿真，您可以观察到 /base_link 变换现在相对于 Camera_1。

设置里程计#

要为机器人设置里程计，请发布里程计 ROS 消息及其对应的变换。

  1. Turtlebot3 机器人在 /World/tb3_burger_processed/Geometry/base_footprint/base_link 上应用了 Articulation Root API，并在 /World/tb3_burger_processed 上应用了 IsaacRobotAPI 且填充了 isaac:physics:robotLinks，因此无需手动设置 articulation root。

  2. 要设置里程计发布者，请在 Stage 面板中选择主机器人 prim /World/tb3_burger_processed，以便直接在其下创建新的 Action Graph。机器人本地发布者（如里程计、odom -> base_link 以及机器人链接 TF）作用于整个机器人关节结构，因此它们应位于机器人根节点下，而不是单个链接下。通过前往 Window > Graph Editors > Action Graph 并点击 New Action Graph 来打开可视化脚本编辑器；将其命名为 ROS_OdomTF。生成的图形路径为 /World/tb3_burger_processed/ROS_OdomTF。构建一个与下图匹配的 Action Graph。

    • 在 Isaac Compute Odometry Node 的 Property 选项卡中：

      • 将 Turtlebot prim（即 /World/tb3_burger_processed）添加到其 Chassis Prim 输入字段。该节点计算机器人相对于其起始位置的位置。其输出将同时馈入 /odom ROS 2 主题的发布者，以及发布从 /odom 坐标系到 /base_link 坐标系的单一变换的 TF 发布者。

    • 在 ROS2 Publish Raw Transform Tree 节点的 Property 选项卡中：

      • 将 childFrameId 输入字段设置为 base_link。

      • 将 parentFrameId 输入字段设置为 odom。这将启用在变换树中发布 odom -> base_link 帧。

    • 在 ROS2 Publish Odometry 节点的 Property 选项卡中：

      • 将 chassisFrameId 输入字段设置为 base_link。

      • 将 odomFrameId 输入字段设置为 odom。这将启用在变换树中发布 odom -> base_link 帧。

注意

ROS2 Publish Odometry 节点发布完整的 3D 速度信息。线速度和角速度均包含所有三个维度（x、y 和 z），从而能够更完整地表示机器人的运动状态。

  1. 此时，我们已发布里程计数据，且我们的变换树仅包含 odom -> base_link。我们还想将 base_link 下的相关机器人 prim 添加到变换树中。为此，请在图中添加一个 Isaac Compute Transform Tree 节点和一个 ROS 2 Publish Transform Tree 节点。将 Compute 节点的输出（execOut、parentFrames、childFrames、translations、orientations）连接到 Publish 节点对应的输入，并像上述其他节点一样，将 Publish 节点上的 Exec In、Context 和 Timestamp 字段进行相应连接。

    • 在 Isaac Compute Transform Tree 节点的 Property 选项卡中：

      • 将 parentPrim 输入字段设置为 Turtlebot Prim 中 base_link 的路径：/World/tb3_burger_processed/Geometry/base_footprint/base_link。

      • 将 targetPrims 输入字段设置为 TurtleBot 根 prim： /World/tb3_burger_processed。该节点会展开此机器人根节点，并发布 base_scan、caster_back_link、imu_link、wheel_left_link 和 wheel_right_link 相对于 base_link 的变换。

  2. 保留 /World/tb3_burger_processed/ROS_OdomTF 中现有的里程计、odom -> base_link 以及机器人链接 TF 发布者。不要在机器人图中添加 world -> odom 发布者。该变换是场景级真值，因为它描述了机器人的里程计坐标系在世界中的位置。在完整的导航栈中，诸如 Nav2 AMCL 这样的定位包可以发布全局坐标系与 odom 坐标系之间的变换。

图快捷方式#

以下菜单快捷方式用于构建变换和里程计图：

TF 发布者

对于 TF 发布者，请前往 Tools > Robotics > ROS 2 OmniGraphs > TF Publisher。如果您未看到列出的任何 ROS 2 图，则需要先启用 ROS 2 桥接。将弹出一个对话框，询问填充图所需的参数。您必须提供：

  • 图路径和节点命名空间（如果您有的话）。

  • 目标 Prim，如果要在变换中获取完整的关节链，则需包含关节根 API；或者，如果要发布单个 Prim 的变换，则提供单个 Prim。

  • 用作变换参考帧的父 Prim。默认值为 "/World"，但也可以是舞台上的任意帧。

如果已有一个变换发布器，并且想要添加更多要发布的 prim，只要它们具有相同的参考 prim，就可以同时勾选“添加到现有图形”和“添加到现有节点”复选框，提供图形和节点路径，以及要添加到现有图形的新目标 prim。如果想要添加到同一图形但使用不同的参考 prim，它将创建一个新的变换节点，并在存在的情况下使用现有的 tick、内容和时间戳节点。

里程计发布器

对于里程计发布器，请转到 Tools > Robotics > ROS 2 OmniGraphs > Odometry Publisher。将弹出一个对话框，询问用于填充图形所需的参数。您必须提供：

  • 图路径和节点命名空间（如果您有的话）。

  • 包含 Articulation Root API 的 prim，以及用于计算里程计的原点所在的底盘 prim。

在 Isaac Sim 中查看变换树#

Isaac Sim 的变换查看器允许您在视口窗口的模拟场景本身以及由 Isaac Sim 和/或外部 ROS 2 节点发布的变换树（位于 /tf 和 /tf_static 主题下）上进行绘制。

  1. 首先，使用 Extension Manager 搜索 isaacsim.ros2.tf_viewer 来启用 Isaac Sim 的变换查看器扩展。

  2. 启用扩展后，请转到顶部菜单栏并点击 Window > TF Viewer 以打开变换查看器控制窗口。

    窗口组件：

    1. 用于计算变换的坐标系。

    2. 是否显示坐标系（标记）。标记颜色。标记大小（相对值）。

    3. 是否显示坐标系名称。文本颜色。文本大小（相对值）。

    4. 是否显示坐标系的轴（RGB -> XYZ 轴）。轴长度（以米为单位）。轴厚度（相对值）。

    5. 是否显示子坐标系与父坐标系之间的连接。线条颜色。线条厚度（相对值）。

    6. 坐标系变换更新频率（Hz）。较高的频率可能会降低仿真性能。

    7. 重置变换树（清除变换缓冲区）。例如，可用于清除 TF_OLD_DATA 警告。

    注意

    关闭变换查看器窗口会停止显示并清除视口绘制内容。

  3. 要开始可视化，请选择用于计算变换的适当根坐标系（例如，根据发布的变换树规范，选择 World 或 world）。

    注意

    如果 /tf 和/或 /tf_static 主题下存在发布数据，但可视化（或特定根坐标系）未显示：

    1. 确保在打开 TF Viewer 窗口之前仿真正在运行

    2. 关闭并重新打开 TF Viewer 窗口以更新变换订阅

    3. 按 TF Viewer 窗口上的 Reset 按钮以重置变换树

在 Windows 11 中，根据机器配置，某些带宽密集型主题可能无法在 WSL 中的 RViz2 中进行可视化。

ROS 2 参考架构#

本节概述了结合 Isaac Sim 使用 ROS 2 的工作流程及相关构建模块。 旨在为使用 ROS 2 的机器人开发人员提供必要信息，以便将 Isaac Sim 集成到其现有工作流程中，用于仿真和验证其机器人软件栈。

此工作流程包括导入资产、设置场景以及与场景交互，可以通过 GUI 执行，也可以通过 Python 脚本以无头模式执行。 Isaac Sim 还内置了一组最小化的 ROS 2 库，当系统未安装 ROS 2 时，可使用这些库来启用 ROS 2 Bridge。请参阅 配置选项并启用内部 ROS 库。 这在基于容器的工作流程中特别有用，其中仿真和机器人软件在两个独立的容器中运行。启用 bridge 后，Isaac Sim 容器可以与在另一个容器中运行的 ROS 2 软件进行交互。

可以使用 URDF 导入器导入机器人。添加传感器后，开发人员可以使用 Python 脚本或 ROS 2 Bridge Extension 提供的 ROS 2 OmniGraph Nodes，使仿真场景和机器人能够与 ROS 2 进行交互。

机器人 URDF#

统一机器人描述格式（Unified Robotics Description Format，简称 URDF）是一种 XML 文件格式，在 ROS 2 和机器人社区中广泛用于描述机器人的各个元素。 机器人的所有连杆、关节、视觉和碰撞网格以及材料均以层级结构在 XML 文件中表示。 开发人员可以使用软件包和 工具 来验证和 可视化 URDF 文件。许多机器人制造商为其机器人提供 URDF 模型。

URDF 包含各种 元素/标签，如 robot、sensors、joints 和 transmission，用于定义 机器人及其组件。此外，还可以选择性地为传感器添加自定义的 Isaac Sim 标签到 URDF 文件中。 目前支持预配置的激光雷达（lidar）或用户自定义配置。

流行的 CAD 建模程序（如 SolidWorks、Fusion360 和 OnShape）支持将机器人模型导出为 URDF 格式的方法。

URDF 导入器#

Isaac Sim 附带了一个扩展，用于教程：导入 URDF，该扩展允许用户导入自己的机器人 URDF 文件。 扩展使开发人员能够为 Isaac Sim 添加功能并集成其他工具。URDF 导入器扩展是开源的， 它将机器人 URDF 转换为 USD，以便在 Isaac Sim 中使用。导入器可以直接读取 URDF 文件，或者订阅 发布机器人描述的 ROS 2 主题。在导入机器人时，可以设置各种参数，例如导入惯性张量、 固定基础链接、设置关节强度和阻尼、碰撞和物理属性。 还支持通过多种 Schemas 和 APIs 对机器人的物理参数进行调优。

开发人员还可以访问各种预打包的机器人资产，这些资产可以直接添加到任何场景中。

环境设置#

CAD 转换器可用于从各种 CAD 建模工具导入资产。 Isaac Sim 还附带了超过一千个 “SimReady” 资产。 SimReady 或仿真就绪资产是具有物理准确性的 3D 对象，包含精确的物理属性、行为以及连接的数据流，用于在仿真的数字世界中表示现实世界。这些资产可作为构建模块，用于构建机器人环境。 仓库资产集合包含超过 800 个 3D 资产，涵盖仓库中常见的工具、设备和物品，包括叉车、托盘、货架和架子。

Isaac Sim 还包含一些环境资产，例如简单的房间、仓库、医院和办公室。 开发人员可以利用各种工具（如 Warehouse Creator 和 Conveyor Belt Utility）来构建适合其用例的环境。 通过 Replicator Agents 扩展，还可以将人物资产添加到场景中，执行行走、坐下、站立和环顾四周等任务。使用 OpenUSD 也可以导入在其他数字内容创作工具中构建的 3D 场景。

添加传感器#

在导入机器人并设置好环境后，下一步是添加相关传感器。开发人员可以利用多种传感器，包括： RGB 和 RGBD 相机、2D 和 3D RTX Lidar，以及基于物理的传感器（例如，接触传感器、IMU、雷达、超声波传感器等）。 常用的传感器，如 Intel Realsense 相机、Leopard Imaging 的 Hawk Stereo 相机、Stereolabs 的 ZED X，以及来自 Hesai、Velodyne、 SLAMTEC、SICK 和 Ouster 的 Lidar 均已可用，更多传感器可在 Camera Sensors 和 RTX Lidar Sensors 中找到。这些传感器可以直接添加到机器人和环境中。

配置 ROS 2 Bridge 接口#

Isaac Sim 通过 ROS 2 Bridge 扩展与 ROS 2 连接。开发人员可以通过此扩展以两种主要方式与 ROS 2 进行交互：

  1. ROS 2 OmniGraph 节点

  2. Python 脚本

ROS 2 OmniGraph 节点#

此 ROS 2 Bridge 扩展包含专为 ROS 2 开发者设计的各种 Isaac Sim OmniGraph 教程 (OG) 节点。 OG 节点与 ROS 2 节点不同，它们拥有独立的框架。OG 节点提供封装好的功能模块，可在连接的图结构中使用，以在仿真场景中执行复杂任务。例如，可以创建一个 OG 节点，用于在当前 stage 中添加一个立方体，并根据某些约束条件改变其位置。Isaac Sim 的扩展中提供了大量 OG 节点。

ROS 2 Bridge 为开发者提供了多种适用于机器人任务且可与 ROS 2 交互的 OG 节点。这些 OG 节点可用于发布来自仿真相机或激光雷达的数据、发布机器人的变换树以及订阅速度消息。请参阅 ROS 2 页面。 它们可以连接起来构建 Action Graph，从而结合流行的 ROS 2 软件包实现导航和操控等复杂任务。 许多常用的 Action Graph 现在可以直接添加到场景中，可在 常用 OmniGraph 快捷方式 中找到。

上图展示了一个使用 OG 节点创建的简单 action graph。该图使得能够以适当的消息类型在 ROS 2 topic 上发布仿真时间。 上图中的部分关键 OG 节点执行以下任务：

  1. On Playback Tick：此节点在回放期间执行输出执行脉冲

  2. Isaac Read Simulation Time：提供仿真时间

  3. ROS 2 Publish Clock：此 OG 节点是 ROS 2 Bridge Extension 的一部分。当它连接到 ‘On Playback Tick’ 的输出后便会激活。它从 ‘Isaac Read Simulation Time’ 节点接收仿真时间，并将其发布到 ROS 2 topic，该 topic 可在节点中进行修改。这一点非常重要，因为仿真时间用于同步 ROS 2 节点，而仿真时间并不等同于现实世界时间。

ROS 2 OG 节点还具有各种可修改的参数，例如 topic 名称、命名空间、上下文和 QoS。

开发人员还可以使用 C++ 或 Python 编写自己的 OG 节点，以满足特定任务的需求。例如，如果您想在自定义消息 topic 上发布接触传感器状态。

Python 脚本编写#

Isaac Sim 内置了 Python 3 环境。您可以通过 Script Editor 或独立的 Python Environment 访问该环境。启用 ROS 2 Bridge 后，即可访问 rclpy，即 ROS 2 的 Python 客户端库。 这使得您可以编写包含节点、服务和操作的自定义 ROS 2 代码，这些代码可以在使用 Python 进行脚本编写时直接访问和修改场景及仿真机器人的数据。在运行 Isaac Sim 之前 source 您的工作区，即可启用对 ROS 2 自定义消息的支持。请参阅 ROS 2 Python Custom Messages 教程。

还可以使用 Python API 创建、修改 ROS 2 OG 节点并将其连接以形成 Action Graph。

仿真场景#

在导入环境和机器人并设置好 ROS 2 的 action graph 后，即可开始仿真场景。 在仿真中点击播放后，所有 ROS 2 OG 节点都将进入 active 状态，并根据图的设置发布和订阅数据。 需要注意的是，所有 ROS 2 OmniGraph 节点都依赖于仿真处于运行或活动状态，这发生在点击播放之后。

ROS 2 软件包#

启动仿真后，开发人员可以使用其 ROS 2 软件包来控制仿真中的机器人和场景。ROS 2 OG 节点或您的 Python 代码将充当与 ROS 2 软件进行接口交互并控制场景中仿真机器人的角色。例如，可以使用 ROS 2 bridge 发送传感器和机器人状态数据，供机器人软件栈使用。这些算法可能会根据接收到的输入输出动作。然后，仿真机器人执行这些动作。

ROS 2 Bridge 在独立工作流中的应用#

学习目标#

  • 运行独立的 ROS 2 Python 示例

  • 手动逐步执行 ROS 2 组件

请在此页面顶部的 Standalone Environment 横幅中验证或选择您的配置，以查看适用于您设置的启动命令。您的选择将决定本页面其余部分中特定于平台的命令。

独立环境

Platform:

入门指南#

先决条件

  • 已完成 开发方法 和 Hello World 教程，以了解两种工作流（独立模式和扩展模式）。

当未设置 ROS_DISTRO 时，python.sh 启动器会自动配置捆绑的 ROS 2 环境。它在 Ubuntu 22.04 上选择 ROS 2 Humble，在 Ubuntu 24.04 上选择 ROS 2 Jazzy，因此您无需在运行本页面中的示例之前设置 ROS_DISTRO、RMW_IMPLEMENTATION 或 LD_LIBRARY_PATH。

如果您使用系统 ROS 安装或包含自定义 ROS 接口的工作空间，请在运行 python.sh 之前加载该环境。启动器会保留现有的 ROS 环境。有关手动覆盖设置（包括 ROS_DISTRO、RMW_IMPLEMENTATION 和 LD_LIBRARY_PATH）的信息，请参阅 配置选项并启用内部 ROS 库。

若要禁用自动 ROS 配置，请在独立脚本路径之前传递 --no-ros-env。启动器在启动 Python 之前会移除该选项：

./python.sh --no-ros-env <path/to/standalone/script.py>

从 Isaac Sim 包目录中使用捆绑的 python.bat 启动器运行 Windows 独立 ROS 2 示例。当未设置 ROS_DISTRO 时，启动器会自动配置捆绑的 ROS 2 Jazzy 库。

若要使用 Zenoh，请通过 Pixi 工作空间运行独立脚本，或在运行 python.bat 之前选择 Isaac Sim 中捆绑的 Zenoh 库。有关这两种工作流，请参阅 使用 Zenoh 启用 ROS 2 桥接（ROS 2 Jazzy）。

注意

在 Windows 11 中，根据您机器的配置，RViz2 可能无法正常打开。

手动步进 ROS 2 组件#

独立脚本通常非常适合手动控制仿真步骤。可以将 OnImpulseEvent OmniGraph 节点连接到任何 ROS 2 OmniGraph 节点，从而精确控制发布者和订阅者的频率。

以下是一个示例，展示了如何设置包含 ROS2 Publish Clock 节点的新动作图，并使用 ROS 2 域 ID 1 对其进行精确控制：


import omni.graph.core as og

# Create a new graph with the path /ActionGraph
og.Controller.edit(
    {"graph_path": "/ActionGraph", "evaluator_name": "execution"},
    {
        og.Controller.Keys.CREATE_NODES: [
            ("ReadSimTime", "isaacsim.core.nodes.IsaacReadSimulationTime"),
            ("Context", "isaacsim.ros2.bridge.ROS2Context"),
            ("PublishClock", "isaacsim.ros2.bridge.ROS2PublishClock"),
            ("OnImpulseEvent", "omni.graph.action.OnImpulseEvent"),
        ],
        og.Controller.Keys.CONNECT: [
            # Connecting execution of OnImpulseEvent node to PublishClock so it will only publish when an impulse event is triggered
            ("OnImpulseEvent.outputs:execOut", "PublishClock.inputs:execIn"),
            # Connecting simulationTime data of ReadSimTime to the clock publisher node
            ("ReadSimTime.outputs:simulationTime", "PublishClock.inputs:timeStamp"),
            # Connecting the ROS2 Context to the clock publisher node so it will run under the specified ROS2 Domain ID
            ("Context.outputs:context", "PublishClock.inputs:context"),
        ],
        og.Controller.Keys.SET_VALUES: [
            # Assigning topic name to clock publisher
            ("PublishClock.inputs:topicName", "/clock"),
            # Assigning a Domain ID of 1 to Context node
            ("Context.inputs:domain_id", 1),
            # Disable useDomainIDEnvVar to ensure we use the above set Domain ID
            ("Context.inputs:useDomainIDEnvVar", False),
        ],
    },
)

在任意帧运行以下命令以设置脉冲事件，这将使时钟发布者触发一次：

og.Controller.set(og.Controller.attribute("/ActionGraph/OnImpulseEvent.state:enableImpulse"), True)

注意

由于在独立脚本中显式控制渲染和物理仿真步骤，完成每个步骤所需的时间将取决于计算负载，并且很可能与实时时间不匹配。这可能会导致在使用独立脚本与使用 GUI 运行同一应用程序时，观察到的动作速度存在差异。当发生这种情况时，请以仿真时钟为参考。

示例#

部分教程示例已转换为独立 Python 示例。以下是运行这些示例的说明。

ROS 2 时钟#

此示例演示了如何创建包含 ROS 2 组件节点的动作图，并以不同的频率触发它们。

运行以下命令即可执行该示例：

./python.sh standalone_examples/api/isaacsim.ros2.bridge/clock.py

python.bat standalone_examples\api\isaacsim.ros2.bridge\clock.py

回显以下主题以观察发布的消息：

ros2 topic echo /sim_time
ros2 topic echo /manual_time

若要使用 Isaac Sim UI 创建并设置 ROS 2 时钟发布者，请参阅 ROS 2 时钟 教程。

ROS 2 相机#

以下两个示例演示了如何使用 ROS 2 Camera Helper 和 Camera Info Helper OmniGraph 节点创建动作图，这些节点用于设置 ROS 2 RGB 图像、深度图像和相机信息发布者。 这两个示例都实现了以不同频率发布 ROS 2 图像数据的目标，但采用了不同的解决方案。

  • 每帧：

    • 发布 Camera Info

  • 每 5 帧：

    • 发布 RGB 图像

  • 每 60 帧：

    • 发布深度图像

周期性图像发布#

在 SDGPipeline 图中，通过修改每个 ROS 2 图像和相机信息发布者对应的 Isaac Simulation Gate OmniGraph 节点，来设置其执行频率（每 N 帧）。 通过设置执行频率，图像发布者将自动在每 N 个渲染帧被触发一次。

运行以下命令即可执行该示例：

./python.sh standalone_examples/api/isaacsim.ros2.bridge/camera_periodic.py

python.bat standalone_examples\api\isaacsim.ros2.bridge\camera_periodic.py

要退出示例，可以在终端中使用 CTRL-C 终止进程。

手动图像发布#

ROS 2 图像和相机信息发布者通过在每个发布者节点与其对应的 Isaac Simulation Gate OmniGraph 节点之间注入 Branch OmniGraph 节点来进行手动控制。 Branch 节点充当自定义门控，可以随时启用或禁用。每当 Branch 节点被启用时，连接的 ROS 2 发布者节点就会被触发。

运行以下命令即可执行该示例：

./python.sh standalone_examples/api/isaacsim.ros2.bridge/camera_manual.py

python.bat standalone_examples\api\isaacsim.ros2.bridge\camera_manual.py

要退出示例，可以在终端中使用 CTRL-C 终止进程。

可视化结果#

要在 RViz2 中可视化任一示例的结果，请在新的已加载 ROS 2 环境的终端中导航至 Isaac Sim 包目录，并运行以下命令：

rviz2 -d <ros2_ws>/src/isaac_tutorials/rviz2/camera_manual.rviz

注意

由于 RViz2 存在一个问题，深度图像显示可能会出现黑帧。在 Linux 上，你可以通过运行 ros2 run rqt_image_view rqt_image_view 并将话题设置为 /depth 来验证 Isaac Sim 是否正确发布深度图像。rqt_image_view 在 Windows 上不受支持。

使用 rclpy 进行异步图像发布#

此示例直接从 rclpy 通过 ROS 2 发布相机图像，无需使用 OmniGraph 动作图。 它构建了一个小型自包含场景，将每个渲染帧从 GPU 内存复制到复用的 sensor_msgs/Image 中，并从后台线程发布，从而确保复制和发布操作不会阻塞仿真循环。 当你希望完全通过 Python 控制图像发布的方式和时机时，请使用此示例。

运行以下命令即可执行该示例：

./python.sh standalone_examples/api/isaacsim.ros2.bridge/camera_rclpy_async.py

python.bat standalone_examples\api\isaacsim.ros2.bridge\camera_rclpy_async.py

要验证达到的发布速率，请在新的已加载 ROS 2 环境的终端中运行 ros2 topic hz /rgb。你还可以使用 Isaac Sim ROS Workspaces 中的 Greenwave Monitor，从 ROS 2 节点检查相同的实际时间到达率：

ros2 run greenwave_monitor greenwave_monitor --ros-args \
   -p gw_monitored_topics:='["/rgb"]' \
   -p gw_time_check_preset:=nodetime_only

要退出示例，可以在终端中使用 CTRL-C 终止进程。

Carter 立体视觉#

此示例演示了如何获取包含 ROS 2 组件节点的动作图的现有 USD 阶段，并修改默认设置。立体相机对会自动启用，第二个视口窗口会停靠在 UI 中。

  • 每帧执行以下操作：

    • 发布 ROS 2 时钟

    • 发布源自 RTX Lidar 的 ROS 2 PointCloud2 消息

    • 发布里程计数据

    • 运行 Twist 订阅者回调

    • 发布 TF 消息

    • 发布左相机和右相机图像

  • 每两帧执行以下操作：

    • 发布 Twist 命令消息

运行以下命令即可执行该示例：

./python.sh standalone_examples/api/isaacsim.ros2.bridge/carter_stereo.py

python.bat standalone_examples\api\isaacsim.ros2.bridge\carter_stereo.py

要退出示例，可以在终端中使用 CTRL-C 终止进程。

要可视化结果：

在新的终端中，运行以下命令以加载 RViz2：

rviz2 -d <ros2_ws>/src/isaac_tutorials/rviz2/carter_stereo.rviz

确保 Displays 中的 Right Camera - RGB 和 Left Camera - RGB 已启用，以便可视化 RGB 图像。

注意

如果某些图像未在 RViz2 中显示，请在模拟器中按 Stop 和 Play，以便图像显示出来。

多机器人 ROS 2 导航#

此示例演示了如何运行现有的 USD 阶段。

要可视化输出，请参阅此示例的交互版本：

  • 每帧执行以下操作：

    • 发布 ROS 2 时钟组件

    • 发布源自 RTX Lidar 的 ROS 2 PointCloud2 消息

    • 发布里程计数据

    • 运行 Twist 订阅器

    • 发布 TF 消息

该示例可在医院和办公室环境中运行。 运行以下任一命令，即可在指定环境中运行该示例：

./python.sh standalone_examples/api/isaacsim.ros2.bridge/carter_multiple_robot_navigation.py --environment hospital

python.bat standalone_examples\api\isaacsim.ros2.bridge\carter_multiple_robot_navigation.py --environment hospital

./python.sh standalone_examples/api/isaacsim.ros2.bridge/carter_multiple_robot_navigation.py --environment office

python.bat standalone_examples\api\isaacsim.ros2.bridge\carter_multiple_robot_navigation.py --environment office

接收 ROS 2 消息#

这是一个基本的订阅者示例，当接收到空的 ROS 2 消息时，场景中的立方体会传送至随机位置。该示例在启用渲染的情况下运行，您可以观察场景以及立方体的移动。要运行此示例：

./python.sh standalone_examples/api/isaacsim.ros2.bridge/subscriber.py

python.bat standalone_examples\api\isaacsim.ros2.bridge\subscriber.py

要退出示例，可以在终端中使用 CTRL-C 终止进程。

加载包含立方体的场景后，您可以从另一个终端手动发布空消息。使用 1Hz 的频率。

ros2 topic pub -r 1 /move_cube std_msgs/msg/Empty

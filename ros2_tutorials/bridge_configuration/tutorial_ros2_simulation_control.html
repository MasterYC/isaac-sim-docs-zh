ROS 2 仿真控制#

学习目标#

在本页面中，您将学习如何：

  • 了解 Isaac Sim 的 ROS 2 Simulation Control 扩展

  • 使用 ROS 2 服务和动作控制 Isaac Sim 仿真

  • 使用 ROS 2 接口操作仿真实体和世界

  • 以编程方式步进仿真

入门指南#

先决条件

  • 完成 ROS 2 安装。

  • 如果使用多个系统，请在启动 Isaac Sim 之前，按照 ROS 2 安装 中的说明设置 FASTRTPS_DEFAULT_PROFILES_FILE 环境变量，并在发送或接收 ROS 消息以及启用 ROS 2 Extension 的任何终端中也进行相应设置。

  • Isaac Sim 5.0 或更高版本

  • ROS 2（Humble 或更高版本）

  • 使用以下命令安装 Simulation Interfaces 软件包：

    sudo apt install ros-humble-simulation-interfaces

    sudo apt install ros-jazzy-simulation-interfaces

    有关参考，请查看 Simulation Interfaces 软件包的源代码，点击此处。

注意

此扩展目标版本为 simulation_interfaces 1.5.0 或更高版本。如果已安装的软件包中缺少某个服务或 SimulatorFeatures 常量，则相应的服务将跳过注册，并且该功能将从 GetSimulatorFeatures 响应中省略——启动时将记录一条警告，指明不可用的类型。

概述#

ROS 2 Simulation Control 扩展使用 ROS 2 Simulation Interfaces 来控制 Isaac Sim 功能。此扩展设计为可扩展的，允许同时运行多个服务和动作，且性能开销很小。

该扩展通过 ROS 2 服务和动作提供对 Isaac Sim 的全面控制，包括：

  • 仿真状态控制：播放、暂停、停止和逐步执行仿真

  • 实体管理：生成、删除和操作仿真实体（prims）

  • 世界管理：加载、卸载和查询仿真世界（USD 文件）

  • 状态查询：获取有关实体、仿真状态和可用资源的信息

这使您能够通过编程方式或使用 Simulation Interfaces 包通过 ROS 2 命令行界面来控制 Isaac Sim，从而支持自动化测试等工作流。本页列出了 Isaac Sim 支持的 Simulation Interfaces 中的所有服务和动作，并提供了示例命令。

启用扩展#

自动启用#

  1. 使用以下命令从终端打开 Isaac Sim：

    ./isaac-sim.sh --/isaac/startup/ros_sim_control_extension=True

手动启用#

  1. 打开 Isaac Sim

  2. 从 Extension Manager 启用扩展： isaacsim.ros2.sim_control

可用的服务和动作#

该扩展提供以下 ROS 2 服务：

  • /get_simulator_features：列出此 Isaac Sim 实现中支持的功能

  • /set_simulation_state：将仿真设置为特定状态（stopped/playing/paused/quitting）

  • /get_simulation_state：获取当前仿真状态

  • /get_entities：获取仿真中所有实体（prims）的列表

  • /get_entity_info：获取特定实体的详细信息（当前返回 OBJECT 类别类型）

  • /get_entity_state：获取特定实体的位姿、twist 和加速度

  • /get_entities_states：获取多个实体的状态（位姿、twist 和加速度），并支持过滤

  • /delete_entity：从仿真中删除特定实体（prim）

  • /spawn_entity：在指定位置生成新实体到仿真中（已弃用 — 请改用 /spawn_entities）

  • /reset_simulation：将仿真环境重置为初始状态

  • /set_entity_state：设置仿真中特定实体的状态（位姿、twist）

  • /step_simulation：将仿真向前推进指定的帧数

  • /load_world：将世界或环境文件加载到仿真中

  • /unload_world：卸载当前世界并创建一个空的 stage

  • /get_current_world：获取当前加载的世界的信息

  • /get_available_worlds：获取可加载的可用世界文件列表

  • /spawn_entities：在单个请求中批量生成多个实体（在 Humble 上需要 simulation_interfaces >= 1.4.0，在 Jazzy 上需要 >= 1.5.0）

  • /get_entity_bounds：获取实体的世界空间轴对齐边界框

  • /get_spawnables：发现可生成的可用 USD 资产

以及以下 ROS 2 动作：

  • /simulate_steps：用于步进仿真并提供进度反馈的动作

使用 ROS 2 仿真控制服务#

本节详细介绍如何使用每个可用服务。

GetSimulatorFeatures 服务#

GetSimulatorFeatures 服务列出 Isaac Sim 从 simulation_interfaces 支持的服务和动作子集。

ros2 service call /get_simulator_features simulation_interfaces/srv/GetSimulatorFeatures

注意：

  • 返回支持的功能列表（例如，SPAWNING、DELETING、ENTITY_STATE_GETTING）

  • 通过 spawn_formats 字段报告对 USD 文件格式的支持

  • 提供包含实现详细信息的 custom_info

  • 有关完整的仿真器功能列表，请参阅 此处

SetSimulationState 服务#

SetSimulationState 服务用于更新仿真的全局状态（stopped/playing/paused/quitting），这些状态对应于 SimulationState.msg 中定义的枚举值（STATE_STOPPED、STATE_PLAYING、STATE_PAUSED、STATE_QUITTING）。

  1. 将仿真状态设置为播放：

    ros2 service call /set_simulation_state simulation_interfaces/srv/SetSimulationState "{state: {state: 1}}"  # 1=playing

  2. 将仿真状态设置为暂停：

    ros2 service call /set_simulation_state simulation_interfaces/srv/SetSimulationState "{state: {state: 2}}"  # 2=paused

  3. 将仿真状态设置为停止：

    ros2 service call /set_simulation_state simulation_interfaces/srv/SetSimulationState "{state: {state: 0}}"  # 0=stopped

  4. 退出仿真器：

    ros2 service call /set_simulation_state simulation_interfaces/srv/SetSimulationState "{state: {state: 3}}"  # 3=quit

注意：

  • 状态 0（Stopped）等同于暂停并重置仿真

  • 状态 1（Playing）启动仿真时间轴

  • 状态 2（Paused）在当前时间暂停仿真

  • 状态 3（Quitting）关闭 Isaac Sim

GetSimulationState 服务#

GetSimulationState 服务用于获取整个仿真的当前状态（stopped/playing/paused/quitting），这些状态对应于 SimulationState.msg 中定义的枚举值（STATE_STOPPED、STATE_PLAYING、STATE_PAUSED、STATE_QUITTING）。

ros2 service call /get_simulation_state simulation_interfaces/srv/GetSimulationState

注意：

  • 停止时返回状态 0，播放时返回 1，暂停时返回 2

  • 用于在执行步进等操作之前查询仿真状态

GetEntities 服务#

GetEntities 服务检索仿真中所有实体的列表，并支持可选的过滤（使用正则表达式模式）。

  1. 获取仿真中的所有实体：

    ros2 service call /get_entities simulation_interfaces/srv/GetEntities "{filters: {filter: ''}}"

  2. 获取具有完整路径或部分路径的实体。在此示例中，过滤路径中包含 ‘camera’ 的 prim：

    ros2 service call /get_entities simulation_interfaces/srv/GetEntities "{filters: {filter: 'camera'}}"

  3. 获取路径以 ‘/World’ 开头的实体：

    ros2 service call /get_entities simulation_interfaces/srv/GetEntities "{filters: {filter: '^/World'}}"

  4. 获取路径以 ‘mesh’ 结尾的实体：

    ros2 service call /get_entities simulation_interfaces/srv/GetEntities "{filters: {filter: 'mesh$'}}"

注意：

  • filter 参数接受 POSIX 扩展正则表达式，用于匹配实体名称（prim 路径）

  • Isaac Sim 使用完整的 USD prim 路径作为实体名称

GetEntityInfo 服务#

GetEntityInfo 服务提供特定实体的详细信息，例如其类型和属性。

ros2 service call /get_entity_info simulation_interfaces/srv/GetEntityInfo "{entity: '/World/robot'}"

注意：

  • 如果实体存在，则返回包含 EntityInfo 的 RESULT_OK

  • 如果实体不存在，则返回 RESULT_OPERATION_FAILED

  • EntityInfo 包含： * category：当前始终设置为 OBJECT (EntityCategory.OBJECT) * description：空字符串（保留供未来使用） * tags：空数组（保留供未来使用）

GetEntityState 服务#

GetEntityState 服务获取特定实体相对于给定参考系的位姿、twist 和加速度。目前仅支持世界坐标系。

ros2 service call /get_entity_state simulation_interfaces/srv/GetEntityState "{entity: '/World/robot'}"

注意：

  • 对于具有 RigidBodyAPI 的实体，将返回位姿和速度

  • 对于没有 RigidBodyAPI 的实体，仅返回位姿，速度为零

  • 加速度值始终报告为零（当前 API 未提供）

  • 如果成功检索到实体状态，则返回 RESULT_OK

  • 如果实体不存在，则返回 RESULT_NOT_FOUND

  • 如果检索实体状态时出错，则返回 RESULT_OPERATION_FAILED

GetEntitiesStates 服务#

GetEntitiesStates 服务获取仿真中多个实体在世界坐标系下的状态（位姿、twist、加速度）。

  1. 获取仿真中所有实体的状态：

    ros2 service call /get_entities_states simulation_interfaces/srv/GetEntitiesStates "{filters: {filter: ''}}"

  2. 获取路径中包含 ‘robot’ 的实体的状态：

    ros2 service call /get_entities_states simulation_interfaces/srv/GetEntitiesStates "{filters: {filter: 'robot'}}"

  3. 获取路径以 ‘/World’ 开头的实体的状态：

    ros2 service call /get_entities_states simulation_interfaces/srv/GetEntitiesStates "{filters: {filter: '^/World'}}"

注意：

  • 结合了 GetEntities 和 GetEntityState 服务的功能

  • 首先使用正则表达式模式匹配来过滤实体

  • 检索每个过滤后实体的状态

  • 返回实体路径及其对应状态的列表

  • 对于具有 RigidBodyAPI 的实体，将返回位姿和速度

  • 对于没有 RigidBodyAPI 的实体，仅返回位姿，速度为零

  • 加速度值始终报告为零（当前 API 未提供）

  • 当需要获取多个实体的状态时，使用此服务比进行多次 GetEntityState 调用更高效

  • 如果成功检索到实体状态，则返回 RESULT_OK

  • 如果在过滤或检索状态时出错，则返回 RESULT_OPERATION_FAILED

DeleteEntity 服务#

DeleteEntity 服务用于删除模拟中指定的实体。

ros2 service call /delete_entity simulation_interfaces/srv/DeleteEntity "{entity: '/World/robot'}"

注意：

  • 如果实体已成功删除，该服务将返回 RESULT_OK

  • 如果实体受保护且无法删除，则返回 RESULT_OPERATION_FAILED

  • 在尝试删除之前，使用 prim_utils.is_prim_no_delete() 检查 prim 是否可以被删除

GetSpawnables 服务#

GetSpawnables 服务用于发现可用于生成的 USD 资产。默认情况下，它在 Isaac 资产根路径中搜索 /Isaac/Samples/ROS2/Robots。您可以使用 sources 字段提供额外的 自定义搜索路径。

  1. 列出所有默认的可生成项：

    ros2 service call /get_spawnables simulation_interfaces/srv/GetSpawnables

  2. 从额外的本地路径列出可生成项：

    ros2 service call /get_spawnables simulation_interfaces/srv/GetSpawnables "{sources: ['/home/user/custom_robots']}"

  3. 从多个来源列出可生成项：

    ros2 service call /get_spawnables simulation_interfaces/srv/GetSpawnables "{sources: ['/home/user/robots', '/opt/isaac_assets/robots']}"

注意：

  • 默认搜索路径为 /Isaac/Samples/ROS2/Robots（搜索深度为 2）

  • sources 中的额外路径会被递归搜索（无限深度）

  • 每个结果都是一个 Spawnable，包含 uri（完整的资源 URI）、description（不含扩展名的文件名）以及空的 spawn_bounds

  • 如果既没有可用的资源根路径，也未提供 sources，则返回 RESULT_OPERATION_FAILED

注意

Windows 用户（包括 WSL）：在 sources 中提供路径时，请使用原生 Windows 路径（例如，C:/Users/foo/robots）。Isaac Sim Windows 进程无法访问 WSL 风格的路径（如 /mnt/c/Users/foo/robots），因此不会返回任何结果。

SpawnEntity 服务#

警告

已弃用。请改用 /spawn_entities 服务。SpawnEntities 支持批量操作和逐实体错误报告，适用于单实体和多实体工作流。

SpawnEntity usage (deprecated)

SpawnEntity 服务在指定位置向仿真中生成一个新实体。

  1. 使用默认位置生成基本实体：

    ros2 service call /spawn_entity simulation_interfaces/srv/SpawnEntity "{name: 'MyEntity', allow_renaming: false, uri: '/path/to/model.usd'}"

  2. 使用特定位置和方向生成：

    ros2 service call /spawn_entity simulation_interfaces/srv/SpawnEntity "{name: 'PositionedEntity', allow_renaming: false, uri: '/path/to/model.usd', initial_pose: {pose: {position: {x: 1.0, y: 2.0, z: 3.0}, orientation: {w: 1.0, x: 0.0, y: 0.0, z: 0.0}}}}"

  3. 创建空的 Xform（无 URI）：

    ros2 service call /spawn_entity simulation_interfaces/srv/SpawnEntity "{name: 'EmptyXform', allow_renaming: false, uri: ''}"

  4. 启用自动重命名：

    ros2 service call /spawn_entity simulation_interfaces/srv/SpawnEntity "{name: 'AutoRenamedEntity', allow_renaming: true, uri: '/path/to/model.usd'}"

  5. 指定命名空间：

    ros2 service call /spawn_entity simulation_interfaces/srv/SpawnEntity "{name: 'NamespacedEntity', allow_renaming: false, uri: '/path/to/model.usd', entity_namespace: 'robot1'}"

注意：

  • 如果提供了 URI，则将 USD 文件作为引用加载到给定的 prim 路径中

  • 如果未提供 URI，则在给定的 prim 路径处创建一个 Xform

  • 所有生成的 prim 都会标记有 simulationInterfacesSpawned 属性以便追踪

  • 如果实体成功生成，则返回 RESULT_OK

  • 如果实体名称已存在且 allow_renaming 为 false，则返回 NAME_NOT_UNIQUE (101)

  • 如果实体名称为空且 allow_renaming 为 false，则返回 NAME_INVALID (102)

  • 如果解析或加载 USD 文件失败，则返回 RESOURCE_PARSE_ERROR (106)

SpawnEntities 服务#

SpawnEntities 服务在单个请求中生成多个实体。spawn_requests 中的每个条目都遵循 SpawnEntity.msg 格式，并独立处理。 每个实体的成功或失败状态会在 results 列表中报告。

注意

此服务要求在 ROS 2 Humble 上 simulation_interfaces >= 1.4.0，在 ROS 2 Jazzy 上 >= 1.5.0。

  1. 在特定位置生成两个实体：

    ros2 service call /spawn_entities simulation_interfaces/srv/SpawnEntities "{
  spawn_requests: [
    {
      name: 'Robot1',
      allow_renaming: false,
      entity_resource: {uri: '/path/to/robot.usd'},
      initial_pose: {pose: {position: {x: 0.0, y: 0.0, z: 0.0}, orientation: {w: 1.0, x: 0.0, y: 0.0, z: 0.0}}}
    },
    {
      name: 'Robot2',
      allow_renaming: true,
      entity_resource: {uri: '/path/to/robot.usd'},
      initial_pose: {pose: {position: {x: 2.0, y: 0.0, z: 0.0}, orientation: {w: 1.0, x: 0.0, y: 0.0, z: 0.0}}}
    }
  ]
}"

注意：

  • spawn_requests 中的每个条目使用 entity_resource.uri 字段（而不是 SpawnEntity 使用的扁平 uri 字段）

  • 每个实体的结果在 results 列表中返回；检查每个 SpawnResult 以获取单个实体的成功或失败状态

  • 如果任何单个生成操作失败，聚合 result 字段将设置为 ENTITIES_SPAWN_FAILED

  • 所有其他 SpawnEntity 规则均适用于每个条目（自动重命名、simulationInterfacesSpawned 标记等）

GetEntityBounds 服务#

GetEntityBounds 服务计算并返回实体的世界空间轴对齐边界框 (AABB)。

ros2 service call /get_entity_bounds simulation_interfaces/srv/GetEntityBounds "{entity: '/World/Cube'}"

注意：

  • 返回一个包含 type=TYPE_BOX 和两个 points 的 Bounds 消息：AABB 的最小角点和最大角点

  • 边界框在默认 USD 时间码处计算，仅包含具有 default 用途的 prim

  • 如果实体不存在，则返回 RESULT_NOT_FOUND

  • 如果边界计算失败，则返回 RESULT_OPERATION_FAILED

ResetSimulation 服务#

ResetSimulation 服务将仿真环境重置为初始状态。

ros2 service call /reset_simulation simulation_interfaces/srv/ResetSimulation

注意：

  • 停止仿真时间轴

  • 查找并移除所有具有 simulationInterfacesSpawned 属性的 prim

  • 使用多次遍历以确保移除所有生成的实体

  • 重启仿真时间轴

  • 如果重置成功，则返回 RESULT_OK

  • 如果重置仿真时出错，则返回 RESULT_OPERATION_FAILED

SetEntityState 服务#

SetEntityState 服务设置仿真中特定实体的状态（位姿、旋量）。目前仅接受 world 坐标系中的变换。

  1. 仅设置位置和方向：

    ros2 service call /set_entity_state simulation_interfaces/srv/SetEntityState "{
  entity: '/World/Cube',
  state: {
    header: {frame_id: 'world'},
    pose: {
      position: {x: 1.0, y: 2.0, z: 3.0},
      orientation: {w: 1.0, x: 0.0, y: 0.0, z: 0.0}
    },
    twist: {
      linear: {x: 0.0, y: 0.0, z: 0.0},
      angular: {x: 0.0, y: 0.0, z: 0.0}
    }
  }
}"

  2. 设置位置、方向和速度（适用于具有刚体物理属性的实体）：

    ros2 service call /set_entity_state simulation_interfaces/srv/SetEntityState "{
  entity: '/World/RigidBody',
  state: {
    header: {frame_id: 'world'},
    pose: {
      position: {x: 1.0, y: 2.0, z: 3.0},
      orientation: {w: 1.0, x: 0.0, y: 0.0, z: 0.0}
    },
    twist: {
      linear: {x: 0.5, y: 0.0, z: 0.0},
      angular: {x: 0.0, y: 0.0, z: 0.1}
    }
  }
}"

注意：

  • 对于任何实体，位置和方向始终会被更新

  • 速度仅针对具有 RigidBodyAPI 的实体进行设置

  • 对于非刚体，仅设置位置和方向（速度设置将被忽略）

  • 目前不支持加速度设置，将被忽略

  • 如果成功设置实体状态，则返回 RESULT_OK

  • 如果实体不存在，则返回 RESULT_NOT_FOUND

  • 如果设置实体状态时出错，则返回 RESULT_OPERATION_FAILED

StepSimulation 服务#

StepSimulation 服务模拟有限数量的步骤，并返回到 PAUSED 状态。

  1. 将模拟步进 1 帧（注意：内部将使用 2 个步骤）：

    ros2 service call /step_simulation simulation_interfaces/srv/StepSimulation "{steps: 1}"

  2. 将模拟步进 10 帧：

    ros2 service call /step_simulation simulation_interfaces/srv/StepSimulation "{steps: 10}"

  3. 将模拟步进 100 帧：

    ros2 service call /step_simulation simulation_interfaces/srv/StepSimulation "{steps: 100}"

注意：

  • 在执行步进之前，仿真必须处于暂停状态

  • 服务调用将阻塞，直到所有步骤完成

  • 步进完成后，模拟将自动返回到暂停状态

  • 如果步进成功完成，则返回 RESULT_OK

  • 如果调用服务时模拟未处于暂停状态，则返回 RESULT_INCORRECT_STATE

  • 如果在步进期间发生任何错误，则返回 RESULT_OPERATION_FAILED

LoadWorld 服务#

LoadWorld 服务将世界或环境文件加载到模拟中，清除当前场景并将模拟设置为停止状态。目前支持 USD 格式的世界。

  1. 从 USD 文件加载世界：

    ros2 service call /load_world simulation_interfaces/srv/LoadWorld "{uri: '/path/to/world.usd'}"

  2. 使用 Isaac Sim 示例环境加载示例世界：

    ros2 service call /load_world simulation_interfaces/srv/LoadWorld "{uri: 'https://omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/6.1/Isaac/Environments/Simple_Room/simple_room.usd'}"

  3. 使用 ROS 2 场景加载示例世界：

    ros2 service call /load_world simulation_interfaces/srv/LoadWorld "{uri: 'https://omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/6.1/Isaac/Samples/ROS2/Scenario/carter_warehouse_apriltags_worker.usd'}"

注意：

  • 仅支持 USD 文件（.usd, .usda, .usdc, .usdz）

  • 在加载世界之前，仿真必须处于停止或暂停状态（不能处于播放状态）

  • 加载世界将清除当前场景，并从 USD 文件创建新的舞台

  • 如果无法直接找到给定路径，Isaac Sim 将自动尝试在其前添加默认资产根路径

  • 如果世界成功加载，返回 RESULT_OK

  • 如果不支持文件格式，返回 UNSUPPORTED_FORMAT

  • 如果无法解析或加载 USD 文件，返回 RESOURCE_PARSE_ERROR

  • 如果调用服务时仿真正在播放，返回 RESULT_OPERATION_FAILED

UnloadWorld 服务#

UnloadWorld 服务从仿真中卸载当前世界，清除当前场景并创建一个新的空舞台。之前生成的所有实体都将被移除。

ros2 service call /unload_world simulation_interfaces/srv/UnloadWorld

注意：

  • 在卸载世界之前，仿真必须处于停止或暂停状态（不能处于播放状态）

  • 在卸载当前世界后创建一个新的空舞台

  • 如果世界成功卸载，返回 RESULT_OK

  • 如果当前未加载任何世界，返回 NO_WORLD_LOADED

  • 如果调用服务时仿真正在播放，返回 RESULT_OPERATION_FAILED

GetCurrentWorld 服务#

GetCurrentWorld 服务返回有关当前加载世界的信息，包括其 URI、名称和格式。

ros2 service call /get_current_world simulation_interfaces/srv/GetCurrentWorld

注意：

  • 如果从文件加载了世界，则返回包含 URI 和名称的世界信息

  • 对于在内存中创建的世界（新阶段），返回空 URI 和名称“untitled_world”

  • 如果成功，返回包含世界信息的 RESULT_OK

  • 如果当前未加载任何世界，返回 NO_WORLD_LOADED

GetAvailableWorlds 服务#

GetAvailableWorlds 服务返回可加载到仿真中的可用世界文件列表。它在默认的 Isaac Sim 路径中搜索 USD 世界文件，并支持基于 TagsFilter 的过滤。

  1. 获取所有默认可用世界：

    ros2 service call /get_available_worlds simulation_interfaces/srv/GetAvailableWorlds

  2. 获取带有标签过滤的世界（搜索文件名中包含特定标签的默认世界）：

    ros2 service call /get_available_worlds simulation_interfaces/srv/GetAvailableWorlds "{filter: {tags: ['warehouse', 'carter']}, continue_on_error: true}"

  3. 搜索其他自定义路径：

    ros2 service call /get_available_worlds simulation_interfaces/srv/GetAvailableWorlds "{additional_sources: ['/custom/worlds/path'], continue_on_error: true}"

  4. 仅离线搜索并包含其他本地源：

    ros2 service call /get_available_worlds simulation_interfaces/srv/GetAvailableWorlds "{additional_sources: ['/home/user/custom_worlds', '/opt/isaac_worlds'], offline_only: true, continue_on_error: true}"

注意：

  • 搜索默认的 Isaac Sim 路径：/Isaac/Environments 和 /Isaac/Samples/ROS2/Scenario

  • 支持 TagsFilter，标签匹配模式为 FILTER_MODE_ANY（默认）或 FILTER_MODE_ALL

  • 可以搜索在 additional_sources 中指定的其他自定义路径

  • 设置 offline_only: true 以仅搜索本地文件系统路径

  • 设置 continue_on_error: true 以在部分路径失败时继续搜索

  • 返回包含可用世界列表的 RESULT_OK

  • 如果默认资源路径不可访问且未提供其他源，返回 DEFAULT_SOURCES_FAILED

注意

Windows 用户（包括 WSL）：在 additional_sources 中提供路径时，请使用原生 Windows 路径（例如，C:/Users/foo/worlds）。Isaac Sim Windows 进程无法访问 WSL 风格的路径（如 /mnt/c/Users/foo/worlds），因此不会返回任何结果。

使用 ROS 2 仿真控制动作#

SimulateSteps 动作#

SimulateSteps 动作模拟有限数量的步骤，并在每个步骤后返回反馈并回到 PAUSED 状态。

  1. 基本用法 - 将仿真步进 10 帧：

    ros2 action send_goal /simulate_steps simulation_interfaces/action/SimulateSteps "{steps: 10}"

  2. 带反馈 - 将仿真步进 20 帧并显示反馈：

    ros2 action send_goal /simulate_steps simulation_interfaces/action/SimulateSteps "{steps: 20}" --feedback

注意：

  • 在执行步进之前，仿真必须处于暂停状态

  • 步骤完成后，仿真将返回到暂停状态

  • 您将在每个步骤后收到反馈，显示已完成和剩余的步骤

  • 该动作在执行期间可以取消

技术细节#

该扩展使用 omni.timeline 接口来控制仿真状态，并通过标准服务提供简洁的 ROS 2 接口。实现包括：

  • 一个单例 ROS2ServiceManager，通过单个节点处理所有 ROS 2 服务

  • 一个 SimulationControl 类，与 Isaac Sim 的时间线进行交互

  • 线程安全的实现，使 ROS 2 旋转独立于 Action Graph 接口

扩展#

要添加更多仿真控制服务，请扩展 SimulationControl 类，并在 ROS2ServiceManager 中注册额外的服务。

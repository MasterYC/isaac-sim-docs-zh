教程 1：导入机器人和 USD 资产结构#

Tutorial

在 Isaac Sim 中检查、过滤或调整机器人之前，请先将其导入 Isaac Sim。机器人可能以网格模型、STEP 文件、统一机器人描述格式 (URDF) 或 MuJoCo XML 格式 (MJCF) 文件的形式提供。Isaac Sim 使用 USD 资产结构 3.0 标准将这些资产导入到 OpenUSD 中。

学习目标#

在本教程中，您将：

  • 了解 URDF 连杆和关节，并将 Inspire Hand URDF 导入 Isaac Sim。

  • 了解资产结构 3.0 如何将几何体、材质、元数据、实例和物理属性分离到专用文件中。

  • 检查 Inspire Hand 的文件层级、资产堆栈、物理堆栈以及嵌套的刚体结构。

先决条件#

  • 完成 设置。

URDF 概述#

URDF 通过连杆和关节来描述机器人：

  • 连杆是机器人上的刚体和参考坐标系。

  • 关节连接连杆以形成机器人的运动链。

<link name="r_base_link">
  <visual>
    <origin xyz="0 0 0" rpy="0 0 0" />
    <geometry>
      <mesh filename="../meshes/r_base_link.STL" />
    </geometry>
    <material name="">
      <color rgba="0.827450980392157 0.83921568627451 0.827450980392157 1" />
    </material>
  </visual>
  <collision>
    <origin xyz="0 0 0" rpy="0 0 0" />
    <geometry>
      <mesh filename="../meshes/r_base_link.STL" />
    </geometry>
  </collision>
</link>

visual 标签描述连杆的可见网格和材质。collision 标签描述物理引擎使用的碰撞几何体。URDF 还定义了每个连杆的质量和惯性。

<joint name="right_little_1_joint" type="revolute">
  <origin xyz="-0.00028533 -0.025587 0.1357" rpy="1.6755 0 0" />
  <parent link="r_base_link" />
  <child link="right_little_1" />
  <axis xyz="0 0 -1" />
  <limit lower="0" upper="1.344" effort="1" />
</joint>

关节类型决定了连杆之间的约束方式。parent 和 child 标签标识相连的连杆，而 limit 指定下限和上限、最大力矩，以及在提供时的最大速度。

导入 URDF#

  1. 点击 File > Import 以打开文件导入器。

  2. 打开 Isaac/Samples/Rigging/Inspire/module_1_start/inspire_urdf/urdf/inspire_hand.urdf。

  1. 在 Collider 中，选择 Allow Self-Collision。这允许手部与其自身发生碰撞，这对于设计避免网格穿透的控制器非常重要。

  2. 在 Options 中，可选地将 Robot Type 设置为 End Effector，因为手部将连接到另一个组件。

  3. 将 USD Output 留空，以便将导入的资产写入 URDF 旁边。

  4. 点击 Import。如果手部显示过小，请使用滚轮缩放。

USD 资产结构 3.0#

USD 资产结构 3.0 是 Isaac Sim 6.0 中机器人资产的标准布局。它提供：

  • 将 USD 组件分离到多个文件中，以便于审查和维护。

  • 用于动画、仿真以及不同物理引擎的层（Layers）、载荷（Payloads）和变体（Variants）。

  • 隔离特定于物理引擎的属性，以防止它们的意见（Opinions）发生冲突。

  • 独立的物理调优层，使您可以在更改运行时而不覆盖共享的几何体或元数据。

由此生成的多层结构共享几何体、材质和元数据，同时通过负载（payloads）和变体（variants）组合物理专用数据。您可以在 physics.usda 中编写碰撞过滤，并在 physx.usda 中进行 PhysX 专用的关节调优，而无需编辑基础几何体。

Inspire Hand 概述#

Inspire Hand（来自 Inspire Robotics 的 RH56DFX）是本系列中使用的示例数字孪生体。它是一款紧凑型的欠驱动灵巧手，具有六个驱动自由度和十二个关节。

下图展示了该手的 Asset Structure 3.0 文件层级、资产堆栈和物理堆栈。

文件层级与堆栈#

  • Inspire Hand 文件层级 — 独立的 USD 文件分别存储几何体、材质、机器人元数据、实例、基础场景、物理以及后端专用覆盖项。

  • Inspire Hand 资产堆栈 — 通过层（Layers）和引用（References）组合网格、材质、变换和机器人 API。

  • Inspire Hand 物理堆栈 — 通过负载（Payloads）和变体（Variants）添加刚体、关节、驱动器和后端专用调优，而无需更改基础资产。

综合来看，组合堆栈创建了一个可用于无物理、通用物理、MuJoCo 或 PhysX 的仿真就绪 inspire_hand prim。

资产结构详解#

每个文件都为最终资产贡献了不同的部分。二进制几何层高效地存储大型网格数据；可读的 USDA 层包含可编辑的结构和调优参数。

geometry.usd — 网格文件#

  • 作用：存储机器人使用的网格。

  • 格式：二进制 .usd 以提高效率。

  • 仅包含几何信息，不包含材质或物理属性。

material.usda — 材质文件#

  • 作用：存储机器人材质，例如 Plastic_ABS。

  • 格式：可读的 ASCII .usda。

  • 定义实例层用于视觉网格和碰撞网格的材质及着色器连接。

robot.usda — 机器人元数据#

  • 作用：存储机器人元数据和 Isaac Robot API。

  • 将 IsaacRobotAPI 作为叠加层应用于 inspire_hand prim。

  • 通常包含 isaac:changelog、isaac:description、isaac:license、isaac:namespace 和 isaac:physics:robotJoints。

此层将资产标识为机器人；它不定义几何或物理属性。

over "inspire_hand" (
    prepend apiSchemas = ["IsaacRobotAPI"]
)
{
    string[] isaac:changelog
    string isaac:description
    token isaac:license
    string isaac:namespace
    rel isaac:physics:robotJoints
}

instances.usda — 网格、材质和碰撞体#

  • 作用：将 material.usda 和 geometry.usd 组合成视觉网格和碰撞网格。

  • 引用几何信息，应用材质，并应用 PhysicsCollisionAPI 和 PhysicsMeshCollisionAPI。

  • 使用碰撞近似方法（如 convexHull）来选择碰撞体表示形式。

def Xform "r_base_link_1" (
    prepend references = @./geometries.usd@</Geometries/r_base_link>
)
{
    over "r_base_link" (
        apiSchemas = ["PhysicsCollisionAPI", "NewtonCollisionAPI", "PhysicsMeshCollisionAPI", "NewtonMeshCollisionAPI"]
    )
    {
        token physics:approximation = "convexHull"
        token purpose = "guide"
    }
}

base.usda — 支持动画的场景#

  • 作用：以可实例化引用的形式加载视觉网格和碰撞网格，并为每个连杆应用变换。

  • 引用 instances.usda 并使用 instanceable = true 以实现高效复用。

  • 引用或子层化 robot.usda，以便根图元包含机器人元数据。

  • 定义运动学树和网格放置，不包含关节或驱动数据。

physics.usda — USD 物理文件#

  • 作用：存储与引擎无关的刚体、质量、关节、驱动和状态属性。

  • 应用 PhysicsRigidBodyAPI、PhysicsMassAPI、PhysicsRevoluteJoint、PhysicsDriveAPI、PhysicsJointStateAPI 和 NewtonJointAPI 等 API。

  • 定义关节体、限位、位置和速度状态、保留的 URDF 力矩元数据以及原生速度限制。

此层提供与引擎无关的物理表示形式。

def PhysicsRevoluteJoint "right_little_2_joint" (
    prepend apiSchemas = ["NewtonJointAPI", "NewtonMimicAPI", "PhysicsDriveAPI:angular", "PhysicsJointStateAPI:angular"]
)
{
    float drive:angular:physics:maxForce = 1
    float newton:mimicCoef0 = -0.15
    float newton:mimicCoef1 = 1.1169
    rel newton:mimicJoint = </inspire_hand/Physics/right_little_1_joint>
    uniform token physics:axis = "Z"
    custom rel physics:body0
    prepend rel physics:body0 = </inspire_hand/Geometry/r_base_link/right_little_1>
    custom rel physics:body1
    prepend rel physics:body1 = </inspire_hand/Geometry/r_base_link/right_little_1/right_little_2>
    float physics:lowerLimit = 0
    float physics:upperLimit = 87.490654
    custom float urdf:limit:effort = 1
    float newton:velocityLimit = inf
}

physx.usda — PhysX 文件#

  • 作用：存储 PhysX 特定属性，而不修改通用物理层。

  • 在 physics.usda 中定义的关节之上添加 PhysxJointAPI 等 API。

这种分离机制将特定于后端的调整（如最大速度和求解器设置）保留在通用物理层之外，从而确保 PhysX 的值不会覆盖通用值。这种分离机制控制的是编写，而非解析：每个后端仍会从多个架构中解析出一个值。

over "right_thumb_1_joint" (
    prepend apiSchemas = ["PhysxJointAPI"]
)
{
    float physxJoint:maxJointVelocity = 107
}

警告

PhysX 和 Newton 后端以不同的方式解析关节速度限制。PhysX 读取 physxJoint:maxJointVelocity。Newton 在其解析器顺序中采用第一个已编写的值——先检查 newton:*，再检查 physxJoint:*——并在此停止，因此已编写的 newton:velocityLimit 生效，Newton 永远不会在该关节上查询 physxJoint:maxJointVelocity。由于 newton:velocityLimit = inf 表示无限制，如果在 physics.usda 中为 inf 编写了值，而在 physx.usda 中编写了有限上限，则该关节在 PhysX 下受限制，而在 Newton 下实际上不受限制。

上述两个代码片段编写的是不同的关节，因此它们不会相互影响。当两个架构都在同一关节上编写时，就会出现不匹配的情况。教程 4：关节驱动调整 仅编写了 PhysX 限制，因此当两个后端必须遵守相同的上限时，请编写匹配的 newton:velocityLimit。

嵌套刚体结构#

在 USD 中，刚体链接是镜像 URDF 运动链的嵌套 prim。根链接 r_base_link 携带 PhysicsArticulationRootAPI。每个下游链接携带 PhysicsRigidBodyAPI 和 PhysicsMassAPI。物理关节连接这些链接，但编写在扁平的 /inspire_hand/Physics 范围内。

inspire_hand/Geometry/
└── r_base_link               ← ArticulationRoot + RigidBody
    ├── right_thumb_1         ← RigidBody + joint to r_base_link
    │   └── right_thumb_2     ← RigidBody + joint to right_thumb_1
    │       └── right_thumb_rubber_1
    ├── right_index_1         ← RigidBody + joint to r_base_link
    │   └── right_index_2
    │       └── right_index_rubber_1
    └── right_little_1        ← RigidBody + joint to r_base_link
        └── ...

每个关节通过 physics:body0 和 physics:body1 关系引用其两个刚体。这样既保持了运动学树的可读性，又允许 physics.usda 和 physx.usda 在不改变链接层级的情况下覆盖驱动限制和速度。

inspire_hand/
├── Geometry/             ← Nested rigid-body links
│   └── r_base_link/
│       └── right_thumb_1/ ...
└── Physics/              ← Flat joint scope
    ├── right_thumb_1_joint   body0 → Geometry/r_base_link
    │                         body1 → Geometry/r_base_link/right_thumb_1
    ├── right_thumb_2_joint   body0 → .../right_thumb_1
    │                         body1 → .../right_thumb_1/right_thumb_2
    └── right_index_1_joint   ...

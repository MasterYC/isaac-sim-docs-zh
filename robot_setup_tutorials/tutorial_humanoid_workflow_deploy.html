阶段 5：部署策略#

部署过程必须重建已训练策略的接口和机器人动力学：观测定义及顺序、 历史记录、动作顺序和缩放、执行器行为、初始状态以及控制时序。

请遵循以下两条路径中的一条，不要同时使用。选项 1：Python 部署在 Isaac Sim 中运行仿真 和策略推理，是验证已训练策略能否复现其训练行为的较短路径。选项 2：Isaac ROS 部署导出一个 AGILE LEAPP 包，并通过 ros2_control 和 ROS 2 主题将其推理运行时连接到 Isaac Sim， 这是在同一策略上运行硬件的路径。

选项 1：Python 部署#

导出 IO 描述符#

在训练完成后，当已知带时间戳的运行目录时，导出 IO 描述符。在更改任务配置之前运行此命令， 并将 TIMESTAMP_h2_full_50000 替换为阶段 4 训练命令创建的目录名称：

uv run scripts/train.py \
    --task Velocity-H2-History-v0 \
    --num_envs 1 \
    --max_iterations 0 \
    --run_name export_io_descriptors \
    --headless \
    --viz none \
    env.export_io_descriptors=true \
    env.log_dir=logs/rsl_rl/velocity_h2_history/TIMESTAMP_h2_full_50000

零迭代运行会初始化环境并导出其接口，但不执行训练迭代。它将 IO_descriptors.yaml 写入 logs/rsl_rl/velocity_h2_history/TIMESTAMP_h2_full_50000/io_descriptors/IO_descriptors.yaml。AGILE 还会为此调用创建一个未使用的时间戳运行目录。有关导出接口的详细信息， 请参阅 Isaac Lab IO 描述符。

定位部署工件#

Python 部署使用导出的 TorchScript 策略、env.yaml 和 IO_descriptors.yaml。环境配置提供机器人的初始状态、执行器 参数、仿真时序以及其他部署属性。IO 描述符提供有序的策略 观测值和动作，包括观测历史要求。

将工件保留在同一训练运行目录下的原生位置：

logs/rsl_rl/velocity_h2_history/TIMESTAMP_h2_full_50000/
|-- exported/
|   `-- policy.pt
|-- io_descriptors/
|   `-- IO_descriptors.yaml
`-- params/
    |-- agent.yaml
    `-- env.yaml

自定义集成可以分别引用每个路径。将 agent.yaml 与训练记录一起保留； Python 策略运行器在部署时不会使用它。

运行 Isaac Sim 部署#

阅读 在 Isaac Sim 中部署策略 以获取完整的 工件和控制工作流。然后从 Isaac Sim 根目录运行 H2 独立示例：

./python.sh standalone_examples/api/isaacsim.robot.policy.examples/h2_standalone.py

该示例使用来自 Nucleus 的经过测试的 H2 USD 和策略工件。由于 H2 不是捆绑策略，脚本会直接创建其策略规范。其命令循环向前、向后、向左和向右行走，然后向两个方向转弯。

PolicyArtifact 对模型、环境配置和 IO 描述符进行分组。PolicySpec 添加 H2 USD、PhysX 引擎和自定义绑定。RobotPolicyRunner 配置关节结构，构建观测值，以导出速率运行策略，并应用关节目标。核心构建如下：

artifact = PolicyArtifact.from_files(model_path, env_config_path, descriptor_path)
spec = PolicySpec(
    name="unitree_h2_velocity_history",
    engines={"physx": artifact},
    usd_path=robot_usd_path,
    binding=partial(derive_h2_policy_binding, artifact),
)
robot = RobotPolicyRunner(spec, prim_path="/World/H2", training_engine="physx")
robot.spawn()

robot.restart_from_default_state(command)
robot.step(step_size, command)

运行器通常直接从 IO_descriptors.yaml 派生绑定。H2 的描述符还包含一个零宽度的 RandomPositionAction，它在训练期间移动手臂和头部，但不消耗策略输出。derive_h2_policy_binding 移除该项，因此部署仅命令 14 个经过训练的腿部和腰部关节。策略控制器维护五帧观测历史。

对于其他人形机器人，请替换机器人资产和策略工件。仅当通用描述符映射无法重现导出的项时，才添加自定义绑定。

选项 2：Isaac ROS 部署#

导出 LEAPP 包#

将训练好的检查点导出为 AGILE LEAPP 包。从 AGILE 仓库运行以下命令，并将 RUN_DIRECTORY_NAME 替换为第 4 阶段训练运行：

uv run scripts/export_policy_leapp.py \
    --task Velocity-H2-History-v0 \
    --load_run RUN_DIRECTORY_NAME \
    --disable_graph_visualization

导出会在训练运行下创建一个以任务命名的包：

<RUN_DIRECTORY>/leapp-bundles/Velocity-H2-History-v0/
|-- Velocity-H2-History-v0.yaml
|-- Velocity-H2-History-v0.onnx
`-- Velocity-H2-History-v0_initial_values.safetensors

保持包完整。YAML 文件描述了策略图，并引用了位于其旁边的模型和初始状态文件。请按照使用导出的 AGILE 包来检查并加载它。

准备 Isaac ROS 集成#

请按照Isaac ROS 入门指南创建并激活 Isaac ROS 工作区。对于 Isaac Sim 部署，请使用源码构建路径，因为 Isaac ROS Deploy Isaac Sim 扩展是以源码形式分发的。

请遵循自带本体中的包布局：

<robot>_description/    # URDF, xacro, and simulator assets
<robot>_ros2_control/   # Real-hardware plugin; not required for this simulation stage
<robot>_bringup/        # Controller configuration, policy groups, and launch files

对于此仿真工作流，请重点关注 <robot>_description 和 <robot>_bringup。声明策略所需的命令接口以及关节和 IMU 状态接口。确保机器人描述、LEAPP 元数据、控制器配置和 Isaac Sim 主题之间的名称保持一致。

复用 TopicBasedSystemInterface 将 ros2_control 连接到 Isaac Sim。在此路径中，您无需编写自定义的 SystemInterface。

准备仿真 USD#

Isaac ROS Deploy 烘焙脚本分两个阶段准备 USD：

robot.usd
    -> add_newton_actuators_to_robot
    -> add_ros2_bridge_to_robot
    -> robot_deploy.usd

在烘焙之前，为每个受控关节提供一个有限的 physics:maxForce 值。第一阶段添加显式执行器模型并移除冲突的原生驱动增益。第二阶段添加默认关节状态、IMU、时钟和关节命令 ROS 2 图。如果策略需要此默认集合之外的信号，请添加桥接节点。请使用 Bring your own embodiment 中 Isaac Sim 部分提供的确切命令。

配置并验证控制器#

在 <robot>_bringup 中，调整 controller_manager.yaml 以声明控制器插件、关节和增益。 调整 controller_groups.yaml 以选择 LEAPP 包、将策略源映射到接口，并定义控制器激活顺序。使用 Bring your own embodiment 中链接的 G1 文件作为结构参考，但需移除 G1 特定的关节和阈值。

按以下顺序验证集成：

  1. 展开机器人描述，确认关节和传感器接口具有预期的名称。

  2. 烘焙部署 USD，通过 Isaac ROS Deploy 扩展启动它，并按下 Play。

  3. 在加载策略之前，确认 Isaac Sim 关节和 IMU 状态主题已更新。

  4. 使用 Isaac Sim 硬件类型启动控制器管理器，并确认其声明了预期的接口。

  5. 加载策略控制器组，发送保守的速度命令，并将模拟运动与阶段 4 的 AGILE 评估进行比较。

按层级进行故障排除#

症状

可能的层级

检查项

IO_descriptors.yaml 缺失。

Python 导出。

确认任务是基于 manager 的，并且 env.export_io_descriptors 和 env.log_dir 均已设置。

部署时报告观测值或动作宽度不匹配。

工件接口。

检查策略、环境 YAML 和 IO 描述符是否来自同一任务和训练运行。

策略移动了错误的关节。

绑定或关节顺序。

比较描述符顺序、解析后的关节结构顺序、动作选择以及自定义绑定。

策略运行正常，但与 AGILE 评估结果不同。

被控对象或时序保真度。

比较物理步长、控制间隔、执行器模型、延迟、增益、动作缩放、默认姿态和历史记录。

Isaac ROS Deploy 未收到状态。

仿真桥接。

检查预烘焙的 ROS 2 图、话题名称、时钟、关节状态和 IMU 发布者。

ros2_control 无法声明接口。

控制器配置。

比较 TopicBasedSystemInterface、控制器关节名称、命令接口和策略元数据。

LEAPP 无法加载包。

包完整性。

将 YAML、ONNX 和初始值文件放在一起，并验证 YAML 中引用的路径。

完成检查清单#

  • 所有部署工件均来自同一 Stage 4 运行。

  • 运行时复现了 Actor 观测定义、顺序、缩放、噪声策略和五帧历史。

  • 动作宽度、顺序、偏移、缩放和受控关节与训练一致。

  • 部署的 USD、初始姿态、执行器行为、物理步长、控制间隔和延迟与训练一致。

  • Python 运行器或 ROS 2 桥接加载时无接口错误。

  • 保守的前进、横向、偏航和零指令与 AGILE 评估行为一致。

  • 重置和普通扰动行为与评估保持一致。

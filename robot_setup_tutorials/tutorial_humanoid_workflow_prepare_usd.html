Stage 1：准备人形机器人 USD#

运动策略会学习训练资产所表示的动力学特性。因此，错误的质量、惯性、碰撞、关节或执行器属性都会成为策略学习行为的一部分。在 AGILE 中编码同一机器人之前，请先准备并验证 USD。更长的训练时间无法纠正这些错误；相反，策略会适应错误的模型。

本阶段不假设机器人制造商发布了哪些信息。如果 H2 已发布执行器数值，我们将将其作为示例展示，但即使你仅拥有资产本身，此处的每个流程也都适用。

选择你的起点#

在此阶段，有三种资产可以代表人形机器人，你拥有哪一种仅决定从哪里开始，而不改变需要验证的内容：

资产

何时使用

随附的参考 H2

Isaac/Robots/Unitree/H2/H2.usda，随 Isaac Sim 一起提供。这是针对已知良好的人形机器人练习此阶段的最便捷方式。请从从参考 H2 资产开始开始。

你自己的人形机器人 URDF

大多数读者在实际工作中将遵循的路径。请从从 URDF 导入自定义人形机器人开始。

机器人动物园 H2

参考 AGILE 任务所训练的资产，由 Stage 2 中的 fetch_h2_usd() 检索获取，而非手动打开。你无需准备此资产；请参阅 Stage 2 实际训练的内容。

以上三者均指向后续的检视、姿态、增益和验证章节，这些章节才是本阶段的重点。

Stage 2 实际训练的内容#

参考 H2 任务并不使用你在 Stage 1 中打开的 USD 进行训练。Stage 2 调用 fetch_h2_usd() 从 AGILE Robot Menagerie 中检索 H2，因此对随附的 Isaac Sim 资产所做的编辑不会影响参考运行。

使用 Stage 1 在一个可检视的资产上学习验证流程。对于你自己的人形机器人，请将 Stage 2 的机器人配置指向你在此处验证的 USD。该 USD 随后将成为训练资产，且所有 Stage 1 的检查项都直接适用于它。

请记住这两个 H2 资产之间的以下差异：

  • Menagerie 资产提供了 collision_profile 和 hands 变体集。Stage 2 分别选择 feet_only 和 none。随附资产仅提供 Physics 变体集。如果你的机器人使用变体，请在其 Stage 2 生成配置中定义其名称和选择。

  • 本阶段稍后的碰撞体审计将教你验证碰撞覆盖范围的方法。参考任务使用 Menagerie 资产所选定的碰撞体；你的自定义任务使用你自己 USD 中的碰撞几何体，因此在训练前请对其进行审计。

另请参阅

  • 在 Isaac Sim 中模拟灵巧手 在一个较小的资产上演示了相同的检查、碰撞体和增益调整工作流程。

  • 增益调整器 是调整工作流程以及本阶段未使用的正弦波和 dt 扫描测试模式的参考文档。

  • 为运动策略绑定腿式机器人 介绍了人形机器人上下文之外的通用腿式机器人情况。请注意，其临时锚点附加在躯干上以进行姿态捕获；对于增益测试，请改为锚定关节根。

从参考 H2 资产开始#

从 Content Browser 中打开 Isaac/Robots/Unitree/H2/H2.usda。该资产由 URDF 导入器从 Unitree 的 h2_description 包生成，因此它已经具备此工作流程所期望的结构：

  • 默认 prim 是 H2，关节根是 /H2/Geometry/pelvis。

  • 一个 Physics 变体集包含 physics、physx、mujoco 和 none 负载。在编辑任何内容之前，请在 Property 面板的 Variants 下检查选定的变体，并将物理编辑写入支持该变体的负载层，以便后续的几何更新不会丢弃这些编辑。

  • 该机器人采用浮动基座。它不包含任何固定于世界的关节，这正是运动训练所要求的。

  • 它包含 31 个旋转关节：每条腿六个（hip_pitch、hip_roll、hip_yaw、knee、ankle_roll、 ankle_pitch），三个腰部关节，两个头部关节，以及每条手臂七个。

在训练之前，仍有若干属性需要您关注，由于资产可以正常打开并仿真而不报错，这些属性很容易被忽略：

属性

出厂资产中的状态

操作

驱动刚度与阻尼

所有 31 个关节均统一设置为 1000 和 10，运行时以弧度单位报告为 57295.8 和 573.0。

替换为按组设置的值。腿部与腕部共用单一刚度值只是占位符，而非经过调校的受控对象。全新导入的 URDF 会为两者分别生成 0，因此这两种起始点都无法提供可用的增益。请参阅 编写执行器增益。

最大关节速度

驱动性能包络为 inf，但运行时每个关节仍解析出有限限制，从髋部和膝部的 20 rad/s 到踝部滚转的 100.7 rad/s。

验证而非添加。使用 在 Isaac Sim 中部署策略 中的关节属性代码片段读取解析后的限制值，并确认其与您的硬件匹配，而不是假设 inf 包络意味着驱动无界。

力矩限制

按关节编写，且大多与 Unitree 发布的数值一致。

对照 H2 执行器增益 进行抽查。腰部横滚和俯仰的值为 180 N·m，而 Unitree 发布的腰部组数值为 120 N·m；肩部俯仰的值为 120 N·m，而发布的臂部组数值为 54 N·m。请确认哪一组数值适用于您的硬件。

电枢惯量和关节摩擦

未定义；两者均解析为零。

Unitree 为每个驱动组发布 armature = 0.01。请在此处定义它，或在 Stage 2 的 AGILE 执行器配置中设置它，但请勿在两个地方设置不同的值。

传感器与手部坐标系

缺失。该资产在构建时启用了固定关节合并，因此 imu_in_pelvis、imu_in_torso 以及 URDF 中声明的手部连杆并未作为 prim 存在。

参考观测项不读取 IMU prim，因此在 H2 路径上这不会造成任何影响。如果您的自定义观测项或部署接口通过名称引用这些坐标系，请禁用合并功能从 URDF 重新导入，而不是尝试从该资产中恢复它们。

注意

头部关节（head_pitch_joint 和 head_yaw_joint）在资产中带有驱动器，但未出现在 Unitree 发布的执行器组中。请明确决定策略是控制它们、保持它们静止，还是将其留给随机动作，并将该决定记录到 Stage 2 中。

从 URDF 导入自定义人形机器人#

按照 导入 URDF 中的说明操作，并将结果保存为 USD 资产。有三个导入器设置决定了该资产是否可用于运动训练。

  1. 将 Base Type 设置为 Mobile。默认值为 Source，该值会遵循源 URDF 的定义；由于 H2 仅在注释掉的代码块中声明其浮动基座，因此使用默认设置导入 H2 会在根 prim 和骨盆之间创建一个 /H2/Physics/root_joint 固定关节，这会导致生成一个无法平移的关节结构。针对固定在世界中的根节点训练的运动策略，学习到的将是一个并不存在的模型。将设置改为 Mobile 会移除该关节，仅保留 URDF 自身声明的固定关节。

  2. 如果您的机器人手臂能够触及躯干或腿部，请启用 Allow Self-Collision。如果不启用，训练过程中可能会发现肢体穿过身体的姿态。

  3. 将 Robot Type 设置为 Humanoid，以便导入器为该资产打上机器人模式标签，供机器人工具读取。

注意

固定关节合并是区分两个起始点的关键，通过 GUI 操作时您无需进行任何额外设置即可正确完成。导入对话框未公开该选项，且导入器默认不执行合并操作，因此通过 GUI 导入会保留 URDF 中声明的传感器和惯性系。对于 H2 而言，这意味着全新导入会将 imu_in_pelvis 和 imu_in_torso 保留为普通的 Xform 帧，并将 left_hand_link 和 right_hand_link 保留为刚体，而随附的资源是在启用合并的情况下构建的，其中不包含这些帧。参考 H2 观测项不读取 IMU prim，因此仅当您的自定义观测项或部署接口通过名称引用这些帧时，才需保留它们。如果您通过脚本执行导入，请在验证期间将 merge_fixed_joints 保持为其默认值 False。

导入器写入 USD Asset Structure 3.0：一个覆盖 payloads/base.usda 的薄根层用于几何体，以及一个覆盖物理负载的 Physics 变体集。将增益和限位写入物理负载，以便来自 CAD 或 URDF 源的几何体更新不会丢弃您的调优参数。

检查关节结构#

在调整驱动参数之前，先检查导入的或库中的资产。以下每一项都能发现一类在训练开始后难以诊断的故障。

  1. 通过 Eye > Show by Type > Physics > Colliders > All 启用碰撞体可视化，并确认每个接触表面都有几何体。刚体碰撞体显示为绿色，静态碰撞体显示为品红色。因此，如果你预期是动态的机器人上出现品红色，说明物理引擎尚未解析，你查看的是错误的内容。

  2. 通过 Eye > Show by Type > Physics > Joints 启用关节可视化，并确认每个轴指向预期方向。轴反向会导致训练出的策略以错误方向驱动关节，且该症状仅在部署时显现。

  3. 打开 Window > Robot Inspector，并确认每个运动连杆都具有合理的质量、质心和惯性。肢体上的零值或默认惯性是常见的 URDF 导出缺陷。当负载将 prim 分散到多个层时，Tree 层级模式比舞台视图更易于扫描。

  4. 确认资产在源数据中使用米、千克、秒、弧度和牛顿作为单位。

  5. 确认关节轴、位置限制、速度限制和力矩限制与机器人匹配。

  6. 确认在根连杆上存在且仅存在一个 articulation root。在 H2 上，该位置为 /H2/Geometry/pelvis。在进行运动训练时，不要使用固定关节将人形机器人连接到世界。

  7. 确认关节和连杆名称稳定且唯一。你在 AGILE 机器人和任务配置中引用这些名称，后续重命名会使已训练的策略失效。

不要将“具有碰撞体”理解为“具有正确的碰撞体”。导入的 H2 在 34 个刚体链接中的 23 个上设置了碰撞，而随附资源在 32 个中的 21 个上设置了碰撞；导入资源中多出的两个链接是 left_hand_link 和 right_hand_link，合并操作会移除它们。这听起来很完整，直到你查看这些形状是什么。大多数链接携带其视觉网格的凸包，但 URDF 还为每条腿附带了两个粗糙的原始几何体替身：

提示

如果你更希望捕捉机器人自然稳定的姿态，而不是手动输入，请在关节根节点上添加一个临时固定关节以锚定机器人，在 Edit > Preferences > Physics 中取消勾选 Reset Simulation on Stop，播放仿真直到姿态看起来正确，然后停止。稳定后的状态会保留在关节上，因此请保存图层，删除固定关节，并重新启用 Reset Simulation on Stop。运行两次以确认该姿态在重置后依然保持。

编写执行器增益#

这两个起始点都无法提供可用的增益。新导入的资产会写入 0 刚度和 0 阻尼，导致关节在点击 Play 时坍塌。随附的资产为 16 kg 的腿部链和腕部统一写入了 1000 和 10，这会使机器人像雕像一样保持任何给定姿态，并让策略学习到一个并不存在的执行器模型。两者都需要替换为按组设置的值。

在测试任何内容之前先锚定机器人#

请先执行此操作。以下每个增益测试都会播放时间轴，且机器人采用浮动基座，因此未锚定的仿人机器人在整个测试期间都会下落，你读取到的每个数值描述的都是自由落体中的机器人，而非跟踪目标的机器人。

  1. 在世界与articulation root（/H2/Geometry/pelvis）之间添加一个临时固定关节。 应锚定根节点本身，而不是躯干或腰部：如果锚定位置较高，则锚点与腿部之间的腰部关节仍处于自由状态，导致腿部关节是在一个仍在移动的基座上进行测试，且腰部关节会承受自由飞行状态下本不应承受的负载。

  2. 如果场景中存在地面平面，请在测试期间将其移除或停用。地面接触会在 Snap to Limits 中报告为 BLOCKED，这会掩盖真实结果。裸 H2.usda 没有地面平面，因此可能无需移除任何内容。

警告

在保存用于训练的资产之前，请删除临时固定关节。如果世界固定的根节点延续到 Stage 2，将导致机器人在原地站立训练，看起来似乎什么也没学到。

理解增益的作用#

PhysX 位置驱动是一个弹簧-阻尼器。它施加的力为

\[F = K_p \, (\theta_{target} - \theta) + K_d \, (\dot{\theta}_{target} - \dot{\theta})\]

其中 \(K_p\) 为刚度，\(K_d\) 为阻尼。它们的比值决定了关节如何响应新的目标位置：

状态

行为

原因

欠阻尼

在稳定之前出现超调和振荡。

刚度相对于阻尼较高。

临界阻尼

快速到达目标位置且无超调。

刚度与阻尼平衡。

过阻尼

缓慢接近目标位置且无超调。

阻尼相对于刚度较高。

力求实现接近临界阻尼的状态。如果出现振荡或超调，请提高阻尼或降低刚度；如果关节缓慢趋向目标位置，请提高刚度或降低阻尼。

为您的机器人寻找稳定的增益#

打开 Tools > Robotics > Asset Editors > Gain Tuner，并在 Robot 下拉菜单中选择机器人。如果面板显示的是 ADD ROBOT SCHEMA 按钮而不是关节表，则该资产没有 Robot Schema；请先应用该 Schema，因为该工具读取的是 Schema 中的关节列表。在 Gain Settings 选项卡上一次处理一个关节组，从最重的链开始，因为稳定的腿部不会被手腕破坏稳定性，但反之则不然。对于每个组，应用来自 Tuning Workflow 的位置驱动启发式方法：

  1. 将阻尼设为 0，并提高刚度，直到关节收敛到目标位置附近。在没有微分项的情况下，您可以单独观察刚度的响应。

  2. 将刚度降低一个数量级。

  3. 添加阻尼，其值比刚度低一个数量级。此基线设置不应产生超调。如果您希望获得更快的响应，请进一步降低阻尼。

  4. 围绕该基线微调刚度和阻尼，以优化稳定性、响应时间和超调量。

在 Test Gains 选项卡上评估每次迭代，将 Test Mode 设置为 Step Function，该模式会驱动突然的位置变化，是最接近策略在训练期间发出目标值的方式的模拟。为组中的关节启用 Test，将它们设置为相同的 Sequence 以便同时运行，然后单击 Run Test，如果仿真尚未播放，这将启动时间轴。在 Charts 中读取结果。

提示

如果你完全没有参考值，请将 Controller Gains 表单切换为 Natural Frequency / Damping Ratio。然后，你指定一个以 Hz 为单位的目标固有频率和一个无量纲阻尼比，其中 \(\zeta = 1.0\) 表示临界阻尼，Gain Tuner 会使用关节的有效惯性将它们转换为刚度和阻尼。 这通常比绝对刚度更容易理解，因为频率和阻尼比在髋关节和腕关节上的含义是相同的。转换需要惯性，因此 请先播放时间轴，并注意它使用的是初始配置。

如果存在公开值，请从这些值开始#

制造商提供的增益编码了真实的执行器特性，而不是猜测，因此请将它们作为起点并进行验证，而不是从零开始调参。具有相似尺寸、关节数量和执行器类别的机器人也可以提供初始值，但请将这些值视为初步猜测，并运行相同的测试。

\[S_{deg} = S_{rad} \times \frac{\pi}{180} \qquad D_{deg} = D_{rad} \times \frac{\pi}{180}\]

验证驱动器#

一旦某组关节的跟踪效果可接受，请使用其余测试模式来发现制作错误，而不是寻找更好的增益。弧度与度数之间相差 57.3 倍的单位转换错误、缺失的最大力限制或反转的关节体，都会在此处表现为几乎所有关节同时失败。

出于同样的原因，在这些测试中保留锚点和从 在测试任何内容之前固定机器人 中移除的地面平面。

  1. 在所有驱动关节上运行 Snap to Limits。该测试命令每个关节运动至其下限，保持一段时间，然后命令其运动至上限，从而验证增益、限位和碰撞几何体是否一致。

  2. 最后运行 Stress。该测试使用极端的随机命令驱动关节，并暴露出激进强化学习探索可能产生的求解器不稳定性。

  3. 删除临时固定关节，并恢复之前移除的地面平面（如果有）。

结果

为了区分接触阻挡与扭矩不足的问题，请在勾选 Disable Self-Collisions During Test 的情况下重新运行测试。在 H2 上，两次运行的结果仅在一个关节上存在差异，这表明限制因素是扭矩而非接触。Disable Velocity Limits During Test 以相同的方式隔离速度上限。真正需要引起注意的是某个关节失败而其镜像关节通过，或者机器人的一侧整体失败。

提示

如果关节在接近其极限时变得不稳定，而不是简单地无法达到极限，请在 Stage 面板中选择 PhysicsScene，并在更改任何增益之前将 Time Steps Per Second 提高到 120。

验证物理模型#

上述章节分别介绍了静态属性和驱动器。在配置训练任务之前，请确认整个机器人的动态行为：

  1. 恢复地面平面，将机器人放置在其上方，按下 Play，并确认机器人能够下落并稳定，而不会发生爆炸、穿透地面或产生持续的接触抖动。

  2. 在 Tools > Robotics > Joint Inspector 中，让每个关节在保守范围内运动，并确认其方向、限位和报告状态是否正确。

  3. 确认机器人是浮动基座，且没有残留的世界固定关节，并且根链接上恰好存在一个关节树根。

  4. 在运行时读取位置、速度和力矩限制，而不是信任编辑时设置的属性。在 H2 上，驱动性能包络报告的速度为无限大，而关节解析出的限制为有限值，因此编辑时设置的值与实际生效的值不一致。

  5. 确认驱动的刚度和阻尼是您为每个组单独设置的值，而不是在所有关节上重复使用的统一值。

完成检查清单#

  • USD 包含一个经过验证的浮动基座关节体。

  • 质量、惯性、碰撞、关节轴和关节限位值在物理上是可信的。

  • 任务所依赖的接触表面具有代表它们的碰撞几何体，而不是占位图元。

  • 机器人下落并稳定，没有不稳定的接触。

  • 每个关节都按预期方向运动并遵守其限位。

  • 关节和连杆名称稳定且唯一。

  • 站立姿态已作为关节状态编写，而不仅仅是驱动目标。

  • 驱动刚度、阻尼和最大力是按关节组编写的，而不是统一设置的。

  • 用于增益测试的临时固定关节已删除。

  • Stage 2 输入列表记录了资产、姿态、执行器、关节、连杆和传感器值。

阶段 3：配置并验证运动 MDP#

阶段 2 的任务注册告知 AGILE 需要加载哪些类。本阶段将加载的环境转化为针对您机器人的连贯速度跟踪学习问题。即使您预期保留其默认值，也请逐一检查每个 H2 *Cfg 类：如果某个项解析了错误的刚体、关节、传感器或时序，即使没有明显的配置错误，训练也可能出现问题。

本教程解释 H2 配置如何应用 AGILE 基于管理器的设计。有关框架级的整体模式，请参阅 任务配置如何组合 MDP 组件；有关完整目录，请参阅 MDP 组件。以下章节仅关注 h2/velocity_history_env_cfg.py 中存在的项。

理解速度跟踪问题#

马尔可夫决策过程（MDP）描述了一个序贯决策问题。在每个控制步骤中，策略接收观测值并产生动作。模拟器推进机器人状态，环境测量结果，而奖励则指示该状态转换对任务有多大用处。

                      command: desired vx, vy, yaw rate
                                   |
                                   v
observation history -------> [ policy ] -------> joint-position action
       ^                                             |
       |                                             v
       |                                      [ robot + terrain ]
       |                                             |
       +---- next state, reward, termination <-------+

对于 H2，任务采样期望的平面速度，actor 观测可部署机器人的状态和五帧历史，动作控制 14 个腿部关节和腰部关节。奖励用于塑造速度跟踪、平衡、安全性和运动质量。终止条件限制失败的回合，事件改变模拟体验，课程随着学习的进展改变难度。

模拟器的完整状态大于 actor 的观测。H2 使用非对称 actor-critic 训练：actor 接收部署时可复现的信号，而 critic 接收特权模拟器状态以在训练期间估计价值。只有 actor 成为部署的策略。

在此阶段全程使用以下建议标签：

  • 必须更改： 该值名称或模型特定于 H2 的解剖结构或动力学。

  • 需检查： H2 的值是一个有用的起点，但你必须确认其尺度、范围和意图。

  • 可能保持不变： 除非你的平台或任务给出了更改它的具体理由，否则在首次验证运行中保持该值不变。

注意

此阶段的代码摘录已简化。... 代表实际配置中存在但此处省略的参数，以保持相关字段可见，因此请将每个摘录视为阅读指南，而非可直接复制的文件。请根据各部分中指定的 AGILE 源文件进行操作。

MySceneCfg: 场景和传感器#

建议操作：必须更改

替换机器人配置和所有相对于机器人的 prim 路径。检查地形和接触模型。

场景是 MDP 运行的物理世界。它本身不是观测值；它提供机器人、地形和传感器，供观测、奖励、终止和事件项查询。有关 AGILE 的地形选择，请参阅 MDP 组件：地形。

@configclass
class MySceneCfg(InteractiveSceneCfg):
    terrain = TerrainImporterCfg(
        ...,
        terrain_type="generator",
        terrain_generator=MEDIUM_ROUGH_TERRAIN_CFG,
        max_init_terrain_level=1,
    )
    robot = unitree_h2.H2_DELAYED_DC_MOTOR.replace(prim_path="{ENV_REGEX_NS}/Robot")
    contact_forces = ContactSensorCfg(prim_path="{ENV_REGEX_NS}/Robot/.*", history_length=3, track_air_time=True)
    sky_light = AssetBaseCfg(...)
    height_measurement_sensor = RayCasterCfg(...)
    height_measurement_sensor_left_foot = RayCasterCfg(...)
    height_measurement_sensor_right_foot = RayCasterCfg(...)

CommandsCfg：期望行为#

推荐操作：检查

从机器人可以跟踪的保守速度开始，然后在建立稳定基线后扩大范围。

Commands 在不改变任务结构的情况下对任务进行参数化。H2 策略被要求跟踪采样的前向、横向和偏航速度。请参阅 MDP Components: Commands 及其 Velocity Commands 部分。

@configclass
class CommandsCfg:
    base_velocity = mdp.UniformNullVelocityCommandCfg(
        asset_name="robot",
        resampling_time_range=(8.0, 12.0),
        rel_standing_envs=0.25,
        rel_heading_envs=1.0,
        heading_command=False,
        debug_vis=True,
        ranges=mdp.UniformNullVelocityCommandCfg.Ranges(
            lin_vel_x=(-0.5, 0.5),
            lin_vel_y=(-0.5, 0.5),
            ang_vel_z=(-1.0, 1.0),
        ),
    )

resampling_time_range 使每个目标保持激活状态 8 到 12 秒，而 rel_standing_envs=0.25 保留四分之一的仿真环境用于学习零指令平衡。在验证期间保持 debug_vis=True 开启，以便目标箭头保持可见。

重要

ranges 块定义了任务的训练范围。H2 从 -0.5 到 0.5 m/s 采样前向和横向速度，从 -1.0 到 1.0 rad/s 采样偏航速度。正负边界使策略能够练习两个方向。这些是期望速度，而非执行器限制，且训练后的策略预计不会在这些范围之外可靠地泛化。对于自定义机器人，请从保守的范围开始，仅在它跟踪初始指令而不跌倒后，再扩大这三个范围。

ActionsCfg：策略控制接口#

建议操作：必须更改

替换受控关节集，验证其解析顺序，并选择安全的位置动作比例。

Actions 将策略输出转换为模拟机器人的指令。参见 MDP Components: Actions、 Joint Position Actions 和 Random Actions。

CONTROLLED_JOINT_NAMES = unitree_h2.LEG_JOINT_NAMES + ["waist_roll_joint", "waist_pitch_joint"]


@configclass
class ActionsCfg:
    joint_pos = mdp.JointPositionActionCfg(
        ...,
        joint_names=CONTROLLED_JOINT_NAMES,
        scale=0.5,
        use_default_offset=True,
    )
    random_pos = mdp.RandomActionCfg(
        ...,
        joint_names_exclude=unitree_h2.LEG_JOINT_NAMES + unitree_h2.WAIST_JOINT_NAMES,
    )

H2 成员

建议

功能说明

CONTROLLED_JOINT_NAMES

必须修改

定义动作宽度和关节顺序。H2 使用 12 个腿部关节以及腰部 roll 和 pitch 关节。

joint_pos

必须修改

将策略输出解释为相对于默认姿态的偏移量。在训练前验证关节解析度、scale、偏移量和 裁剪设置。

random_pos

检查

使用梯形轮廓移动非运动策略控制的关节。对于 H2，这会改变上半身姿态而不消耗策略输出；如果这些关节必须保持固定或由策略控制，请移除或重新定向该动作。

训练模型的输出宽度等于解析后的 joint_pos 动作宽度。在观测构建、对称性增强、导出和部署过程中保持此顺序不变。

ObservationsCfg: Actor 和 Critic 输入#

推荐操作：检查

保留可部署的 Actor 信号，替换受控关节集，并有意选择历史长度。

观测值是决策时可用的信息。参见 MDP 组件：观测值、 观测组 和 历史堆叠。

@configclass
class ObservationsCfg:
    @configclass
    class HistoryPolicyCfg(ObsGroup):
        base_ang_vel = ObsTerm(...)
        projected_gravity = ObsTerm(...)
        velocity_commands = ObsTerm(func=mdp.generated_commands, params={"command_name": "base_velocity"})
        controlled_joint_pos = ObsTerm(
            func=mdp.joint_pos_rel,
            params={"asset_cfg": SceneEntityCfg("robot", joint_names=CONTROLLED_JOINT_NAMES)},
        )
        controlled_joint_vel = ObsTerm(...)
        actions = ObsTerm(...)

        def __post_init__(self):
            self.history_length = 5
            self.enable_corruption = True
            ...

    @configclass
    class PrivilegedVelocityCriticCfg(ObsGroup): ...

CurriculumCfg: 在学习过程中改变难度#

建议操作：可能保持原样

保留初始的进阶结构，但验证其距离、成功次数、时间表和奖励名称。

课程学习（Curriculum）会随着策略的改进而改变分布或目标。请参阅 MDP 组件：课程学习 和 地形课程学习。

@configclass
class CurriculumCfg:
    terrain_levels = CurrTerm(...)
    increase_action_rate_regularization = CurrTerm(...)
    increase_action_rate_rate_regularization = CurrTerm(...)

terrain_levels 使用 4.0 m 和 2.0 m 的移动阈值，要求四次成功以进阶， 十次失败以回退。increase_action_rate_regularization 从第 50,000 步开始，并在 100,000 步内将其目标 权重提升至 -1.0。第二个平滑度课程学习从第 60,000 步开始，并在相同持续时间内将 action_rate_rate 提升至 -0.5。请确认两个奖励名称与 RewardsCfg 完全匹配。对于平坦地形的结构基线，请禁用地形课程学习。

H2LowerVelocityHistoryEnvCfg：组合并配置环境的时间参数#

建议操作：必须更改

重命名该类，并验证控制频率、物理频率、回合持续时间、传感器周期以及 评估行为。

顶层类组装了所有管理器配置，并固定了策略与仿真器之间的时间关系。这是 任务配置如何组合 MDP 组件 在 H2 中的具体应用。

@configclass
class H2LowerVelocityHistoryEnvCfg(ManagerBasedRLEnvCfg):
    scene: MySceneCfg = MySceneCfg(num_envs=4096, env_spacing=2.5)
    observations: ObservationsCfg = ObservationsCfg()
    actions: ActionsCfg = ActionsCfg()
    commands: CommandsCfg = CommandsCfg()
    viewer: ViewerCfg = ViewerCfg()
    rewards: RewardsCfg = RewardsCfg()
    terminations: TerminationsCfg = TerminationsCfg()
    events: LocomotionEventCfg = LocomotionEventCfg()
    curriculum: CurriculumCfg = CurriculumCfg()

    def __post_init__(self):
        self.controller_freq = 50.0
        self.physics_freq = 200.0
        self.episode_length_s = 30.0
        self.max_episode_length_offset_s = 0.0
        self.decimation = int(self.physics_freq / self.controller_freq)
        self.sim.dt = 1.0 / self.physics_freq
        self.sim.render_interval = self.decimation
        self.sim.physics_material = self.scene.terrain.physics_material
        ...
        self.scene.contact_forces.update_period = self.sim.dt
        self.scene.height_measurement_sensor.update_period = self.sim.dt
        self.scene.height_measurement_sensor_left_foot.update_period = self.sim.dt
        self.scene.height_measurement_sensor_right_foot.update_period = self.sim.dt
        self.only_positive_rewards = False
        ...

    def eval(self):
        self.observations.eval = mdp.EvaluationObservationsCfg()
        self.rewards = None
        self.curriculum = None

在 50 Hz 控制频率和 200 Hz 物理频率下，一个策略动作跨越四个物理步。执行器延迟以物理步为单位指定，因此更改任一频率都会改变以秒为单位的延迟表示。传感器更新周期必须与其 MDP 项所消耗的量保持同步。

当 AGILE 切换到评估模式时，eval() 会禁用仅用于训练的奖励和课程，并添加一个用于评估指标的独立观测组。它不会替换策略所消耗的观测值。请保持 Actor 观测字段、历史长度、动作数量和顺序与训练时完全一致，以确保训练出的策略和导出的策略仍能匹配其输入和输出。

验证环境#

在训练之前，使用生成的测试动作运行环境。这不需要训练好的策略：

uv run scripts/play.py --task Velocity-H2-History-v0 --num_envs 2 --viz kit

对于自定义人形机器人，请将 Velocity-H2-History-v0 替换为在阶段 2 中注册的任务 ID。检查重置、关节方向、动作缩放、接触、观测形状和终止条件。在调整奖励之前，先修复环境错误。

play 脚本加载环境时不使用 RL 策略，移除仅用于训练的成分，并向受控关节发送平滑的正弦动作。关节使用错开的相位偏移和一系列频率。这是对关节映射、动作缩放、仿真稳定性和重置的冒烟测试；它不是对已学习运动能力的测试。

绿色箭头显示采样的目标线速度，蓝色箭头显示机器人的实测线速度。箭头方向指示行进方向，箭头长度指示速度。由于没有训练好的策略在跟踪指令，因此在此测试期间箭头预计不会对齐。

完成检查清单#

  • 已针对自定义机器人审查了每个 H2 *Cfg 类。

  • 每个关节、刚体、传感器、命令、动作和奖励名称引用均按预期解析。

  • Actor 观测值可部署、有序且宽度固定；特权信号仅供 Critic 使用。

  • 所有 23 个奖励项都有明确的保留、调整或禁用理由。

  • 终止条件会产生可信的原因，且不会终止有效的初始状态。

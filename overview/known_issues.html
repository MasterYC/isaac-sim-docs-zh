已知问题#

常规更新#

  1. 在某些 Windows 系统上，您可能会遇到如下错误：

    OSError: [WinError 126] The specified module could not be found. Error loading "C:\path\to\omni.isaac.ml_archive\pip_prebundle\torch\lib\fbgemm.dll" or one of its dependencies.

    此问题是由缺少构建工具引起的。要解决此问题，请安装 Visual Studio 2022，然后通过 Visual Studio 界面安装 MSVC v143 - VS 2022 c++ x64/86 build tools。

  2. 当在 world 使用的 stage 上调用 Scatter3D OmniGraph 节点时，该 replicator 节点会破坏物理效果。

  3. 如果使用 Ctrl-C 退出独立 Python 脚本，可能需要执行两次才能退出。

  4. 如果 URDF 中的多个资产包含相同的材质名称，则只会创建一个材质，即使材质参数不同也是如此。例如，如果两个网格具有名为 “material” 的材质，一个为蓝色，另一个为红色，则这两个网格将全部变为红色或全部变为蓝色。这也适用于带纹理的材质。

  5. 在 OmniGraph 中使用 isaacsim.core.api 中的 World 或 SimulationContext 时，请确保在初始化 World 或 SimulationContext 之前创建图。

  6. 使用 replicator 的 rep.new_layer() 功能（该功能会创建一个新图层，用于放置和随机化资产）可能会导致在这些资产被使用的模拟场景中出现问题。在这种情况下，可以省略 rep.new_layer() 的使用。

  7. 在 OmniGraph 节点中拖放具有默认值的资产后，应将其与场景一起保存，并在点击 Play 之前重新加载，以确保所有值均已正确设置。

  8. 如果运行 FPS 低于 25 FPS，带有 ROS 同步功能的 Cortex 示例可能会出现异常行为，并且无法执行任务。

  9. 如果用于合成数据生成的随机化材质未能及时加载，则必须将 rt_subframes 设置为至少 2。

  10. Multiple Robot ROS 2 Navigation 教程具有较高的 CPU 使用率。如果您观察到机器人实例发生碰撞或出现定位问题，这很可能是因为 Nav2 堆栈无法与传感器数据正确同步，从而导致控制器命令丢失。

  11. 在运行 Isaac Sim 时，可能会出现许多警告和其他消息。可以使用以下命令行参数来减少日志输出量：

    --/log/level=error --/log/fileLogLevel=error --/log/outputStreamLevel=error

  12. 在 Windows 上使用 Replicator 通过内置后端写入 S3 存储桶时，可能需要通过环境变量而不是 AWS 配置文件来设置凭据。这是因为 boto3 在 Windows 上可能存在路径解析错误。

  13. 在 Windows 上运行独立示例时，在某些场景下，应用程序关闭时线程可能无法被正确清理。这通常可以忽略，因为应用程序仍会成功关闭。作为变通方法，可以在调用 standalone_app.close() 之前添加多个 standalone_app.update() 调用。

    Windows fatal exception: access violation

Thread 0x00000634 (most recent call first):

  14. ROS 2 QoS Profile OmniGraph 节点无法保存自定义配置文件，除非您先手动将 createProfile 输入更改为“Custom”，然后再更新其他字段。

  15. 在 ROS 2 关节名称覆盖解析不支持 IsaacJointAPI isaac:NameOverride 的构建版本中，自定义关节名称可能不会出现在 /joint_states 上，或者可能无法通过 Isaac Joint Name Resolver 节点解析。请使用已编写的 USD 关节 prim 名称进行控制，或者仅作为临时的旧版兼容性变通方法，在受影响的关节 prim 上编写 isaac:nameOverride。新的关节资产应继续使用 IsaacJointAPI isaac:NameOverride。请将小写的 isaac:nameOverride 保留用于非关节 prim 和旧版兼容性。请参阅 NameOverride Attribute。

  16. USD 到 URDF 导出器：

    • 碰撞体网格可能被错误地包含在视觉元素中。可以从 URDF 文件中手动移除它们。

    • Body 和 Joints 在 URDF 文件中按字母顺序编写。可以在 URDF 文件中手动重新排序。

    • 根据机器人结构，由于不同帧的合并，某些 body 名称可能会被覆盖。请检查输出并验证其准确性。

    • 当无界时，URDF 导出器会将关节的 effort 和 velocity 限制添加为 inf。如果 URDF 解析器不支持 Float 中的 inf 值，这可能导致 URDF 无法正确导入。

  17. Isaac Sim 资产路径不能直接用于 Omniverse Kit 文件选择器对话框。作为变通方法，当在 Omniverse Kit 文件选择器中使用 S3 资产路径时，请复制并粘贴该路径，然后按 enter 而不是点击 Select。

  18. 对于具有显著变化的场景（例如移动物体或变化的光照条件），Replicator 合成数据生成可能需要渲染更多的子帧。有关更多信息，请参阅 RT Subframes Parameter 和 subframes examples。

  19. Franka Open Drawer 示例在 Blackwell GPU 上默认无法打开抽屉，将 self._physics_rate 增加到 600 即可正常工作。该问题目前正在调查中。

  20. 在独立模式下运行时，Replicator CosmosWriter 可能会跳过从录制帧生成视频。在这种情况下，请在分离写入器之前运行几次应用更新，以确保视频能够生成。

  21. 在使用 Replicator 进行合成数据生成 (SDG) 工作流时，建议将 DLSS 模型设置为 Quality 模式以避免渲染伪影。在较低分辨率下（尤其是低于 600x600 时），默认的 Performance 模式可能会导致生成的图像中出现透明或渲染错误的边缘等问题。

    import carb.settings

# Set DLSS to Quality mode (2) for best SDG results (Options: 0 (Performance), 1 (Balanced), 2 (Quality), 3 (Auto)
carb.settings.get_settings().set("/rtx/post/dlss/execMode", 2)

  22. 从 Isaac Sim 5.0 开始，完整的 Isaac Sim 体验（isaacsim.exp.full.kit）默认启用 Fixed Time Stepping，以便 SimulationApp 工作流能够确定性地步进时间轴。作为副作用，包含关键帧动画且渲染速率低于目标速率（通常为 60 Hz）的 USD 场景在 GUI 中会显得缓慢或卡顿，因为时间轴在每个循环刻度上按固定的 dt 推进，而不是按实际时间推进。在 USD Composer 和 Isaac Sim 4.5 中，这些场景可以平滑播放，因为它们使用 Variable stepping。若要在动画审查/编辑时让 GUI 使用 Variable stepping，请使用以下三个标志启动（第三个标志可防止 isaacsim.core.throttling 扩展在每次 Play 时重新启用手动模式）；有关完整讨论，请参阅 Choppy or Slow Animation Playback (Fixed Time Stepping)。

    ./isaac-sim.sh \
    --/app/player/useFixedTimeStepping=false \
    --/app/runLoops/main/manualModeEnabled=false \
    --/exts/isaacsim.core.throttling/enable_manualmode=false

  23. DL 降噪器（DLSS 光线重建）可能会在简单场景中的材质上留下白噪声斑点，例如在物体重建资产 SDG 示例中的紫色地板上。禁用 /rtx/dldenoiser/responsiveDenoising 以切换到另一个时间稳定性更好的 RR 模型；降噪器保持启用状态。禁用它可能会引入重影；对于随机化材质的 SDG，请等待额外的子帧或重置 DLSS 历史记录。请参阅使用 DL 降噪器时材质上的白噪声。

    import carb.settings

carb.settings.get_settings().set("/rtx/dldenoiser/responsiveDenoising", False)

  24. 在 Isaac Sim 6.0 和 6.1 中，RTX Lidar 的 echoId 字段始终为 0，即使对于每个发射光线报告多个回波的多回波 Lidar 配置文件也是如此。这会影响 GenericModelOutput 缓冲区以及所有转发该字段的消费者，包括 RTX 传感器标注器和 ROS 2 点云发布者。其他每个回波的字段（如 range 和 intensity）不受影响。目前没有变通方法；计划在后续版本中修复此问题。请参阅已知问题：RTX Lidar 的 echoId 始终为零。

  25. 在渲染开始后重命名或重新设置渲染产品（render product）或其祖先 prim 的父级，可能会导致以下错误：

    ValueError: Invalid object in Py_Graph in getWrappedGraphFromNode

    为避免此错误，请在渲染开始前完成 prim 层级的最终确定。在渲染产品或其祖先 prim 开始渲染后，请勿重命名或重新设置其父级。

警告#

  1. 可以忽略类似于以下的警告：

    • [Warning] [omni.usd] Warning (secondary thread)

    • [Warning] [carb.tasking.plugin] Counter 0x7f25e002f8d0

    • [Warning] [rtx.neuraylib.plugin] [MDLC:COMPILER]   1.0   MDLC   comp warn

    • [Warning] [rtx.mdltranslator.plugin] Unable to resolve

    • [Warning] [omni.tagging.plugin] Failed to discover tagging service

    • [Warning] [omni.isaac.dynamic_control.plugin] DcFindArticulationDof: Function called while not simulating

    • [Warning] [omni.isaac.dynamic_control.plugin] DcSetDofProperties: Function called while not simulating

    • [Warning] [omni.client.plugin]  Tick: authentication: Could not connect to discovery service at "wss://...

  2. 如果模拟的深度图像中存在不需要的噪声，请在 Render Settings > Ray Tracing > Anti-Aliasing 选项卡下禁用抗锯齿，方法是将 Algorithm 设置为 None。

  3. 某些扩展使用 Pyperclip 来复制文本，如果您看到以下消息，请参考链接以安装受支持的复制/粘贴机制：

    Pyperclip could not find a copy/paste mechanism for your system.
For more information, see https://pyperclip.readthedocs.io/en/latest/index.html#not-implemented-error

挂起#

  1. 在 Windows 上，使用扩展管理器时，单击依赖项窗口会导致视口变黑并挂起。

  2. 在 Firefox 上，单击 Play 按钮后，WebRTC 客户端可能会在几秒后看似挂起。建议使用 Google Chrome 或 Chromium 浏览器。

崩溃#

  1. 在 OmniGraph 中使用复合节点可能会导致崩溃，我们不建议在 OmniGraph 中使用复合节点。

  2. 在多 GPU 系统上，构建 MobilityGen 场景然后关闭舞台（File > New / Open / Exit）可能会导致在拆卸期间发生致命崩溃。作为变通方法，请将 CUDA 工作和渲染固定到驱动显示器的 GPU。将 CUDA_VISIBLE_DEVICES 设置为其物理 GPU 索引，然后选择 CUDA 设备索引 0 进行渲染：

    CUDA_VISIBLE_DEVICES=<physical_render_gpu_index> ./isaac-sim.sh --/renderer/multiGpu/activeCudaGpus=0,

    对于独立的 SimulationApp 工作流，请在启动配置中传递 "active_cuda_gpus": [0]。 有关物理 GPU 和 CUDA GPU 索引的详细信息，请参阅 Multi-GPU。

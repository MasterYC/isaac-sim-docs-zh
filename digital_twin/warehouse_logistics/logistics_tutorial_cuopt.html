NVIDIA cuOpt#

Tool Reference

学习目标#

演示并提供使用 NVIDIA cuOpt 在仿真中解决路径优化问题的参考指南。

主题包括：

  • 创建航点网络

  • 与 cuOpt 服务的基本交互

  • 优化特定数据的可视化与处理

  • 仓库内运输用例演示

15-20 分钟教程

入门指南#

先决条件

  • 访问 NVIDIA cuOpt 服务器，并按照 cuOpt 快速入门指南 设置 cuOpt 服务器。

  • 查阅核心 API Hello World 以及入门教程系列 机器人设置教程系列。

  • NVIDIA cuOpt 示例扩展默认处于禁用状态。请从Extension Manager中启用本教程所需的扩展， 方法是搜索 omni.cuopt.examples。启用 omni.cuopt.examples 将自动启用 omni.cuopt.service 和 omni.cuopt.visualization

NVIDIA cuOpt 示例#

本教程基于 omni.cuopt.examples 扩展中的三个示例。 这些示例按保真度递增排列，从仅包含基本可视化的简单随机路由问题，到包含高保真仓库资产的仓库内运输场景。每个示例都利用支持扩展来与 cuOpt 服务交互并可视化优化数据。所有示例和支持扩展的代码均可用，并可扩展用于其他应用程序。

示例概述#

  • Create Network：一个演示如何使用可视化工具创建网络的示例。该网络可以保存并重复使用，以表示优化问题的路径点图。使用 omni.cuopt.visualization 扩展中的实用工具来创建和显示路径点图。

  • Simple Cost Matrix：一个使用简单原语来表示基于仓库的车队路径规划问题的最小示例，其中车辆从仓库（Cone）出发，必须满足所有位置（Spheres）的需求。通过测量点之间的欧几里得距离来创建表示位置间行驶成本的 Cost Matrix。omni.cuopt.service 用于场景数据与运行中的 cuOpt 服务实例之间的通信。

  • Simple Waypoint Graph：cuOpt 还支持优化环境的加权路径点图表示，这也是本示例的重点。路径点图是室内环境的常见表示形式，在这些环境中，位置间的成本可能不是预先确定的，且直线距离不足以描述实际路径。在此示例中，路径点图表示交通网络，目标位置（图节点的子集）表示需要访问的位置以及车队的位置。除了使用 omni.cuopt.service 之外，还使用了 omni.cuopt.visualization 扩展中的实用工具来处理并显示路径点图以及优化后的路线。路径点图、订单数据和车辆数据均从与本示例源代码并存的 JSON 文件中加载，并可根据需要进行修改。

  • 仓库内运输演示：在此示例中，生成一个更复杂的路径点图来表示仓库环境的交通网络。您可以创建并放置语义区域，以标记需要避开的高成本通行区域。除了 Simple Waypoint Graph 示例中使用的实用工具外，还使用了 omni.cuopt.visualization 扩展中的附加功能，从与示例源代码并存的 JSON 配置文件生成仓库环境。

支持扩展概述#

  • omni.cuopt.service：此扩展包含 cuOpt 服务的轻量级封装，用于预处理场景数据以及格式化并向 cuOpt 服务发送请求。此扩展还包含用于表示优化数据以及格式化文本结果以便在示例 UI 中显示的实用工具。

  • omni.cuopt.visualization：此扩展包含用于生成场景数据的实用工具，包括路径点图、语义区域和仓库环境。此扩展还包含辅助函数，用于根据与给定语义区域的邻近程度调整图边的权重。

运行 cuOpt 示例#

创建网络#

  1. 从新的 Isaac Sim 会话（CTRL + N）开始，导航至 Isaac Sim 界面中现已出现的 cuOpt 菜单项，并选择 Create Network。

  2. 在 Create Node 部分，点击 CREATE NODE：

    • Create Node：在默认位置创建一个网络节点。将节点移动到所需位置。可以逐个创建多个网络节点。

  3. 在 Create Edge 部分，点击 CREATE EDGE：

    • Create Edge：在两个节点之间创建一条边。选择两个节点并点击创建边。可以在网络中逐个创建节点之间的多条边。

  4. 创建的网络将包含如下所示的节点（Nodes）和边（Edges）：

  5. 将网络文件保存为 USD 格式，以便在后续的优化问题中使用。

  6. 点击 Open Source Code 查看参考实现。

简单成本矩阵#

  1. 从新的 Isaac Sim 会话开始（CTRL + N），导航至 Isaac Sim 界面中现有的 cuOpt 菜单项，并选择 Simple Cost Matrix。

  2. 输入为您分配的 NVIDIA cuOpt 托管服务凭据。

    请参阅 运行 cuOpt 示例。

  3. 在 Optimization Problem Setup（优化问题设置）部分，为以下各项选择值（或使用默认值），然后单击 SETUP PROBLEM：

    • Fleet Size：可用车辆的最大数量。注意 如果可以使用更少的车辆找到解决方案，则返回该解决方案。

    • Vehicle Capacity：每辆车可以访问的站点数量（需求=1）。

    • Number of Locations：必须访问的非仓库位置数量。

    • Solver Time Limit：分配给 cuOpt 求解器以寻找优化解决方案的时间量。注意 为了保持解决方案质量，对于较大的问题应给予更多时间。

  4. 在 Run cuOpt 部分，单击 SOLVE 以返回优化后的路线。UI 中会显示路线的文本表示形式，视口中也会显示结果。

  5. 单击 Open Source Code 以查看参考实现。

简单航点图#

  1. 从新的 Isaac Sim 会话（CTRL + N）开始，导航至 Isaac Sim 界面中现已存在的 cuOpt 菜单项，并选择 Simple Waypoint Graph。

  2. 输入为您分配的 NVIDIA cuOpt 托管服务凭据。

    请参阅 运行 cuOpt 示例。

  3. 在 Optimization Problem Setup 部分，从上到下依次点击 LOAD 按钮（Waypoint Graph、Orders、Vehicles）以设置问题：

    • Load Waypoint Graph 点击 LOAD JSON 可从 /extension_data/waypoint_graph.json 加载示例路径点图，该文件与本示例的源代码位于同一目录。若要加载使用 Create Network 工具创建的 USD 文件中的网络，请将文件拖入 Stage 窗口并点击 LOAD SCENE。/extension_data/Network.usda 中提供了一个示例文件 Network.usda，该文件与本示例的源代码位于同一目录。

    • Load Orders 从 /extension_data/order_data.json 加载示例订单数据，该文件与本示例的源代码位于同一目录。订单位置现在以绿色显示。

    • Load Vehicles 从 /extension_data/vehicle_data.json 加载示例车辆数据，该文件与本示例的源代码位于同一目录。注意 车辆被分配从 Node_0 位置出发，但不会在视口中显示。

  4. 在 Run cuOpt 部分，点击 SOLVE 以返回优化后的路线。UI 中会显示路线的文本表示形式，结果也会在视口中显示。

  5. 点击 Open Source Code 以查看参考实现。

仓库内运输演示#

  1. 从新的 Isaac Sim 会话开始（CTRL + N），导航至 Isaac Sim 界面中现已存在的 cuOpt 菜单项，并选择 Intra-warehouse Transport Demo。

  2. 输入为您分配的 NVIDIA cuOpt 托管服务凭据。

    请参阅 运行 cuOpt 示例。

  3. 在 Optimization Problem Setup 部分，从上到下依次点击 LOAD 按钮（Sample Warehouse、Waypoint Graph、Orders、Vehicles、Semantic Zone）以设置问题：

    • Load Sample Warehouse 加载由 /extension_data/warehouse_building_data.json 定义的示例仓库、由 /extension_data/warehouse_conveyors_data.json 定义的传送带以及由 /extension_data/warehouse_shelves_data.json 定义的货架。 所有 JSON 文件均位于此示例的源代码旁边。

    • Load Waypoint Graph 从 /extension_data/waypoint_graph.json 加载示例路径点图，该文件位于此示例的源代码旁边。

    • Load Orders 从 /extension_data/order_data.json 加载示例订单数据，该文件位于此示例的源代码旁边。 订单位置现在以绿色显示。

    • Load Vehicles 从 /extension_data/vehicle_data.json 加载示例车辆数据，该文件位于此示例的源代码旁边。 注意 车辆被分配从 Node_0 位置出发，但不会在视口中显示。

    • (OPTIONAL) Create Semantic Zone 在 (0,0,0) 位置创建一个用户定义大小的语义区域。如果生成的语义区域覆盖路径点图中的一个或多个边，则该语义区域内的边将被分配极高的通行成本。cuOpt 会尝试在优化解决方案中尽可能避开这些边。注意 每次点击 Generate 按钮都会创建一个新的语义区域。

  4. 在 Run cuOpt 部分，如果已创建或移动了语义区域，请点击 UPDATE 以捕获当前权重。然后 点击 SOLVE 以返回优化后的路径。路径的文本表示形式将显示在 UI 中，结果也会显示在视口中。

  5. 点击 Open Source Code 以查看参考实现。

附加信息#

此处展示的示例仅演示了 cuOpt 功能的一小部分。有关更多功能和高级用法， 请参阅 cuOpt 文档 和 cuOpt-Resources 仓库。

通过 RTSP 进行实时摄像头流式传输#

Tool Reference

NVIDIA Isaac Sim 可以通过实时流传输协议 (RTSP) 发布场景中摄像头的实时视频流。从渲染产品捕获的帧使用 NVIDIA 的硬件视频编码器 (NVENC) 进行编码，并推送到进程内 RTSP 服务器，任何标准客户端（VLC、ffplay、GStreamer、OpenCV）均可连接到该服务器。这是将模拟摄像头输出接入感知堆栈、录制装置、广播管道或已支持 RTSP 的下游分析服务的推荐路径。

流式传输管道包含在 isaacsim.streaming.rtsp 扩展中。在需要 RTSP 流式传输时启用该扩展。它提供两个入口点：用于声明式场景图编辑的 OmniGraph 节点，以及用于完全编程式设置的 Replicator 写入器。

先决条件#

确保您具备以下条件：

  • 支持 NVENC 的 NVIDIA GPU（H.264 编码所需）。

  • 通过导航至 Window > Extensions，在 Extension Manager 窗口中启用 isaacsim.streaming.rtsp 扩展，或使用 --enable isaacsim.streaming.rtsp 启动 NVIDIA Isaac Sim。

流式传输摄像头#

isaacsim.streaming.rtsp.RTSPCameraHelper OmniGraph 节点通过 RTSP 发布摄像头的渲染产品。完整的管道由该节点和两个支持节点组成，它们连接在单个执行链中：

  • OnPlaybackTick — 在播放运行时，每个时间轴帧运行一次图。

  • IsaacCreateRenderProduct — 为目标摄像头创建（或复用）指定分辨率的渲染产品，并在 renderProductPath 上发出其 USD 路径。

  • RTSPCameraHelper — 将流式写入器附加到该渲染产品，并在配置的端口和挂载路径上启动 RTSP 服务器。

在编辑器中构建图#

建议使用 OmniGraph 编辑器来编写管线。 构建图的步骤如下：

  1. 打开 Window > Graph Editors > Action Graph 并点击 New Action Graph。

  2. 添加上述三个节点。要找到它们，请搜索 RTSP、 Isaac Create Render Product 和 On Playback Tick。

  3. 将 OnPlaybackTick.tick 连接到 IsaacCreateRenderProduct.execIn， 然后将 IsaacCreateRenderProduct.execOut 连接到 RTSPCameraHelper.execIn。

  4. 将 IsaacCreateRenderProduct.renderProductPath 连接到 RTSPCameraHelper.renderProductPath，以便辅助节点附加到前一个节点创建的 渲染产品上。

  5. 在 IsaacCreateRenderProduct 节点上，将 cameraPrim 设置为您要流式传输的 摄像头。

  6. 在 RTSPCameraHelper 节点上，设置 port（默认 8554）和 mountPath（默认 /stream）。

  7. 在时间轴中按下 Play。RTSP 服务器会在第一帧渲染后惰性启动，流将在 rtsp://localhost:8554/<mountPath> 处可用。当您按下 Stop 时， 服务器会干净地关闭。

从脚本构建图#

相同的流水线也可以通过编程方式使用 omni.graph.core.Controller 进行构建。这对于无头环境、批处理作业和测试非常有用。以下代码片段针对位于 /Camera 的摄像机构建等效图，并在 rtsp://localhost:8554/stream 处配置流。按 Play 或启动 Replicator 捕获以生成帧并启动 RTSP 服务器。

import omni.graph.core as og
import omni.kit.app
import omni.usd
from pxr import UsdGeom

ext_mgr = omni.kit.app.get_app().get_extension_manager()
ext_mgr.set_extension_enabled_immediate("isaacsim.core.nodes", True)
ext_mgr.set_extension_enabled_immediate("isaacsim.streaming.rtsp", True)

stage = omni.usd.get_context().get_stage()
UsdGeom.Camera.Define(stage, "/Camera")

og.Controller.edit(
    {"graph_path": "/RTSPGraph", "evaluator_name": "execution"},
    {
        og.Controller.Keys.CREATE_NODES: [
            ("OnPlaybackTick", "omni.graph.action.OnPlaybackTick"),
            ("CreateRenderProduct", "isaacsim.core.nodes.IsaacCreateRenderProduct"),
            ("RTSPHelper", "isaacsim.streaming.rtsp.RTSPCameraHelper"),
        ],
        og.Controller.Keys.SET_VALUES: [
            ("CreateRenderProduct.inputs:cameraPrim", "/Camera"),
            ("CreateRenderProduct.inputs:width", 1280),
            ("CreateRenderProduct.inputs:height", 720),
            ("RTSPHelper.inputs:port", 8554),
            ("RTSPHelper.inputs:mountPath", "/stream"),
            ("RTSPHelper.inputs:useRawEncoding", False),
        ],
        og.Controller.Keys.CONNECT: [
            ("OnPlaybackTick.outputs:tick", "CreateRenderProduct.inputs:execIn"),
            ("CreateRenderProduct.outputs:execOut", "RTSPHelper.inputs:execIn"),
            ("CreateRenderProduct.outputs:renderProductPath", "RTSPHelper.inputs:renderProductPath"),
        ],
    },
)

连接客户端#

任何标准 RTSP 客户端（如 VLC、ffplay 或 GStreamer）都可以在 rtsp://<host>:<port><mountPath> 处订阅该流。

从其他计算机连接时，请将 localhost 替换为模拟器主机的 IP 地址，并确保该端口可通过防火墙访问。

流参数#

RTSPCameraHelper 节点公开以下输入：

输入

默认值

描述

renderProductPath

—

要流式传输其 LdrColor 任意输出变量 (AOV) 的渲染产品的路径。将其连接到 IsaacCreateRenderProduct 的 renderProductPath 输出，或将其设置为预先创建的渲染产品 prim。

port

8554

RTSP 服务器监听的 TCP 端口。必须在 1–65535 范围内。每个同时进行的流都需要一个唯一的端口。

mountPath

/stream

附加到服务器 URL 的路径（例如 /front、/cam_1）。必须以 / 开头。

useRawEncoding

false

当 false 时，帧在渲染流水线中预编码为 H.264 (NVENC)，并按帧注入补充增强信息 (SEI) 元数据。当 true 时，流式传输原始 RGBA CUDA 缓冲区，并由 RTSP 服务器对其进行编码。请参阅 编码模式。

enabled

true

在运行时切换流。在附加后将其设置为 false 会拆除服务器并释放端口。

编码模式#

写入器支持两种编码路径，由 useRawEncoding 控制：

H.264（默认，推荐）#

渲染管线直接使用 NVENC 生成 H.264 编码的字节，并将已压缩的数据传递给 RTSP 服务器。此模式：

  • 最小化数据拷贝（无需 CPU 回读，无需双重编码）。

  • 支持逐帧 SEI 元数据。请参阅 Frame Metadata。

  • 随每个流式传输的帧发送仿真时间戳，以便下游消费者将帧与仿真时间对齐。

除非有特定理由需要绕过 NVENC，否则请使用此模式。

Raw（原始数据）#

写入器流式传输未压缩的 RGBA CUDA 缓冲区，并让 RTSP 服务器在内部对其进行编码。

渲染产品的分辨率从第一帧的 CUDA 缓冲区形状中读取。Raw 模式不支持 SEI 元数据注入。

流式传输多个相机#

要同时发布多个相机，请为每个相机实例化一个 RTSPCameraHelper，并为每个辅助工具指定唯一的 port。mountPath 可以在多个流之间共享，但为每个相机使用描述性的挂载路径（如 /front 和 /rear）可以使 URL 具有自文档性：

import omni.graph.core as og
import omni.kit.app
import omni.usd
from pxr import UsdGeom

ext_mgr = omni.kit.app.get_app().get_extension_manager()
ext_mgr.set_extension_enabled_immediate("isaacsim.core.nodes", True)
ext_mgr.set_extension_enabled_immediate("isaacsim.streaming.rtsp", True)

stage = omni.usd.get_context().get_stage()
UsdGeom.Camera.Define(stage, "/CameraFront")
UsdGeom.Camera.Define(stage, "/CameraRear")

og.Controller.edit(
    {"graph_path": "/MultiStreamGraph", "evaluator_name": "execution"},
    {
        og.Controller.Keys.CREATE_NODES: [
            ("OnPlaybackTick", "omni.graph.action.OnPlaybackTick"),
            ("FrontRP", "isaacsim.core.nodes.IsaacCreateRenderProduct"),
            ("RearRP", "isaacsim.core.nodes.IsaacCreateRenderProduct"),
            ("FrontRTSP", "isaacsim.streaming.rtsp.RTSPCameraHelper"),
            ("RearRTSP", "isaacsim.streaming.rtsp.RTSPCameraHelper"),
        ],
        og.Controller.Keys.SET_VALUES: [
            ("FrontRP.inputs:cameraPrim", "/CameraFront"),
            ("FrontRP.inputs:width", 1280),
            ("FrontRP.inputs:height", 720),
            ("RearRP.inputs:cameraPrim", "/CameraRear"),
            ("RearRP.inputs:width", 1280),
            ("RearRP.inputs:height", 720),
            ("FrontRTSP.inputs:port", 8554),
            ("FrontRTSP.inputs:mountPath", "/front"),
            ("RearRTSP.inputs:port", 8555),
            ("RearRTSP.inputs:mountPath", "/rear"),
        ],
        og.Controller.Keys.CONNECT: [
            ("OnPlaybackTick.outputs:tick", "FrontRP.inputs:execIn"),
            ("OnPlaybackTick.outputs:tick", "RearRP.inputs:execIn"),
            ("FrontRP.outputs:execOut", "FrontRTSP.inputs:execIn"),
            ("RearRP.outputs:execOut", "RearRTSP.inputs:execIn"),
            ("FrontRP.outputs:renderProductPath", "FrontRTSP.inputs:renderProductPath"),
            ("RearRP.outputs:renderProductPath", "RearRTSP.inputs:renderProductPath"),
        ],
    },
)

上述两个流可通过 rtsp://localhost:8554/front 和 rtsp://localhost:8555/rear 进行访问。每个辅助工具拥有自己的 RTSP 服务器，因此连接到其中一个流的客户端不会影响另一个流。

帧元数据#

在 H.264 模式下，每一帧都携带一个包含 JSON 有效载荷的补充增强信息（SEI）网络抽象层（NAL）单元。该有效载荷使用固定 UUID aa71e48f-0711-5d80-a247-cd31ca6fa49c，该 UUID 派生自 isaacsim.streaming.rtsp.sei_metadata，以便消费者能够识别并过滤元数据流。其架构如下：

{
    "publish_sim_time_ns": 1500000000,
    "timestamp_iso8601": "2026-01-01T12:00:01.500Z",
    "timestamp": 1767268801500000000,
    "frame_num": 42
}

  • publish_sim_time_ns — 帧捕获时的模拟时间，单位为纳秒。当时间轴停止并重启时重置为零。

  • timestamp_iso8601 — 以 RTSP 服务器启动时刻为基准的挂钟时间戳，由 publish_sim_time_ns 推进。适用于与日志及其他挂钟时间戳流进行关联。

  • timestamp — 与 timestamp_iso8601 相同的时刻，以自 Unix 纪元以来的纳秒数表示。

  • frame_num — 单调递增的帧计数器，从 1 开始，并在分离时重置。

解析 SEI NAL 单元的下游工具（例如 GStreamer 中的自定义 rtspsrc 回调，或 NVIDIA DeepStream 的元数据 API）可以通过匹配 UUID 并解码 JSON 字节来恢复有效载荷。

直接附加写入器#

对于已经通过 Python 驱动 Replicator 且不需要 OmniGraph 层的工作流（自定义 SDG 脚本、批处理作业、无头服务），可以将 isaacsim.streaming.rtsp.RTSPStreamWriter 直接附加到渲染产品上。该写入器在扩展启动时注册到 Replicator 的 WriterRegistry，并接受 port、mountPath、encoding、width 和 height 参数。首先通过 isaacsim.streaming.rtsp.impl.render_var_utils.ensure_render_var_on_product 在渲染产品上编写 SRTX LdrColor RenderVar，然后附加写入器：

import omni.kit.app
import omni.replicator.core as rep
import omni.usd
from pxr import UsdGeom

ext_mgr = omni.kit.app.get_app().get_extension_manager()
ext_mgr.set_extension_enabled_immediate("isaacsim.core.nodes", True)
ext_mgr.set_extension_enabled_immediate("isaacsim.streaming.rtsp", True)

from isaacsim.streaming.rtsp import RTSPStreamWriter
from isaacsim.streaming.rtsp.impl.render_var_utils import ensure_render_var_on_product

stage = omni.usd.get_context().get_stage()
UsdGeom.Camera.Define(stage, "/Camera")

render_product = rep.create.render_product("/Camera", (1280, 720))

success, _rv_path = ensure_render_var_on_product(stage, render_product.path, "LdrColor", "h264")
if not success:
    raise RuntimeError(f"Failed to create LdrColor render var on {render_product.path}")

writer = RTSPStreamWriter(
    port=8554,
    mountPath="/stream",
    encoding="h264",
    width=1280,
    height=720,
)
writer.attach([render_product])

附加写入器后，启动 Replicator 捕获或播放时间轴以生成帧。当写入器接收到第一帧时，RTSP 服务器启动。

服务器生命周期#

RTSP 服务器在 writer 首次接收帧时启动，并在 writer 分离时停止。RTSPCameraHelper 将此生命周期与时间轴关联：

  • 播放 — 动作图运行，writer 附加到渲染产品，服务器在接收到第一帧时启动。

  • 停止 — writer 分离，服务器被拆除，端口被释放。

  • 将 enabled 设置为 false — 对该 helper 产生与停止相同的效果。

如果 RTSP 服务器在流式传输期间遇到不可恢复的错误（例如连接失败或 NVENC 错误），writer 会记录该错误，关闭其服务器，并静默跳过后续帧，直到时间轴重启。这可以防止损坏的流刷屏日志或阻塞仿真循环。

故障排除#

流 URL 拒绝连接

RTSP 服务器仅在渲染出第一帧后启动。按播放并确认时间轴正在推进。如果 writer 记录了设置错误（例如“render product has no resolution attribute”），则服务器从未启动。请检查 carb 日志以获取详细信息。

端口已被占用

另一个进程（或同一场景中的另一个 RTSPCameraHelper）已经绑定了该端口。为每个 helper 选择一个唯一的端口，并使用 ss -ltnp | grep 8554 验证没有其他进程正在监听。

流在运行中途停止且无法恢复

编码器或传输首次出错时，写入器进入“失败”状态，静默丢弃后续帧，并等待时间线重启。停止并重启时间线（或切换 enabled）以重试。

缺少 SEI 元数据

SEI 元数据仅在 H.264 模式下注入。将 useRawEncoding 设置为 false（默认值）。

Asset Transformer 规则参考#

Tool Reference

本页提供了 Asset Transformer 所有可用转换规则的参考。

有关一般用法，请参阅 Asset Transformer。有关 API 和自定义规则开发，请参阅 Asset Transformer API。

规则概览#

规则根据其功能分为四个包：

包

规则

用途

核心路由

SchemaRoutingRule, PropertyRoutingRule, PrimRoutingRule, RemoveSchemaRule

将 USD 意见路由到专用图层

性能

MaterialsRoutingRule, GeometriesRoutingRule

通过去重和实例化优化资产

结构

FlattenRule, VariantRoutingRule, InterfaceConnectionRule

重组 USD 组合结构

Isaac Sim

RobotSchemaRule, MakeListsNonExplicitRule, PhysicsJointPoseFixRule, MergeMeshRule, MjcToPhysxConversionRule, UrdfToMjcPhysxConversionRule, PhysxToMjcConversionRule

应用 Isaac Sim 特定的转换

注意

在 Asset Transformer UI 中，Rule Type 下拉列表通过其短类名（例如 SchemaRoutingRule）列出每个规则，并在 Package 列中按作用域对规则进行分组。此处显示的作用域标记与本页面类别的对应关系如下：Core Routing 对应 core，Performance 对应 perf，Structure 对应 structure，Isaac Sim 对应 isaac_sim。下方列出的每个规则的 Fully Qualified Type 是存储在 profile JSON 中并传递给 API 的值；UI 根据所选作用域和类名组合生成该值。

可用规则#

选择一个类别选项卡以查看可用规则。展开每个规则以查看详细的参数和执行逻辑。

这些规则将 USD 意见（模式、属性、prim）从源层路由到专用的目标层。路由过程通过在目标层中创建覆盖意见并从源层中移除原始意见，从而保留组合语义。

SchemaRoutingRule

将已应用的 API 模式及其关联属性路由到单独的层。这支持模块化组织，允许选择性加载物理模式、机器人模式或其他 API 模式。

完全限定类型：isaacsim.asset.transformer.rules.core.schemas.SchemaRoutingRule

参数：

参数

类型

描述

schemas

列表

要路由的 API 模式模式列表。支持通配符（例如，Physics* 匹配 PhysicsRigidBodyAPI、PhysicsMassAPI）

ignore_schemas

列表

要从路由中排除的 Schema 模式。覆盖 schemas 中的正向匹配。

stage_name

字符串

输出 USD 文件名（默认值：schemas.usda）

prim_names

列表

用于筛选要处理的 Prim 名称的通配符模式（默认：["*"] 匹配所有）

ignore_prim_names

列表

要从处理中排除的 Prim 名称模式

执行逻辑：

  1. Schema 发现：遍历 Stage 中的所有 Prim，并收集与指定模式匹配的已应用 API Schema。

  2. 属性命名空间解析：对于每个匹配的 Schema，确定属性命名空间前缀（例如，PhysicsRigidBodyAPI 使用 physics: 命名空间，PhysicsDriveAPI:angular 使用 drive:angular:）。

  3. Schema 传输：使用 USD 的 TokenListOp 从源层的 apiSchemas 元数据中移除 Schema 标记，并将其前置到目标层。

  4. 属性传输：使用 Sdf.CopySpec 将属于该 Schema 命名空间的所有属性从源层复制到目标层，然后从源层中移除它们。

  5. 层管理：设置目标层的默认 Prim 以匹配源层，并保存这两个层。

PropertyRoutingRule

将匹配名称模式的属性路由到单独的层。这允许将特定的属性命名空间（例如，物理属性、自定义属性）组织到模块化层中。

完全限定类型：isaacsim.asset.transformer.rules.core.properties.PropertyRoutingRule

参数：

参数

类型

描述

properties

列表

用于匹配属性名称的正则表达式模式（例如，physics:.* 匹配所有物理命名空间属性）

ignore_properties

列表

从路由中排除的正则表达式模式

stage_name

字符串

输出 USD 文件名（默认值：properties.usda）

scope

字符串

用于限制搜索范围的根 Prim 路径（默认值：/ 搜索整个 Stage）

prim_names

列表

用于筛选要处理的 Prim 名称的通配符模式

ignore_prim_names

列表

要排除的 Prim 名称模式

执行逻辑：

  1. 模式编译：编译提供的正则表达式模式以实现高效匹配。

  2. 属性发现：遍历范围内所有 Prim 上的属性和关系，将名称与编译后的模式进行匹配检查。

  3. 属性复制：对于每个匹配的属性，使用 Sdf.CopySpec 将 Prim 堆栈中最强意见的 spec 复制到目标层。

  4. 源移除：从 Prim 堆栈中的所有源层（目标层除外）移除属性 spec，以防止出现重复意见。

  5. Layer Finalization：导出目标层并保存所有已修改的源层。

PrimRoutingRule

将匹配类型模式的整个 prim 路由到单独的层中。这有助于将物理 prim、渲染 prim 或其他类型的 prim 组织到模块化层中。

完全限定类型：isaacsim.asset.transformer.rules.core.prims.PrimRoutingRule

参数：

参数

类型

描述

prim_types

列表

要路由的 Prim 类型模式。支持通配符（例如，Physics* 匹配 PhysicsJoint、PhysicsScene）

ignore_prim_types

列表

要从路由中排除的 Prim 类型模式

stage_name

字符串

输出 USD 文件名（默认值：prims.usda）

scope

字符串

用于限制搜索范围的根 Prim 路径（默认值：/）

prim_names

列表

用于筛选要处理的 Prim 名称的通配符模式

ignore_prim_names

列表

要排除的 Prim 名称模式

执行逻辑：

  1. 类型匹配：使用 fnmatch 收集范围内所有类型名称与指定模式匹配的 prim。

  2. 组合复制：将完整的组合 prim 定义（包括所有属性、元数据和已应用的 schema）复制到目标层。

  3. 完全移除：从所有源层中移除 prim spec，包括显式删除所有属性 spec（以处理由其他规则（如 SchemaRoutingRule）编写的覆盖属性）、清除 apiSchemas 元数据，以及从父命名空间中删除 prim spec。

  4. 层管理：导出目标层并保存已修改的源层。

RemoveSchemaRule

从目标层中移除特定的已应用 API schema（以及可选的其关联属性）。在准备资产以适配不同的物理后端时，可用于剥离模拟器专用的 schema。

完全限定类型：isaacsim.asset.transformer.rules.core.remove_schema.RemoveSchemaRule

参数：

参数

类型

描述

stage_name

字符串

要编辑的目标 USD 文件名（例如，mujoco.usda）

schema_patterns

列表

匹配要移除的 API schema 名称的通配符模式（例如，PhysicsDriveAPI.*）

prim_path_patterns

列表

限制受影响 prim 路径的正则表达式模式（默认：[".*"]）

clear_properties

布尔值

同时移除属于匹配 schema 命名空间的属性（默认：False）

执行逻辑：

  1. 模式匹配：遍历目标层中的所有 prim，将已应用的 API schema 与指定的通配符模式进行匹配。

  2. Schema Removal：使用 TokenListOp 操作，从每个 prim 的 apiSchemas 元数据中移除匹配的 schema 令牌。

  3. Property Cleanup：如果启用了 clear_properties，则从 prim spec 中移除匹配 schema 命名空间下的所有属性。

  4. Layer Save：保存修改后的层。

这些规则通过去重和实例化来优化资产，从而提升模拟和渲染性能。

MaterialsRoutingRule

将材质 prim 路由到具有全局去重功能的共享层，在原始位置创建可实例化的引用，并将纹理/MDL 资产传输到指定文件夹。

完全限定类型：isaacsim.asset.transformer.rules.perf.materials.MaterialsRoutingRule

参数：

参数

类型

描述

scope

字符串

用于限制材质搜索的根 prim 路径（默认值：/）

materials_layer

字符串

材质层的输出 USD 文件名（默认值：materials.usda）

textures_folder

字符串

相对于目标位置的纹理资产文件夹名称（默认值：Textures）

deduplicate

布尔值

启用基于内容哈希的材质去重（默认值：True）

download_textures

布尔值

将远程纹理（例如来自 Nucleus）下载到本地文件夹（默认值：False）

执行逻辑：

  1. 材质发现：在范围内查找所有材质 prim（UsdShade.Material），并追踪每个材质由哪个层定义。应用了 PhysicsMaterialAPI 的材质会被跳过——这些物理专用材质保留在基础层的原始路径中，以确保 material:binding:physics 关系能够继续解析。

  2. 资产收集：解析材质引用的所有纹理和 MDL 文件路径，处理本地和远程（Nucleus）资产。解析 MDL 文件以发现嵌入的纹理引用。UDIM 模板（<UDIM>，包括 URL 编码的 %3CUDIM%3E 形式）作为单个系列收集，而不是作为不存在的单个文件。

  3. 内容哈希：使用解析后的资产路径计算每个材质内容（类型、属性、连接、关系）的 SHA-256 哈希值，以实现一致的去重。

  4. 资产传输：将所有唯一资产复制到 textures 文件夹，并进行全局去重。通过追加数字后缀来处理文件名冲突。更新 MDL 文件以指向传输后的纹理。UDIM 系列会展开为其具体的瓦片（从源文件夹枚举），每个瓦片都会被传输，并且材质引用会被重写为相对的 <UDIM> 模板，以便解析器针对传输后的瓦片重新展开它。

  5. 材质层创建：在材质层中创建一个 /Materials 范围。对于每个唯一材质（按哈希值），复制材质定义并更新资产路径。

  6. 可实例化引用：使用指向材质层中已去重材质的可实例化引用，更新每个原始材质位置。

  7. 绑定更新：确保 MaterialBindingAPI 应用于所有具有材质绑定的 prim。

  8. 清理：移除未绑定到任何表面的材质的可实例化引用。

MjcToPhysxConversionRule

将 MJCF 执行器和关节属性转换为 PhysX 驱动和关节模式。这通过将 MJCF 增益/偏置参数转换为 PhysX 刚度/阻尼，实现了多物理引擎支持。

  2. 关节转换：对于每个 revolute/prismatic 关节，转换 MJCF 特定属性（frictionloss → PhysxJointAPI.jointFriction，armature → PhysxJointAPI.armature，ref → DriveAPI.targetPosition）。

UrdfToMjcPhysxConversionRule

将 URDF 关节属性转换为 MJCF 执行器和 PhysX 关节架构。这是针对 URDF 导入资产的多物理场转换步骤，用于创建双后端表示。

完全限定类型：isaacsim.asset.transformer.rules.isaac_sim.urdf_to_mjc_physx_conversion.UrdfToMjcPhysxConversionRule

参数：无

执行逻辑：

  1. 创建物理范围：确保在默认 prim 下存在一个 Physics 范围，用于执行器 prim。

  2. URDF 到 PhysX 转换：对于每个 revolute/prismatic 关节，转换 URDF 属性（effort → DriveAPI.maxForce，旧版 urdf:limit:velocity → PhysxJointAPI.maxJointVelocity，damping → DriveAPI.damping，friction → PhysxJointAPI.jointFriction，calibration → DriveAPI.targetPosition）。

  3. MjcActuator 创建：创建 MjcActuator prim，其中包含从位置或速度控制模式的驱动刚度和阻尼派生的 gainPrm/biasPrm 数组。

  4. PhysX 到 MJC 转换：将 PhysX 关节属性转换回 MJCF 属性（targetPosition → mjc:ref，jointFriction → mjc:frictionloss，armature → mjc:armature）。

Mimic 关节在关节 prim 上保留为 NewtonMimicAPI，并由运行时直接消费；不会编写等效的 PhysxMimicJointAPI。

PhysxToMjcConversionRule

将现有的 PhysX 资产转换为 MuJoCo/Newton 架构。与 UrdfToMjcPhysxConversionRule 不同，此规则假定 PhysX 驱动和关节属性已经编写完成，仅在其之上添加 MuJoCo/Newton 表示形式，因此对于已在 PhysX 中模拟的资产而言，这是正确的选择。

完全限定类型：isaacsim.asset.transformer.rules.isaac_sim.physx_to_mjc_conversion.PhysxToMjcConversionRule

参数：无。该规则使用由 transformer 框架提供的标准输入阶段、输出目录和 destination。

执行逻辑：

  1. 创建物理范围：确保在默认 prim 下存在一个 Physics 范围，用于执行器 prim。

  2. 多自由度警告：遍历阶段，针对通用 D6 和球形关节发出警告，并保持其不变。转换它们会改变关节结构。

  3. 关节转换：对于每个旋转/棱柱关节，应用 MjcJointAPI（如果缺失），编写 mjc:* 关节属性（targetPosition → mjc:ref，jointFriction → mjc:frictionloss，armature → mjc:armature），并创建一个 MjcActuator（如果不存在），其 gainPrm/biasPrm 源自 PhysX 驱动的刚度和阻尼。

  4. 模仿转换：将 PhysxMimicJointAPI 移植到 NewtonMimicAPI，映射参考关节以及齿轮/偏移系数。

  5. 关节根转换：为携带 PhysxArticulationAPI 的 prim 添加 NewtonArticulationRootAPI，映射 enabledSelfCollisions → newton:selfCollisionEnabled。

  6. 输出：就地编辑工作阶段（管理器会持久化保存），或者当规则的 destination 是 USD 文件时，将转换结果写入单独的覆盖层。

幂等性要求#

所有转换规则必须是幂等的：对同一资产运行两次完整的配置文件（第一次在原始资产上运行，第二次在第一次运行的输出上运行）必须产生完全相同的 USD 层，唯一的例外是 doc 元数据字段，该字段嵌入了绝对路径。该扩展包含一个幂等性测试（test_profile_idempotency.py），用于强制执行此要求。

开发新规则时需要注意的常见非幂等性来源：

  • 浮点漂移 – 矩阵组合/分解的往返操作会引入噪声。将数值量化为固定的有效数字位数，或在可能的情况下直接读取规范的 xformOp 值。

  • 过时的组合弧 – 从变体规范中提取内容可能会在目标 prim 上留下自引用的负载或引用。剥离源中不存在的所有弧。

  • defaultPrim 不一致 – 使用 self.source_stage.GetDefaultPrim()（组合阶段）而不是 self.source_stage.GetRootLayer().defaultPrim（仅根层），以便在重新转换时可靠地解析默认 prim。

  • 非确定性的合并决策 – 在决定是将子级合并到其父级时，需考虑由先前运行遗留的脚手架 prim（例如 VisualMaterials 范围、空的覆盖）。

  • 多余的根级 prim – 在扁平化之后，位于 defaultPrim 层级之外的根级 prim（例如视口/渲染伪影）无法在基于引用的往返过程中保留。InterfaceConnectionRule 会自动处理此问题，将这些 prim 从基础层移动到接口层，但引入根级 prim 的自定义规则应注意此组合约束。

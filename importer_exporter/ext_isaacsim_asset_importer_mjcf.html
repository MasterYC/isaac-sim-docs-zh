MJCF 导入器扩展#

Tool Reference

注意

从 Isaac Sim 2023.1.0 版本开始，MJCF 导入器已开源。 源代码和贡献指南可在 我们的 Github 仓库中找到。 截至 Isaac Sim 5.0，之前的专用仓库已弃用，代码已迁移至 Isaac Sim 仓库。

MJCF 导入器扩展 用于导入机器人的 MuJoCo 表示形式。 MuJoCo 建模 XML 文件 (MJCF) 是一种用于在 MuJoCo 模拟器中表示机器人模型的 XML 格式。

要访问此扩展，请转到顶部菜单栏并点击 File > Import。

此扩展默认启用。如果它被禁用，可以通过 Extension Manager 搜索 isaacsim.asset.importer.mjcf 来重新启用它。

规范#

注意

链接或关节名称中的特殊字符不受支持，会被替换为下划线。如果由于替换导致名称以下划线开头，则会在前面添加 a。建议直接在 MJCF 文件中进行这些名称更改。

请参阅Isaac Sim 约定文档，以获取 NVIDIA Isaac Sim 约定的完整列表。

用户界面#

导入选项#

USD 输出：指定生成的 USD 文件的保存位置。默认情况下，此项设置为“与导入模型相同（默认）”，

即将 USD 文件保存在与源 MJCF 文件相同的目录中。用户可以点击文件夹图标以选择其他 输出位置。

碰撞体：

  • Collision From Visuals：启用后，将从 MJCF 文件中的视觉网格生成碰撞几何体。当 MJCF 文件中未定义显式碰撞几何体时，此选项非常有用。勾选此选项后，Collision Type 下拉菜单将变为可见。

  • Collision Type：在以下选项中进行选择：

    • Convex Hull：围绕视觉网格创建凸包。

    • Convex Decomposition：将视觉网格分解为多个凸体，以实现更精确的碰撞检测。

    • Bounding Sphere：使用简单的包围球近似。

    • Bounding Cube：使用简单的包围盒近似。

  • Allow Self-Collision：启用后，允许机器人模型与自身发生碰撞。这在某些仿真场景中很有用，但如果连杆之间的碰撞网格自相交，可能会导致不稳定。

选项：

  • Robot Type：设置导入机器人的 schema 上的 isaac:robotType 属性。可选值包括：Default、End Effector、 Manipulator、Humanoid、Wheeled、Holonomic、Quadruped、Mobile Manipulators 或 Aerial。

  • Base Type：通过三态控件控制机器人根链接的锚定方式。

    • Source（默认）：保持源 MJCF 文件的原始设置不变。

    • Fixed：添加一个从世界到根节点的固定关节，并将 ArticulationRootAPI 重新定位到正确的祖先 prim。

    • Mobile：移除任何现有的从世界到根节点的固定关节，使机器人可以自由平移和旋转。

    直接映射到 MJCFImporterConfig 上的 fix_base: bool | None 字段（None / True / False）。

  • Add Reference to Stage：将导入的 USD 引用到当前 stage 中，而不是直接打开它。默认禁用。

  • Import Scene：启用时，除了模型外，还会导入 MJCF 仿真设置。

  • Merge Mesh：启用时，尽可能合并网格以优化模型。这可以减少生成的 USD 文件中的 prim 数量并提升性能。

  • Debug Mode：启用时，激活调试模式以保留中间文件和 asset transformer 报告。

机器人属性#

您可能需要调整机器人的许多属性。 这些属性可能分布在多个不同的 Schema 和 API 中。

获取和设置参数的一般步骤如下：

  1. 查找参数所属的 API。大多数常用 API 可以在 Pixar USD API 中找到。

  2. 获取应用了该 API 的 prim 句柄。例如，Articulation 和 Drive API 应用于关节，而 MassAPI 应用于刚体。

  3. 获取该 API 的句柄。然后，您可以获取或设置与该 API 关联的属性。

例如，如果您想要设置车轮的驱动速度和执行器的刚度，必须找到 DriveAPI：

# get handle to the Drive API for both wheels
left_wheel_drive = UsdPhysics.DriveAPI.Get(stage.GetPrimAtPath("/carter/chassis_link/left_wheel"), "angular")
right_wheel_drive = UsdPhysics.DriveAPI.Get(stage.GetPrimAtPath("/carter/chassis_link/right_wheel"), "angular")

# Set the velocity drive target in degrees/second
left_wheel_drive.GetTargetVelocityAttr().Set(150)
right_wheel_drive.GetTargetVelocityAttr().Set(150)

# Set the drive damping, which controls the strength of the velocity drive
left_wheel_drive.GetDampingAttr().Set(15000)
right_wheel_drive.GetDampingAttr().Set(15000)

# Set the drive stiffness, which controls the strength of the position drive
# In this case because we want to do velocity control this should be set to zero
left_wheel_drive.GetStiffnessAttr().Set(0)
right_wheel_drive.GetStiffnessAttr().Set(0)

或者，您可以使用 Omniverse Commands Tool Extension 在 UI 中更改值，并获取用于更改该属性的相应 Omniverse 命令。

注意

  • 在关节驱动上使用位置控制时，应设置 drive stiffness 参数。

  • 在关节驱动上使用速度控制时，应设置 drive damping 参数。

  • 在驱动上同时设置刚度和阻尼会导致两个目标都被应用，这在位置控制中可用于减少振动。

注意

请参阅 Gain Tuner Extension 教程，以调整机器人的增益。

多物理引擎支持#

MJCF 导入器支持将 MJCF 执行器/关节数据转换为 PhysX 架构，以支持多物理引擎。 这允许您在不同的物理引擎中使用相同的 MJCF 文件。

使用 MJCF 导入器时会自动执行转换。 您可以使用 增益调优扩展 教程，在多物理引擎环境下为机器人调优增益。

备注

MJC 执行器：gainType（fixed）

UsdPhysics DriveAPI.gainType

如果存在 gainType 且其值为“fixed”，并且 bias type 为“affine”，则使用 gainPrm 数组来设置刚度（stiffness）和阻尼（damping）。仅支持“fixed”增益类型。请参阅下方警告中的说明。

如果存在 biasType 且其值为“affine”，并且 gain type 为“fixed”，则使用 biasPrm 数组来设置阻尼。仅支持“affine”偏置类型。请参阅下方警告中的说明。

UsdPhysics DriveAPI.stiffness

如果存在 gainprm 数组且第一个元素不为 0，则 stiffness = gainprm[0]。在 USD Physics 中，刚度必须为正值。

MJC 执行器：gainprm ([kd, 0, 0, …]) - 速度控制

UsdPhysics DriveAPI.damping

如果存在 gainprm 数组且第一个元素不为 0，则 damping = gainprm[0]。在 USD Physics 中，阻尼必须为正值。

MJC 执行器：biasprm ([0, -kp, -kd, …]) - 位置控制

UsdPhysics DriveAPI.damping, UsdPhysics DriveAPI.stiffness

如果存在 biasprm 数组且第二个和第三个元素不为 0，则 damping = -biasprm[2]，stiffness = -biasprm[1]。在 USD Physics 中，stiffness 和 damping 必须为正值。

MJC 执行器：biasprm ([0, 0, -kd, …]) - 速度控制

UsdPhysics DriveAPI.damping

如果存在 biasprm 数组且第三个元素不为 0，则 damping = -biasprm[2]，stiffness = 0。在 USD Physics 中，damping 必须为正值。

mjc:forceRange:max

UsdPhysics DriveAPI.maxForce

MJCF 使用 min/max，而 PhysX 使用 maxForce。PhysX 不支持最小力范围，因此如果 abs(min) != max，转换后的行为可能会有所不同。

mjc:frictionloss

PhysxJointAPI.jointFriction

应用于关节摩擦属性

mjc:armature

PhysxJointAPI.armature

设置电枢（armature）参数

mjc:ref

UsdPhysics DriveAPI.targetPosition

初始关节目标位置

警告

USD Physics 使用 PD 控制器进行位置控制，使用 P 控制器进行速度控制，这与 MJCF 的通用控制器公式 F = gain * control + bias 不同，因此仅支持固定增益类型（fixed gain type）和仿射偏置类型（affine bias type）。如果增益类型或偏置类型不是“fixed”或“affine”，则不会创建物理驱动的 stiffness 和 damping，请检查 MJCF 执行器属性并相应调整增益类型和偏置类型。

注意

模仿关节（Mimic joints）：

模仿关节： MJCF 导入器支持转换模仿（依赖）关节，允许一个关节的运动跟随另一个关节，并带有缩放和偏移。在 MuJoCo/MJCF 中，模仿关系使用 mimicJoint 加上 mimicCoef 来建模跟随关节和引导关节之间的高阶关系。导入器捕获一阶项（偏移和缩放），以便运行时可以强制执行 follower = mimicCoef0 + mimicCoef1 * leader。

导入时，模仿属性通过 NewtonMimicAPI 写入从动关节：

  • newton:mimicJoint 是指向主导关节的关系。

  • newton:mimicCoef1 存储缩放因子。

  • newton:mimicCoef0 存储偏移量。

运行时直接消耗 NewtonMimicAPI，因此不会创建等效的 PhysxMimicJointAPI。

有关精确逻辑和用法，请参阅源代码。

关节根 API#

MJCF 导入器在 MJCF 文件的根链接上应用标准的 UsdPhysics.ArticulationRootAPI 和 NewtonArticulationRootAPI。自碰撞行为通过 newton:selfCollisionEnabled 编写，并由运行时直接消耗；不再编写 PhysX 特有的 PhysxArticulationAPI。

已知问题#

同一对刚体之间的多自由度关节#

在 USD 中，关节是两个刚体之间的运动学约束，除了关节自身的轴之外，它锁定所有其他自由度。例如，旋转关节有一个自由度，并移除其他五个自由度。

MuJoCo 将关节视为单个自由度，并允许你在同一对刚体之间堆叠多个单轴关节，以表达多自由度连接。同一父体和子体之间的一个 x 轴旋转关节和一个 y 轴旋转关节共同构成一个 2 自由度的旋转关节。PhysX 拒绝这种布局，因为它会在同一对刚体之间产生多个约束（即“闭合运动链”）。

当启用 run_multi_physics_conversion（默认设置）时，MJCF 导入器会在资产转换器运行后，在 PhysX 变体中自动修复此问题。后处理过程会遍历 payloads/Physics/physx.usda 中的每个关节，按它们的 (body0, body1) 目标进行分组，将每个过约束组中的第一个关节重新类型化为 PhysicsJoint (D6)，并带有逐轴的 LimitAPI/DriveAPI 实例，通过 active = false 停用剩余的关节，并将任何指向新 D6 主机的 NewtonMimicAPI.newton:mimicJoint 引用重定向。所有编辑都限制在 PhysX 覆盖层内；基础 physics.usda 保持不变，因此 MuJoCo/Newton 变体仍然看到原始的逐自由度关节。因此，针对一个变体训练的控制策略无法直接转移到另一个变体。

两种 MJCF 编写模式会产生 D6 无法精确表示的结果：

  • 离轴关节共享相同的标称 physics:axis 标记。MJCF→USD 转换器会将任何 vec3 轴归一化为 "X"/"Y"/"Z" 之一，并将实际方向烘焙到 localRot0/localRot1 中。如果同一组中的两个关节最终具有相同的标记，则只有第一个关节被折叠到 D6 中；第二个关节被停用，其自由度被丢弃。系统会为被丢弃的关节记录一条警告。

  • 无法识别的 ``physics:axis``。该关节无法分配 D6 轴，其处理方式与重复轴情况相同（被停用，自由度被丢弃）。

如果您希望保留所有自由度并且可以编辑 MJCF，手动解决方法是在父体和子体之间插入一个零质量的虚拟链接，并将多自由度关节拆分为每个中间边一个单自由度关节。
